## 一、架构概述与演进哲学

旧版预设使用的 ERA 变量框架在长期实测中暴露了诸多结构性缺陷：
- **角色碎片化严重**：同一角色被割裂为 `characters`（基础）、`char_assets`（资产）和 `char_nsfw`（生理）三个顶层大表，AI 在更新时路径过长且极易写错。
- **实体冗余（两道贩子）**：道具必须先在顶层 `entities` 定义属性，再在 `char_assets` 中挂载，且充斥着 `INV_`、`EQ_`、`EXT_` 等生硬的人工编码。
- **画图标签污染上下文**：旧结构强行要求模型每轮维护数十个纯英文 Danbooru 标签，极大挤占了宝贵的上下文窗口。
- **深层合并脆弱**：靠大段 JSON 深层合并更新，极易出现括号缺失或破坏旧数据的现象。

### 新架构的核心原则：
1. **高内聚实体**：角色即全能实体。一个角色的外貌、心智、装备、生理与数值完全收拢在该角色的唯一键值下。
2. **自然语义替代暗号**：用结构化字段与大白话描述（如 `佩戴`、`背包`、`仓库`）取代人造前缀。
3. **原生适配 JSON Patch (RFC 6902)**：只输出精简的原子操作（`replace`、`delta`、`insert`、`remove`），极大降低模型出错率与 Token 消耗。
4. **轻重按需调度**：通过预设配置的层级开关，自由在「极简日常叙事」与「重度硬核跑团」之间无缝切换。

## 二、分层开关体系 (控制轻重度)

本系统采用 **「底座常驻 + 4 大可拔插扩展包」** 的模块化设计：

```
┌─────────────────────────────────────────────────────────────┐
│                 时空底座 (纪元、时间、地点、在场人员)                 │  ← [必开常驻]
├─────────────────────────────────────────────────────────────┤
│                 角色综合实体 (基础人设、心境状态、随身资产)            │  ← [必开常驻]
├─────────────────────────────────────────────────────────────┤
│   互斥地图体系：[模式 A: 节点拓扑图]  XOR  [模式 B: 网格复合坐标系]  │  ← [扩展包一：二选一]
├─────────────────────────────────────────────────────────────┤
│   深度跑团层 (DND六维、专长技能、平行事件时钟、阵营势力)           │  ← [扩展包二：开关]
├─────────────────────────────────────────────────────────────┤
│   感官与深层生理 (衣物层级破损、情欲心防、敏感部位开发)              │  ← [扩展包三：开关]
├─────────────────────────────────────────────────────────────┤
│   剧情与命运中枢 (主支线进度、核心情报与未解线索)                   │  ← [扩展包四：开关]
└─────────────────────────────────────────────────────────────┘
```

- **纯爱/日常模式**：只开核心底座，Token 消耗极小，留足注意力给正文文笔。
- **西幻冒险/地牢探险**：追加地图（网格或节点）与深度跑团层。
- **成人剧情/沉浸互动**：追加感官与深层生理层。
- **全功能大满贯**：全开进入重度世界模拟器模式。

## 三、核心数据结构详解

### 3.1 时空底座 (核心常驻)
锚定当前叙事镜头所处的具体时空环境。

```yaml
时空:
  纪元历法: string      # 格式示例："第四纪元 2023年11月15日 15:00 (周三 申时)"
  当前地点: string      # 对应地图中的有效节点名称，如："迷雾森林·古老石碑入口"
  气候天色: string      # 语境化的自然描写，如："冷冽大雾，能见度不足十米，伴有微弱魔力潮汐"
  同屏人员: string[]    # 当前处于同一视觉场景内的角色名，如：["雷恩", "艾莉亚"]
```

---

### 3.2 角色综合实体 (核心常驻)
角色是故事的基石。所有属性均挂载在角色名下（支持模型根据剧情动态新增 NPC）。

```yaml
角色:
  [角色名]:
    基础人设:
      是否为玩家: boolean # true 代表玩家当前扮演的主角，其余为 NPC
      身份阵营: string    # 如："精灵族巡逻游侠 (守序中立)"
      外形特征: string    # 中文自然语言浓缩描写，提炼发型、瞳色、体型与辨识特质
      当前着装:
        外层: string      # 如："墨绿色防风短斗篷"
        主体: string      # 如："深绿色贴身游侠皮甲 (完好)"
        贴身: string      # 如："素色亚麻衬衣"
        足部: string      # 如："软底猎手皮靴"
        饰品: string[]    # 如：["风行者护符", "细银耳坠"]
    
    心智反应:
      表层情绪: string    # 当前显露的表情与语调，如："极度警惕且严肃"
      深层心声: string    # 内心真实想法，如："这人类身上有微弱魔力，必须核实来历"
      当前诉求: string    # 短期行动目标，如："解除对方武装并确认没有携带污染源"
    
    人际网络:
      对主角好感: number  # 数值范围：-100 到 100（主角自身为 100）
      关系定位: string    # 枚举或状态：["陌生人", "警惕防备", "熟人", "伙伴", "信任", "暧昧", "至死不渝", "死敌"]
      互动倾向: string    # 描述性态度，如："言语冰冷但原则分明，避免不必要的肢体接触"
    
    资产与装备:           # 自然语义分级存储，淘汰旧版复杂代码
      装备穿戴:
        [装备名]:
          部位: string    # 如："主手" | "副手" | "身体" | "饰品"
          品质: string    # 如："普通" | "精良" | "史诗" | "神器"
          特效描述: string # 语境化效果，如："远距离射击精度显著提升"
      随身携带:
        [物品名]:
          数量: number    # 计件物品记录数量，唯一性道具记 1
          存放位置: string # 如："腰间皮囊" | "战术背心右袋" | "箭袋"
          详细说明: string # 道具简述或剩余次数
      寄存保管:
        [物品名]:
          数量: number
          保管地点: string # 如："精灵营地主帐篷" | "起始镇旅馆储物箱"
```

### 3.3 互斥双模式地图 (扩展包一)

系统根据设置在 **节点拓扑模式** 与 **网格复合模式** 中二选一加载。

#### 模式 A：纯节点拓扑图 (宏观旅行向)
专注于区域之间的逻辑连通性、通行耗时与前置条件。

```yaml
地图_节点模式:
  当前节点标识: string   # 必须与 [时空.当前地点] 对应
  大区域划分:
    [区域名称]:
      区域概况: string   # 区域的风土人情与环境特色
      环境标签: string[] # 如：["原始森林", "高浓度魔力", "浓雾遮蔽"]
      节点集合:
        [节点名称]:
          场景特征: string
          可通行路线:
            - 目标节点: string
              通行耗时: string  # 如："徒步 30 分钟" | "乘马车 2 小时"
              通行条件: string  # 如："拥有精灵向导" | "击败守护魔像" | "无"
              通路状态: "畅通" | "封闭" | "隐藏" | "险阻"
```

#### 模式 B：节点 + 网格复合坐标系 (微观战术/地牢探险向)
在节点场景下细分出局部的笛卡尔网格 `[X, Y]` 坐标，记录障碍、掩体与实时站位。

```yaml
地图_网格模式:
  所属节点场景: string   # 当前场景名
  网格规格:
    空间尺寸: [number, number] # 格式：[宽, 高]，如：[10, 10]
    单位比例: string           # 如："1格 = 1.5米"
  地块障碍清单:                # 仅记录具有战术意义的特殊格子，普通地块自动视为平地
    "[X,Y]":
      地块类型: "掩体" | "陷阱" | "障碍" | "高台" | "交互点" | "出入口"
      环境描写: string
      通行阻碍: boolean       # true 代表不可直接穿行
      当前状态: string         # 如："已触发" | "隐蔽" | "提供半身掩护"
  在场实体坐标:                # 与 [时空.同屏人员] 严格联动
    [实体名称]: [number, number] # 坐标格式：[X, Y]
  视野与迷雾:
    已点亮区域: string         # 描述当前可视范围与盲区
```

## 四、双地图体系操作规范

### 1. 节点地图更新规范
- **位移操作**：当角色穿越路线时，直接 `replace` `/时空/当前地点`，并同步更新节点连通状态中的事件描写。
- **开辟新地点**：当剧情探索出新区域时，使用 `insert` 向 `/地图_节点模式/大区域划分/[区域名]/节点集合` 注入新节点，并确保相邻节点互有连通记录。

### 2. 网格地图更新规范
- **坐标同步**：模型描写角色跑位、冲锋、后撤时，必须在同一轮 Patch 中更新 `/地图_网格模式/在场实体坐标/[角色名]`。
- **障碍变动**：破坏掩体、引爆陷阱或开辟通道时，通过 `replace` 改变地块状态，或 `remove` 消除障碍标记。

## 五、AI 指令规范与思维链模板

模型在输出正文之后，必须在末尾附带 `<UpdateVariable>` 块，格式遵循 **RFC 6902 JSON Patch** 标准。

### 1. 思维链 `<Analysis>` 约束
AI 在打补丁前必须进行结构化自我推演：
```xml
<UpdateVariable>
<Analysis>
- 1. 时空与在场核对：经过了多少时间？地点是否改变？有无角色离场或入场？
- 2. 角色状态变动：各角色心理、外表、着装完好度是否发生变化？
- 3. 关系与好感跃迁：好感度增减多少？是否达成关系阶段晋升的前提？
- 4. 资产与地图检查：物品是否有消耗、转移或拾取？网格坐标是否位移？
- 5. 判定补丁路径完整性：确认所有 path 均精准指向叶子节点。
</Analysis>
<JSONPatch>
[
  { "op": "replace", "path": "/时空/当前地点", "value": "迷雾森林·幽暗深处" },
  { "op": "delta", "path": "/角色/艾莉亚/人际网络/对主角好感", "value": 5 },
  { "op": "replace", "path": "/角色/艾莉亚/心智反应/表层情绪", "value": "态度略微缓和" },
  { "op": "insert", "path": "/角色/雷恩/资产与装备/随身携带/迷雾花", "value": { "数量": 1, "存放位置": "腰包", "详细说明": "刚采摘的草药" } }
]
</JSONPatch>
</UpdateVariable>
```

## 六、Zod 4 落地类型守卫与防御策略

为防止模型在动态长出新角色、新物品时漏填内部字段导致整个对象被判定非法，我们在 Zod 脚本层必须部署以下铁律：

### 1. 内部字段全面 `prefault`
复合对象的每一个子字段必须赋予保底默认值，杜绝因子字段缺失抹杀整个对象：

```typescript
import { registerMvuSchema } from 'https://testingcf.jsdelivr.net/gh/StageDog/tavern_resource/dist/util/mvu_zod.js';

// 角色基础人设 Schema 守卫
const CharacterBaseSchema = z.object({
  是否为玩家: z.boolean().prefault(false),
  身份阵营: z.string().prefault('未知旅人'),
  外形特征: z.string().prefault('外貌特征尚不明显'),
  当前着装: z.object({
    外层: z.string().prefault('无'),
    主体: z.string().prefault('普通布衣'),
    贴身: z.string().prefault('贴身内衣'),
    足部: z.string().prefault('简陋布鞋'),
    饰品: z.array(z.string()).prefault([]),
  }).prefault({}),
}).prefault({});

// 严格数值钳位与枚举防越界
const AffectionSchema = z.coerce.number().transform(v => _.clamp(v, -100, 100)).prefault(0);
const RelationshipSchema = z.enum([
  '陌生人', '警惕防备', '熟人', '伙伴', '信任', '暧昧', '至死不渝', '死敌'
]).prefault('陌生人');

// 动态角色总 Schema
export const CharacterSchema = z.record(
  z.string().describe('角色名'),
  z.object({
    基础人设: CharacterBaseSchema,
    心智反应: z.object({
      表层情绪: z.string().prefault('面无表情'),
      深层心声: z.string().prefault('静观其变'),
      当前诉求: z.string().prefault('无明确意图'),
    }).prefault({}),
    人际网络: z.object({
      对主角好感: AffectionSchema,
      关系定位: RelationshipSchema,
      互动倾向: z.string().prefault('保持距离'),
    }).prefault({}),
    资产与装备: z.object({
      装备穿戴: z.record(z.string(), z.any()).prefault({}),
      随身携带: z.record(z.string(), z.any()).prefault({}),
      寄存保管: z.record(z.string(), z.any()).prefault({}),
    }).prefault({}),
  }).prefault({})
);
```

### 2. 幂等性与非阻塞容错
- 变量结构脚本只使用 `z.transform` 单入参语法，禁止使用 `optional`、`strict` 或 `passthrough`。
- 保证任意状态在执行 `Schema.parse(Schema.parse(input))` 后的结果完全恒等。
- 当玩家在状态栏点击「丢弃/修改」时，前端调用 `Schema.parse` 预检后再通过 `Mvu.replaceMvuData` 写入，确保底层数据与界面始终绝对一致。
