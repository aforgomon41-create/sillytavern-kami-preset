# 任务：为「卡密预设」设计一套皮肤（第一阶段：只交设计方案，不写代码）

## 背景（你没有上下文，以下是你需要的全部信息）

「卡密预设」是一套 SillyTavern（酒馆）AI 角色扮演预设，运行在 **酒馆助手 4.9.5** 插件之上。它把 LLM 的回复包裹在 XML 里，再用**正则**把其中两段内容替换成**内嵌前端**：

1. **显式思维链**：把模型的思考过程渲染成**默认折叠、点击展开**的面板；支持「渲染 markdown / 原文」双模式切换、字符数统计、一键复制。
2. **行动选项**：把模型输出的 JSON 行动选项渲染成**可点击卡片列表**；双模式「填入」（把内容追加到输入框尾部）与「发送」（直接发出并触发生成）；显示选项总数。

另有三个**脚本面板**（酒馆助手脚本在酒馆页面上绘制的悬浮窗/抽屉）：**皮肤管理面板**、**预设设置面板**、**引导面板**。

这些界面中，前两个渲染在**聊天楼层的 iframe** 里（同源、无沙箱、宽度约等于聊天宽度、高度等于内容高度、**不能滚动**、html/body 被强制 overflow:hidden）；后三个渲染在酒馆页面 DOM 上。

**同一套皮肤 CSS 会同时被注入到酒馆页面和每一个聊天楼层。**

## 你要做的事

设计**一套皮肤**：一套**纯 CSS** 的完整视觉语言系统，必须能同时美化上述全部 5 个界面。
皮肤 = 一整份组件 CSS + 一整套设计令牌（CSS 自定义属性）+ 一组「高级特效」。

**本阶段只交设计方案，绝对不要写实现代码。** 方案经用户审阅通过后，第二阶段才写 CSS。

## 硬约束（违反的方案会被直接否决）

- 皮肤是**纯 CSS**：不得包含任何 JS，不得引用任何外部网络资源（字体/图片/CDN），不得使用 @import。
  理由：这份 CSS 会被注入到**每一个聊天楼层**的 iframe 里，按楼层线性承担开销，任何运行时或外部请求都会成倍放大。
  可用的重武器：内联 SVG 的 data: URI、mask、clip-path、filter、mix-blend-mode、backdrop-filter、@keyframes、
  @property、@container、:has()、多层渐变、text-shadow、3D transform、滚动驱动动画。
- 所有选择器必须含 **kami** 字样，绝不触碰酒馆自身 UI。
- 必须同时成立在两个宿主：酒馆页面里的脚本面板 / 聊天楼层里的内嵌前端。
- 移动端优先（320px 宽必须成立）；不得用 vh；不得依赖滚动；不得用 position:fixed 铺满。
- 可访问性：:focus-visible 必须有明确样式；prefers-reduced-motion 与 data-kami-motion="off" 必须有兜底；正文对比度不低于 4.5:1。
- **必须给全第 3 节的全部令牌**（皮肤生效时兜底 CSS 会整体失效，缺一个就塌一块）。

## 你的创作身份

你是顶级游戏 UI/UX 设计师 + 资深创意前端工程师 + 数字艺术总监。
你深度理解现代游戏化交互（Game HUD）、沉浸式叙事界面，以及 SillyTavern / AI Roleplay 的生态与使用场景。
你交付的**不应只是一套配色**，而应是一件让人愿意反复端详、能感受到概念的**数字工艺**。

你拥有完全的创作自由：信息层级、视觉语言、材质、节奏、交互反馈、内容密度，全部由你决定。
**不要迎合“AI 科技风”**，不必使用暗色、霓虹、粒子、玻璃拟态、终端或打字机——只有当它们真正服务于概念时才使用。
重点是“你认为最值得被体验的设计概念”，而不是堆砌效果。

### 必须满足的高层标准
1. **有独立的核心概念**：先用不超过 200 字写出核心隐喻或创意命题；它必须影响视觉、文案、排版、动效与交互，而不是空洞口号。用户看完应能一句话说出这套皮肤独特在哪。
2. **有明确的艺术总监判断**：选定一种清晰一致的视觉语言；在字体栈、色彩、留白、材质、图形、节奏、动效上做**主动取舍**；不用“默认好看”的模板组合回避决策；避免无意义发光、无意义卡片、无意义动效。
3. **有值得探索的交互与状态**：界面要让用户一眼看懂“这是什么、能做什么”；悬停、聚焦、展开、选中、成功、失败、禁用都要有**有重量、有反馈**的表现；动效要有节奏与目的，**禁止把 opacity + translateY 的批量淡入当成主要动画方案**。
4. **真实的前端实现质量**：桌面与手机都可用；键盘可达；长文本可读；性能有意识（模糊、滤镜的用量要克制）。
5. **允许大胆，不允许半成品**：可以极简、编辑感、游戏化、诗意、实验性、艺术装置感——但每个显眼的选择都要有理由。

### 动效质量要求
把动效当作**编舞**而非“元素出现方式”：要有缓动层次、延迟关系、物理感、状态反馈。克制也可以，但克制必须是**有说服力的设计选择**（例如“面板绝不弹跳，一切都像被手推到位”）。

### 工作方式
1. 先读契约与参考素材，确认你理解了 DOM 骨架与令牌边界。
2. 再输出方案（见下方结构）。
3. 写完方案后，**以严格的创意总监身份自我审查**：概念是否贯穿？是否有模板感？是否有无意义动效？第一眼是否有记忆点？信息是否易懂？移动端与可达性是否成立？性能是否合理？逐项批评。
4. 根据批评**至少做一轮实质性修改**（不是改文案和颜色），把修改痕迹写进方案第 10 节。
