# 辉光管 · 皮肤设计方案（皮肤 id：`nixie`，按钮短名：辉光管）

> 阶段：第一阶段（设计方案）。本文件不含实现代码，只给取值、规则与实现思路。
> 依据：`docs/皮肤契约.md`（冻结版）。第 7 节逐条对齐契约 §3 的全部令牌；第 4 / 6 节只给 CSS 实现思路片段，不给成品规则。
> 建议方案：`scheme: 'dark'`（明暗两套都实现，暗色为正典，见 §3.1 末）。

---

## 1. 核心概念

**辉光管里没有像素。一个位置一共十片金属阴极，层层挡在后面，同一时刻只允许一片通电。**

所以这套皮肤的第一性规则不是配色，而是一条**状态律**：**每个位置上永远只有一个「亮」，其余全部保持为可见的暗金属。**

由此推出两条物理规则：

- **光是薄的、贴着轮廓的，且只向下和向外洒**——灯丝在面板上方，辉光打在面板上，绝不会在数字四周形成对称光晕。
- **铭牌是蚀刻的，只有数字发光**——老仪器上所有文字都是刻进金属的暗字，唯一亮着的是读数窗口。

一句话记住它：**蚀刻的标签，通电的读数；一次只亮一个。**

## 2. 用户体验路径

**第一次遇到（0–3 秒）。**
聊天楼层里出现两片暗哑的仪器面板：没有边框高光、没有渐变卡片、没有悬浮阴影，只是一块比聊天底色略深的金属板，表面有一层几乎看不见的竖网纹。眼睛**不会被整体吸引**，而是被板上唯一发光的东西吸走——右上角小窗口里的 `7 项`。用户先读到数字，再回头读标题（「行动选项」），因为标题是刻上去的暗字。信息层级的先后顺序，就是辉光管仪器的物理顺序。

**理解（3–10 秒）。**
不需要教程：铭牌暗、读数亮；未选中的分段键是凸起的哑金属，选中那个**凹进去并且下沿有一条亮线**。「凹陷 + 点亮 = 当前生效」这条规律在四五个组件上重复出现（分段、开关、标签页、选中卡片），用户看两次就学会，之后整个界面不再需要解释。折叠的思维链只显示一行铭牌和 `0 字`，想读的人点它——这是全界面唯一需要用户「学会」的动作，而它由一个凸起的、占满整行的大按键承担（整条头部即热区）。

**使用（持续）。**
展开瞬间是这套皮肤最值得看的一秒（见 §5.B）。读数、卡片、开关的每次响应都很短（90–170ms）且**从不回弹**：这是仪器的手感，不是 app 的手感。选项卡片被点中时，它背后那两片「没通电的阴极」会收回去、卡片落位、底边有一道电流扫过——用户会意识到自己刚才「把一片金属推进了插座」。

**记住。**
两个记忆点：① 选卡片时**层叠被抽开**的那一下；② 读数小窗里数字的**起辉**。第三个记忆点是安静的：在动辄两三千字的思维链里，这块面板是聊天中唯一「大部分是暗的」容器——正文落在最暗的底板上（`--kami-card-2`），长阅读反而不累。它不抢戏，但它一出现你就知道这是卡密预设。

**日常与降级。**
关掉动效它就是一台**断电但刻度还在**的仪器：所有状态仍然可读，因为「亮 / 暗」从来不只靠动画表达，也靠形状（凸起 / 凹陷）、轮廓（有无亮线）和材质（拉丝 / 玻璃高光）。

## 3. 视觉语言

### 3.1 色彩体系（以及为什么不是「黑底橙字」）

**底板不是黑色，是暖调的暗金属漆**（`#191612`，偏沥青棕的暖中性色）。这条决定是整份方案的分水岭：纯黑 + 橙 + 扫描线是「辉光管的照片」，而暖棕金属板 + 一处琥珀光是「辉光管所在的仪器」。前者看一眼就完了，后者有材质可以反复端详。

四层明度而不是三层：**读数窗口最暗（`#13100d`）→ 底板（`#191612`）→ 抬起的面板（`#1f1b15`）→ 悬停（`#272119`）**。文字永远落在**比自己更暗**的底上，这是长文本可读性的结构性保证（旧版前端在代码注释里明确写过「每块文字都落在实色上」的痛点，本方案把它变成色阶纪律：正文只允许出现在 `--kami-card-2` 或更暗处）。

**发光色是放电色，不是品牌橙。** 真正的氖放电在 585–600nm，近看是有白芯的橙。所以 `--kami-accent: #e8862c` 负责「作为颜色」（文字、描边、填充），`--kami-glow: #ff8a20` 只负责「作为光」（shadow 里的颜色），两者从不混用。**光永远比色亮，色永远比光稳。**

**语义七色 = 七种气体 / 指示灯，不是彩虹。** 契约要求按 `data-kami-kind` 着色，天真的做法是七种高饱和色，那会立刻把仪器变成糖果盒。这里的翻译是：七种标签是**仪器上七只不同充气的小指示灯**，全部限制在低面积（徽章字 + 1px 线）上，且必须与蚀刻文字同时出现，永不作为大面积填充。

| kind | 气体 | 取值 | 对底板对比度 |
|---|---|---|---|
| action 行动 | 氖 · 橙（本机主色） | `#e8862c` | 6.7:1 |
| persona 性格 | 氩 · 紫 | `#a685d8` | 6.0:1 |
| plot 推进 | 氪 · 绿 | `#6fb98a` | 7.7:1 |
| info 信息 | 汞 · 青 | `#63b9c9` | 8.0:1 |
| fun 搞笑 | 钠 · 黄 | `#d9b23f` | 9.0:1 |
| nsfw | 氦 · 绯 | `#d9637f` | 5.2:1 |
| other 其他 | 未充气 · 灰 | `#9a9186` | 5.8:1 |

**明暗两套是两台不同的仪器，不是同一台的调色。** 暗色是正典：**亮 = 发光**。亮色（`data-kami-scheme="light"`）是「日光下的仪器 / 陈列柜里的藏品」：象牙搪瓷面板（`#e8e2d6`）、深棕蚀刻字，**通电的定义反转为「实心琥珀底 + 深色字」**（`#9b4210` + `#fffaf2`），辉光半径压到接近 0——白板上画光是看不见的，这是物理事实而不是妥协。两种极性共享同一条规则：**亮 = 相对底板的最大局部对比 + 一处暖色标记**。亮色模式被明确声明为**次要模式**，优先保证金暗模式的完成度。

### 3.2 字体栈与理由

**只有一套字体。** 系统里不存在可靠的「仪器体」，硬凑一套 webfont 既违反约束，又会在不同设备上崩坏版式。所以标题与正文**共用同一个家族**，靠**字重、字距、蚀刻 / 发光两种处理**来区分——这恰好是真实仪器的做法：铭牌和读数用的是同一台机器刻的同一套字形，区别只在有没有通电。

- 正文 / 标题：`system-ui, -apple-system, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans SC", sans-serif`
- 读数 / 原文：`ui-monospace, "SFMono-Regular", "Cascadia Mono", "Consolas", "Roboto Mono", "DejaVu Sans Mono", monospace`
- 读数一律带 `font-variant-numeric: tabular-nums` 与 `font-feature-settings: "tnum" 1, "zero" 1`——**斜杠零**是仪器数字的身份证。这个细节几乎不花成本，但让「7 项」看起来像仪表而不是网页。
- 标题字距 `--kami-ls-title: .18em`：金属铭牌上的字永远是拉开间距冲压出来的，中文标题因此获得「刻上去」的气质（「行动选项」四字在 320px 下约 71px，实测可容纳）。
- `--kami-fs-xs` 只允许用于**非阅读性文字**（阴极编号、单位、角标）；任何需要被读的句子最小 `--kami-fs-sm`。

### 3.3 材质与图形语言

五种材质，全部**静态、零运行时、零外部资源**：

1. **拉丝金属**：1–3px 周期的水平细纹（alpha 1–1.6%）。它只在**容器级**出现一次，卡片永远是平的——纹理重复会立刻变成壁纸。
2. **阳极网**：辉光管里最容易被忽略、最能一眼定性的东西。真实照片里数字前面总隔着一层金属网。实现是**单向竖丝**（4px 周期、alpha 2.2%）+ **每 24px 一根支撑横丝**（alpha 3%）。刻意只用单向网，避免两组 repeating-gradient 产生摩尔纹（移动端的摩尔纹会随着手指动，非常廉价）。
3. **玻璃**：不用 backdrop-filter。玻璃感由三样东西完成——顶部 1px 亮边（凹面玻璃接住顶光）、四周极淡的内壁暗角、灯珠里那根**肉眼可见的灯丝**。三样加起来成本几乎为零，比模糊更像玻璃。
4. **蚀刻**：所有非读数文字用 `text-shadow: 0 -1px 0 <暗>, 0 1px 0 <微亮>` 做凹刻（光来自面板上方），并用 5% 亮度的下沿保证「刻痕」读得出来。**蚀刻只用于对比度 ≥6:1 的文字**，否则刻痕会把可读性吃掉。
5. **铆钉与切角**：`.kami-drop` 四角用单个 `background-image` 的四段 radial-gradient 画出 4 颗 1.5px 铆钉（alpha 6%），右下角一道 45° 切角暗楔。这是给「愿意凑近看」的人的奖励，代价为一次静态绘制。

**图形母题的优先级：阳极网 > 刻度线 > 铆钉 > 任何装饰符号。** 网是「看得见的结构」，刻度是「可读的量」，铆钉是「存在的证据」。皮肤里不出现任何与辉光管无关的装饰图形。

### 3.4 留白与节奏

- 全部间距取 **4 的倍数**，主档只有 8 / 12 / 16 三档（`--kami-gap: 8px`、`--kami-gap-lg: 12px`、正文段间 16px）。仪器面板上的空气是被刻度约束的，不是被审美直觉约束的。
- **上方永远比下方松**：读数窗口上方留白 = 下方 × 1.5。物理上因为光从上往下打，视觉上因为这会让「亮部在上、读数在下」的层级自然成立。
- **一处通电，其余沉寂**：每个组件内部只允许一个「亮部中心」。头部的亮部中心是读数小窗；卡片列表的亮部中心是当前悬停 / 聚焦的那一张；面板的亮部中心是选中的标签页与它的下沿亮线。
- 密度档位不是「缩放」而是**换仪器**：`compact` 是密集读数档（间距 ×0.75、圆角 3px→2px、字距收窄），`roomy` 是实验室档（间距 ×1.35、允许刻度底纹出现、卡片抬升幅度加大）。三档保持完全相同的状态语法。

## 4. 组件设计

> 全局纪律两条：
> ① 皮肤必须自带 `html[data-kami-skin="nixie"] .kami-root [hidden] { display: none !important }`——因为我们会在别的规则里改 `display`，而契约里 `.kami-raw` / `.kami-toast` 依赖原生 `hidden`。
> ② 组件命名空间内**绝不出现** `100vh`、视口单位（脚本面板的 `vw` 除外，它跑在酒馆页面上）、`position: fixed`、`backdrop-filter`（除面板内的 `.kami-toast` 这一处小面积）。

### 4.1 外壳 `.kami-shell` / `.kami-drop`

一块**不透明的**仪器面板。不透明是刻意的：光必须落在自己的面板上；半透明 + 无模糊会让下方聊天文字透上来，长思维链会直接不可读（旧版实现就踩过这个坑）。它也是本皮肤拒绝玻璃拟态的地方。

- 底：`--kami-bg` + `--kami-texture`（拉丝 + 竖网 + 顶部溢光 + 底部暗角，共 4 层静态渐变）。
- 边：不画统一描边，而是**倒角**——顶部 1px 冷白高光（`inset 0 1px 0 rgba(255,236,214,.055)`）、底部 1px 深影（`inset 0 -1px 0 rgba(0,0,0,.5)`）、外圈 1px 极淡玻璃环。光永远从上下来，所以边缘也必须上亮下暗，「面板是凸起的金属」才成立。
- 圆角只到 `--kami-r-md: 4px`（`.kami-drop` 用 `--kami-r-lg: 6px`）。**全皮肤没有药丸形**（`--kami-r-pill: 2px`）。
- `isolation: isolate`：让特效层里的 `mix-blend-mode: screen` 只在面板内部混合，不污染酒馆页面。
- **不设 `overflow: hidden`**：否则选项卡片后面的层叠阴影会被裁掉。裁切只用在思维链正文（见 4.9）。
- `--kami-surface-clip: none`：切角用暗楔渐变实现，不用 `clip-path`——`clip-path` 会连 `box-shadow` 一起剪掉，而层叠 / 辉光全靠 shadow，得不偿失。

### 4.2 头部 `.kami-head`

一条 40px 高的**面板接缝**：左侧灯珠 + 蚀刻铭牌 + 读数，右侧动作区，底部 1px 分界线（`--kami-line`，只在左侧 60% 处渐隐）。

- `min-height: var(--kami-row-h)`（40px）：在思维链里整个头部就是「展开」的点击热区，必须够大。
- 右侧动作区里的分段键与图标键要**内缩**：给分段键留出至少 8px 外边距，这样「点歪一点也想展开」的用户不会误触模式切换。
- `.kami-title` 需要 `min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap`，`.kami-sub` 用 `flex: none`——320px 下这是不炸行的关键。

### 4.3 标题与副信息（这套皮肤的招牌）

**铭牌是蚀刻的，读数是通电的。** 这是全皮肤最重要的一条排版规则：

- `.kami-title`——**暗色、拉开字距、凹刻**。永远不发光。这是「这台仪器叫什么」的铭牌。
- `.kami-sub[data-kami-role="count"]`——**读数窗口**：一个凹陷的小窗（`--kami-bg-soft` 底 + 内阴影 + 1px 深描边），里面是等宽数字、琥珀色、下沿一条 1px 亮线，以及一段 3px 的向下溢光；窗口顶部有一条玻璃高光。它就「7 项」三个字，但整个界面的视觉重心在这里。

原因：辉光管仪器的信息层级本来就是「标签是刻的、数字是亮的」。把所有标题做成发光文字是最俗套的做法（而且满屏发光会让标题失去层级）；把**只有数字发光**这条物理事实翻译成排版规则，就同时得到了层级、记忆点和克制。

- 其余 `.kami-sub`（提示类副信息）沿用蚀刻处理，颜色 `--kami-fg-mute`。
- 读数窗口宽度按内容自适应，并给 `min-width: 3.4em`，让 `0 字` → `1240 字` 变化时头部不抖动。

### 4.4 按钮层级

三种按钮 = 三种开关：

1. **`.kami-btn--ghost`（复制等次要动作）＝ 未通电的按键**：哑金属键帽，顶部 1px 高光、底部 1px 深影、蚀刻文字。悬停时**只有键帽下方 4px 处出现一道极淡的暖色下落光**（不对称！），按键本身不变亮。按下 = `translateY(1px)` + 高光消失 + 底下那道光被压灭——「按到底，光被挡住」。
2. **`.kami-btn--primary` ＝ 通电的按键**：实心 `--kami-accent` 底 + `--kami-accent-fg` 深色字 + 下方 5px 溢光。全组件只允许一个 primary（辉光预算见 §10 批评 B）。
3. **`.kami-icon-btn` ＝ 仪器小键**：26–32px 方形、2px 圆角，蚀刻字形。悬停时**只有字形亮**（键帽不动）；`aria-pressed="true"` 或 `.is-on` 时键帽凹陷 + 字形常亮。`[data-kami-act="close"]` 悬停时字形与描边转为 `--kami-warn`——仪器上的关机键本来就该被标出来。

**行程与节奏**：按下 90ms、回弹 160ms。快进慢出，永不弹跳（唯一例外是开关，见 4.10）。

### 4.5 分段切换 `.kami-seg` / `.kami-seg-item`

**双位读数窗。** 整个 `.kami-seg` 是一个凹陷的深槽（`--kami-bg-soft` + 内阴影 + 1px 描边），槽里两个「数字位」：

- 未选中：凸起的哑金属小键，`--kami-fg-dim`，**顶部有一条极细高光**（凸起）。
- 选中（`.is-on`）：凹进槽底、底色更暗、**下沿一条 1px 琥珀亮线 + 文字发光**（`text-shadow: 0 0 1px, 0 1px 4px`，alpha ≤ .35）。
- 状态差异同时由**形状（凸 / 凹）+ 亮线（有 / 无）+ 颜色**三重表达，不依赖色相，灰度下依然可读。
- 切换时：新选中项的下沿亮线用一个 200ms 关键帧**过亮一次再落回**（起辉），旧选中项的光用 200ms 过渡**衰减**（去离子），槽体本身不动。
- 320px 下按键内边距压到 6px / 9px（用容器查询，见 §8.1）。

### 4.6 卡片 `.kami-card` / 列表项 `.kami-item`

**卡片 = 一片阴极。** 这是「层叠」母题的落点：

- 卡片本身是一块平板（`--kami-card`），顶部 1px 高光、外圈 1px 暗线，**没有柔和投影**。
- 未选中时，卡片背后有**两片更暗、更小、向右下错开的金属层**——用一个 `box-shadow` 的两段零模糊偏移实现（`4px 4px 0 -1px`、`7px 7px 0 -2px`，颜色是比底板更暗的两个色阶），**不新增元素、不新增伪元素**。这正是辉光管「十片阴极叠在一起」的直接翻译：你能看见后面还有东西，但它们没通电。
- 悬停（仅 `@media (hover:hover)`）：卡片**抬起 2px 并向左上**，背后的层叠**同时收紧**（偏移缩到 2px / 4px）——视觉上就是「把一片金属从叠层里抽出来」。同时卡片下沿出现一道 6–12px 的暖色下落光，投在底板上。
- 按下：行程压回 0、层叠归零、底边一道 1px 琥珀线 `scaleX(0)→1`（140ms，`transform` 驱动）= 电流通过。松手后卡片会保持 `:focus`（浏览器天然如此），此时它保留一点微弱暖调——**「刚用过的那一片还是温的」**，这是免费得到的一个有意义的状态。
- 卡片内部用**栅格分栏**：左侧 2.1rem 的编号槽（见 §6 的 `counter` 特效，含一条 1px 竖向接缝），右侧上排 `.kami-card-head`、下排 `.kami-card-body`。这样「编号 / 徽章 + 标题 / 正文」三层信息在窄屏下依然有清晰的对齐轴。
- 标题单行截断；**正文不截断**——选项正文就是内容本体，宁可多两行。
- `.is-demo`（示例数据）：编号槽与动作符熄灭为 `--kami-fg-mute`，卡片右侧出现一条 1px 虚线接缝，整体降一档对比。**用「未接线」表达「点了没用」，而不是变灰。**

### 4.7 列表与网格 `.kami-grid` / `.kami-list`

- 网格：`repeat(auto-fill, minmax(var(--kami-items-min), 1fr))`，`--kami-items-min: 17rem`。320px 聊天宽 → 1 列；约 570px → 2 列；约 850px → 3 列。
- 同行卡片等高（`align-items: stretch`），`.kami-card-body` 允许内容撑高，不裁切。
- `.kami-list` 的主轴由 `--kami-list-dir` 控制（默认 `column`），`--kami-justify` 控制对齐（默认 `stretch`）；`.kami-grid.kami-list` 组合下网格自己按行流动（`grid-auto-flow: row`）。
- 网格只负责排布，**不画任何背景**——列表看起来应该是「插在面板上的一排片子」，不是「卡片放进容器」。

### 4.8 徽章 `.kami-chip` / `.kami-badge`

**冲压标签**，不是药丸。

- 2px 圆角、1px 描边（kind 色 42% alpha）、文字用 kind 色**实色**、底是 kind 色 10% alpha。
- 字距 `.08em`、`--kami-fs-xs`、`text-transform: uppercase`（对中文无影响，对 `NSFW` 这类拉丁词正好）。
- 徽章上下各留 1px 亮 / 暗边，做出「嵌进面板的金属牌」的感觉。
- **徽章永不发光**，即使卡片被选中——发光预算留给真正的状态。

### 4.9 折叠区 `.kami-collapse`

思维链的外壳。

- 收起（`data-kami-open="0"`）：**只显示头部**。头部右侧 chevron 是一个机械指示器（见 §5.E），此时是暗的。
- 展开（`data-kami-open="1"`）：`.kami-collapse-body` 以「起辉前缘」展开（§5.B）；展开后正文落在 `--kami-card-2`（全皮肤最暗的一层）上，左侧 3px（`--kami-accent-mark`）亮条只覆盖正文块的前 40% 高度并向下渐隐——像一根被点亮的阴极丝，而不是一条通到底的装饰线。
- **收起不做高度动画**。收起 = 断电：正文立即消失，只有壳体上的余辉用 340ms 过渡退掉、chevron 熄灭、下沿亮线缩回。理由见 §5.C 与 §10 批评 E。
- **裁切只在这里用**：正文展开用 `clip-path: inset(0 0 100% 0)` → `inset(0)`。选项卡片永远不放进被裁切的容器里（层叠阴影会被切掉）。

### 4.10 表单控件

**滑杆 `.kami-range` ＝ 直线电位器。**
- 槽：4px 高的**沉槽**（`--kami-bg-soft` + 内阴影），槽上下各 4px 露出一排**刻度**（`repeating-linear-gradient`，1px / 8px 周期，alpha 6%，每第 5 根更亮）——刻度是刻在面板上的，槽是铣出来的。
- 通电区段：槽底部一条 2px 琥珀线，只到滑块位置。**前端若写入 `--kami-value`（0–1），可用 `background-size: calc(var(--kami-value) * 100%) 100%` 填充；未写入时退化为全暗槽 + 仅靠滑块位置表达**（依赖已列入附录 A）。
- 滑块 = **滚花旋钮**：14×22px、2px 圆角、竖向滚花纹（`repeating-linear-gradient` 2px），顶部高光、底部深影，正中一条 1px 蚀刻刻线。
- 交互：悬停时旋钮四周亮起 1px 琥珀描边；`:active`（拖动中）描边更亮 + 下方溢光加大——**「拉动的电流变大了」**。
- 键盘可达：`:focus-visible` 时整条槽的刻度亮起（刻度线颜色过渡），给出比 outline 更明确的「你正在调这条轨」。

**数字输入 `.kami-number` ＝ 读数窗。**
- 与读数小窗同一套材质：凹陷、`--kami-bg-soft`、内阴影、等宽数字、右对齐（仪器读数总是右对齐）、琥珀色。
- 原生步进器保留（鼠标可用性），用 `opacity` 与 `width` 收窄后靠右，悬停提亮；不追求跨浏览器完美，重点保证键盘与触屏可用。
- 输入无效时用 `--kami-warn` 描边 + 一条 1px 左竖条，不用红色填充。

**开关 `.kami-switch` ＝ 刀闸。**
- 轨：2px 圆角的**沉槽**（`--kami-bg-soft` + 内阴影），槽两端各有一枚 4px **指示灯**（`.kami-switch-track::after`）：关是暗玻璃，开是琥珀常亮 + 一点溢光。
- 钮：滚花金属手柄（与滑杆旋钮同一材质语言，但为矩形），行程 22–26px，顶部高光 + 底部 1px 深影。
- 动效：**全皮肤唯一允许过冲的地方**——200ms、`cubic-bezier(.34,1.56,.64,1)`，因为刀闸确实会「咔哒」一下卡到位。开的时候槽内从「开」的那一端泛起一点琥珀色（`linear-gradient` 方向随 `input:checked` 翻转）= 指示灯照亮了槽。这一处例外是刻意的：正因为别处从不弹跳，这一下的机械感才被听见。
- 键盘：`input:focus-visible` 时给整轨 1px 琥珀描边（焦点画在可见的轨上，不是画在视觉隐藏的 input 上）。

### 4.11 面板与抽屉 `.kami-drop`

仪器机箱。

- 底板比内嵌面板更重：`--kami-shadow`（向下的长投影）+ 四角铆钉 + 右下 45° 切角暗楔 + 外圈 1px 玻璃环。
- 头部 = **铭牌条**：标题在左、最小化 / 关闭在右，底部 1px 接缝。头部没有背景色差（仪器面板的分区靠接缝，不靠色块）。
- 标签页 `.kami-tabs`：一条**沉轨**上的机械琴键。未选中 = 凸起哑键；选中（`aria-selected="true"`）= **压进轨道**（内阴影反转）+ 下沿一条 2px 琥珀亮线，并有一道向下 6px 的溢光落在面板上。轨道下方 1px 接缝把标签区与内容区分开。
- 打开（`[data-kami-open="1"]`）：起辉前缘从顶边向下扫过一次（220ms，见 §5.B），随后稳定。关闭不做动画（面板消失 = 断电）。
- `.kami-resize` 尺寸把手：右下角 **18×18px 滚花握把**（两排斜向 1px 纹），平常 alpha 45%，悬停时纹路亮起 + 出现 1px 琥珀描边。
- **布局（需要前端保证）**：`.kami-drop` 用 `display: flex; flex-direction: column`，`.kami-body.kami-scroll` 用 `flex: 1 1 auto; min-height: 0; overflow-y: auto`，面板高度 `height: var(--kami-panel-h); max-height: 100%`。因此宿主要把 `.kami-root[data-kami-comp="panel"]` 铺在一个至少覆盖视口高度的定位容器里——见附录 A。**皮肤内不出现任何视口高度单位。**

### 4.12 滚动条 `.kami-scroll`

**刻度槽 + 滑块。** 滚动条在这个皮肤里不是系统装饰，而是又一根电位器：

- 槽：6px 宽，`--kami-bg-soft`，左右各 1px 内阴影（铣出来的槽）。
- 滑块：2px 圆角金属块，顶部高光、底部深影、表面竖向滚花；悬停时**滑块亮起琥珀描边**，拖动时（`:active`）亮起 1px 琥珀中线。
- WebKit 用 `.kami-scroll::-webkit-scrollbar` 系列；Firefox 用 `scrollbar-width: thin; scrollbar-color: <滑块色> <槽色>`（降级为纯色，可接受）。
- 滚动条**只存在于脚本面板**：消息楼层 iframe 不能滚动，相关规则限定在 `[data-kami-comp="panel"]` 之下，避免内嵌前端出现「以为能滚」的视觉暗示。

### 4.13 空态 `.kami-empty`

**未通电的窗口。** 一块凹陷暗窗（1px 虚线刻痕边框，`--kami-fg-mute` 的 35%），左侧一枚 4px 待机灯珠以 4.7s 周期极缓呼吸（仅在 `idle` 特效开启时）。文字用 `--kami-fg-mute`、`--kami-fs-sm`，居左。

**文案由前端决定，皮肤不生成任何文本**（除 §6 的阴极编号）。皮肤只保证：空态看起来像「这里本来该有个读数，只是现在没有」。

### 4.14 内联提示 `.kami-toast`

面板内的浮层读数。`position: absolute`（组件内相对定位，符合契约「不 fixed 铺满」）。

- 外形：小读数窗（`--kami-bg` 底 + 1px `--kami-line-strong` 描边 + `--kami-shadow`），等宽字，`--kami-fs-sm`。
- 入场：从左到右一道 1px 琥珀线扫过窗底（`transform: scaleX(0)→1`，160ms）+ 窗框下沿亮起 → 稳定。定位在组件中上（`left: 50%`）。
- 这是**唯一允许使用 `backdrop-filter: blur(var(--kami-blur))` 的元素**（面积小，且 `--kami-blur` 默认 `0px`，等于不用）。这样令牌有真实落点，又不会让每个楼层都背上模糊开销。
- `.is-bad`：描边转 `--kami-warn`，入场动画改为**双闪**（两次 60ms 断续起辉）——真实的坏管子就是在起辉失败时先闪两下。失败文案由前端给。

## 5. 动效编舞

**总原则：同一时刻只允许一个「主运动」。** 主运动只有一个形状：**起辉前缘**（一道 1px 琥珀亮线沿容器边缘扫过）。它出现在三处——思维链展开、面板打开、楼层首次渲染——除此之外全皮肤再无第二种「主要动画」。其余一切都是 ≤170ms 的状态响应。

**缓动的两层**：`--kami-ease` = `cubic-bezier(.2,.72,.24,1)`（机械落位：起步快、到位稳、**永不过冲**）；`--kami-ease-out` = `cubic-bezier(.4,0,.1,1)`（前缘推进：先匀速后长收尾）。没有弹跳缓动，除了开关那一次。

**速度阶梯**：`--kami-dur-fast: 90ms`（按下）/ `--kami-dur: 170ms`（状态切换、悬停）/ `--kami-dur-slow: 340ms`（起辉、余辉衰减）。

### A. 入场（首次渲染 = 开机自检）

**关键决策：容器不做入场动画。** 面板不是「淡入出现的卡片」，而是「本来就在那里的一块板子，上面的东西依次通电」。所以没有整体 opacity 淡入、没有 translateY 滑入、没有 scale 缩放（`--kami-enter-scale: 1`，这是刻意的「零缩放」取值）。

| t | 事件 | 实现 | 时长 |
|---|---|---|---|
| 0 | 底板 / 网纹 / 蚀刻铭牌**直接呈现** | 静态 | — |
| 0 | 灯珠起辉：灯丝先亮（60ms），再泛出玻璃内的辉光 | `color` 过渡 + 玻璃 `background` 过渡 | 240ms |
| 80ms | 读数窗口起辉：一次 1 帧的过亮 → 落回稳态 | `@keyframes`（`color` / `text-shadow`） | 260ms |
| 160ms | 分段键自左至右依次通电（步长 32ms） | 下沿亮线关键帧 + `animation-delay` | 200ms |
| 200ms | 卡片依次起辉，抬升 2px 落位（`--kami-enter-y: 2px`） | transform + 亮线关键帧 | 240ms |

**错峰上限**：`--kami-stagger: 32ms` 只给前 6 项；第 7 项及以后并入同一档延迟（约 190ms）。理由：12 个选项若线性错峰会长达 380ms，用户已经读完第一张卡片了最后一张才亮——错峰必须短于人的阅读节奏，否则它不是编舞而是卡顿。

**物理感**：所有起辉都是「电流上升」，用 `color` / `box-shadow` / `opacity` 表达；唯一的位移是卡片那 2px，方向朝上（被推入插座）。整段自检在 600ms 内结束。

### B. 展开思维链（本皮肤的主运动）

三层同时进行，但只有一个主角：

1. **主角 · 起辉前缘**（0→300ms，`--kami-ease-out`）：`.kami-surface::before` 是一个 `inset: 0` 的整层元素，背景只有顶部 2px 是亮的（1px 琥珀线 + 下方 4px 渐隐），动画只做 `transform: translateY(100%)`——**纯合成属性，不触发重排 / 重绘**。前缘扫过的同时 `opacity` 从 .85 降到 .25（扩散后变淡）。
2. **副线 · 正文展开**（0→300ms，`--kami-ease-out`）：`.kami-collapse-body` 用 `clip-path: inset(0 0 100% 0) → inset(0)`。文字不是淡入的，是**被前缘照亮**的——前缘到哪里，哪里才出现内容。这一条把「展开」从一个通用动画变成了这套皮肤专属的动作。
3. **余韵 · 壳体闪光**（0→340ms）：`.kami-shell` 的 `box-shadow` 关键帧过亮一次再回落到稳态辉光。这是全皮肤唯一允许的 `box-shadow` 关键帧动画，只作用于小面积外壳，且只在用户主动展开时发生一次。
4. **收尾**（300→460ms）：正文底部的动作区（复制键）从 `--kami-fg-dim` 过渡到 `--kami-fg`（`color` 过渡，不做透明度）——「末端的元件最后通电」。

### C. 收起（断电）

**正文瞬间消失，不播放任何退出动画。** 理由有二：① 技术上，`hidden` 元素无法播放退出动画，硬做就需要给正文做高度动画，而楼层 iframe 的高度等于 `body.scrollHeight`，高度动画会让整个聊天在 300ms 内持续重排、下方内容一直抖动——代价远大于收益；② 概念上，**断电本来就是瞬时的**：切断电流，辉光立刻消失，没有淡出。

留下来的只有**余辉**：壳体的辉光用一个 340ms `box-shadow` **过渡**退掉（过渡在 1→0 时触发，所以加载时不会误播），chevron 用 160ms 熄灭并旋回 0°，正文下沿亮线用 200ms 缩回。用户看到的是「内容不见了，但板子上还有一点点温」。

### D. 状态切换（分段 / 标签页 / 开关 / 选中）

- 新选中：下沿亮线 200ms 过亮一次再落回（起辉）；旧选中：光 200ms 衰减（去离子）。
- 标签页切换：**只动状态，不动内容**——内容区没有滑动、没有淡入，因为在仪器上切换标签就是「另一个读数窗口亮了」。用户不会因为内容跳变而迷失，因为标签键的凹陷与亮线一直在告诉他「现在在哪一档」。
- `aria-selected` / `.is-on` / `input:checked` 三条状态路径使用完全相同的视觉语言与时长。

### E. 悬停与聚焦

- **悬停只做三件事**：卡片抬升 2px、背后层叠收紧、「通电元素」从一个变成三个（编号槽、类型徽章、动作符 `↵` 依次亮起，步长 40ms）。没有缩放、没有颜色反转、没有整卡变亮。
- 动作符 `↵` 不做位移动画（那是通用 app 语言）；它**点亮**——一个 1px 琥珀字形 + 极短的下落光，像一个小指示灯。
- 悬停总时长 170ms，且全部包在 `@media (hover:hover)` 里——手机上不存在「悬停后底色粘住」的问题（契约要求 `--kami-card-hover` 必须不透明，本皮肤遵守：`#272119`）。
- **聚焦 `:focus-visible`**：1px 琥珀描边 + 2px 偏移 + 一圈 1px 底板色隔离环（防止描边与复杂底纹打架），同时该元素的蚀刻文字用 90ms 过渡翻到 `--kami-fg`。网格里的卡片聚焦时 `z-index: 1`，避免描边被相邻卡片压住。
- `:focus`（非 focus-visible）：只保留一点暖调，作为「最近用过的这一片还是温的」状态。

### F. 按下与成功 / 失败

- **按下**（90ms 进 / 160ms 出）：`.kami-item` 层叠归零、卡片落位 1px、底边琥珀线 `scaleX(0)→1`（140ms，transform）。
- **成功 = 继电器吸合**：按下后键帽保持 120ms 才回弹（不需要 JS，用 `:active` 与不对称过渡时长即可读到「多停了一下」），配 `.kami-toast` 的窗底扫光。**成功不使用绿色**——本皮肤里没有绿色成功态，成功就是「通电了」。
- **失败 = 起辉失败**：`.kami-toast.is-bad` 用双闪（两次 60ms 断续），描边转 `--kami-warn`，同时触发它的那个元件保持 `--kami-warn` 描边 340ms。失败有抖动感，但不位移。
- **禁用 / `.is-demo`**：不是变灰，是**断线**——编号槽与动作符熄灭、接缝变 1px 虚线、整体降一档对比；按下时完全没有行程。

### G. 长文本渲染

- **不做逐段错峰**：一段两三千字的思维链若按段落依次淡入，一是每段动画都会触发一次重绘（成本随文本长度线性增长），二是用户在读第二段时第七段还在跳，观感是「卡」而不是「美」。取消这一条是本方案自审后做出的实质性删减（见 §10 批评 D）。长文本的唯一动效就是 §5.B 那一次前缘扫过。
- 长文本的「动效预算」改为花在**排版**上：`--kami-lh: 1.68`、段间 16px、`text-wrap: pretty`（避免孤字行）、`overflow-wrap: anywhere`（长 URL 不撑破）；`.kami-md` 内的层级用字号 + 刻度线表达而不是颜色。
- **明确不用 `content-visibility: auto`**：它会跳过屏外内容的渲染，而楼层 iframe 的高度由 `body.scrollHeight` 决定——被跳过渲染的部分高度会退化，iframe 会变矮、内容被裁掉。这是一个看起来能省性能、实际上会破坏宿主的陷阱，写进纪律。
- **明确不用滚动驱动动画**：内嵌前端根本不滚动。

### H. `data-kami-motion="off"` 与 `calm` 的降级

契约要求的两块兜底必须都在，并且**所有动画时长都由 `--kami-dur-*` 令牌驱动**（不写死毫秒），这样降级是自动的。在此之上再加一层保险：

- `off`：契约规定的令牌覆盖块（时长 1ms、`--kami-enter-y: 0px`、`--kami-stagger: 0ms`）+ 一条兜底：`animation-duration: 1ms !important; animation-delay: 0ms !important; transition-duration: 1ms !important`（作用域限定在 `.kami-root` 及其后代）。前缘不再扫动、卡片不再抬升、灯珠不再呼吸。**状态依然 100% 可读**，因为状态由形状与亮线表达，不依赖动画。
- `calm`（本皮肤建议新增的一档：**稳定电流**）：时长放慢到 150 / 280 / 520ms，`--kami-stagger: 0ms`，关掉灯珠的呼吸与偶发闪烁（`idle` 的循环停止，保持静态辉光），保留所有状态切换。给的是「仪器接在恒流源上工作」的观感。
- `prefers-reduced-motion: reduce`：与 `off` 完全等价的处理（时长 1ms + 关闭循环动画），不依赖 `data-kami-motion` 是否被脚本设置。

## 8. 响应式与可达性

### 8.1 三档宽度

**320px（必须先成立）**
- 容器查询（`.kami-shell { container-type: inline-size; container-name: kami-shell }`）：
  - `@container kami-shell (max-width: 21rem)`：关掉 `counter` 编号槽（`grid-template-columns: 1fr`），卡片内边距降到 11px——320px 下正文列宽从 202px 回到 240px。
  - `@container kami-shell (max-width: 19rem)`：`--kami-ls-title` 降到 `.08em`、分段键内边距降到 6px / 9px。
- 头部：`.kami-title` 单行截断 + `.kami-sub` 不收缩 + 动作区 `flex: none`；`.kami-actions` 允许 `flex-wrap: wrap` 作为最后保险（换行而不是溢出）。
- 网格 1 列；卡片正文自然换行；`--kami-row-h: 40px` 保证所有可点元素 ≥40px 高。
- 全部间距为 4 的倍数，320px 下不存在 `min-width` 超过 240px 的块。
- **降级预案**：若 lint 或目标浏览器在 `@container` 上有问题，改用「`--kami-items-min` + `auto-fill`」的自适应 + 标题允许两行作为兜底，编号槽改为 `flex` 版本。

**平板（约 600–900px）**
- 网格 2 列；读数窗口维持固定宽度不拉伸；面板宽度仍取 `min(23rem, 92vw)`，不做全宽——仪器面板不该变成大白板。
- 悬停态开始生效（`hover: hover`），层叠抽出的动效在这一档最明显。

**桌面（≥1024px）**
- 网格 3 列；`roomy` 密度下允许刻度底纹出现在面板左轨；`halo` 特效在这一档才有意义（大屏上才看得出溢光）。
- 面板仍不使用视口高度单位，高度由 `--kami-panel-h` 与 `max-height: 100%` 决定。

### 8.2 键盘与焦点

- 全皮肤**绝不移除轮廓**：`:focus-visible` 统一为 1px `--kami-accent` 描边 + 2px 偏移 + 1px 底板色隔离环。
- 网格内卡片聚焦时 `z-index: 1`，防止描边被相邻卡片裁住。
- `.kami-range` / `.kami-switch` 的焦点画在**可见的轨上**（真正的 `input` 是视觉隐藏的），保证纯键盘用户看得见自己在哪里。
- `.kami-collapse-head` 是 `role="button" tabindex="0"` 的 div，其内部又嵌了两个真实的 `.kami-seg-item` 按钮——这是冻结骨架里既有的嵌套可交互结构。皮肤无法修正语义，但能做到两件事：给头部一个明显更大、更「沉」的聚焦态（整行描边 + 铭牌全部提亮），给分段键一个更小、更贴身的聚焦态（描边只包住键本身），让键盘用户一眼分清「焦点在整条头部」还是「焦点在某个模式键」。
- 触控热区：头部 ≥40px；分段键 ≥32px 且与头部边缘保持 8px 以上内缩。

### 8.3 对比度

- 正文（`--kami-fg`）对 `--kami-card-2` 约 13.4:1；对底板 12.0:1。
- 次要（`--kami-fg-dim`）6.7:1；最弱（`--kami-fg-mute`）4.7:1 —— 全部 ≥4.5:1。
- 蚀刻只在 ≥6:1 的色阶上使用，且暗色刻痕 alpha ≤ .5，衰减后仍 ≥4.5:1。
- 七种语义色对底板 5.2–9.0:1（见 §3.1 表），作为文字使用时全部达标。
- 亮色模式：正文 `#2b261d` 对 `#e8e2d6` 约 11.8:1；accent 作文字 5.1:1；accent 底上的字 6.3:1。

### 8.4 状态不只靠颜色表达（色盲与灰度打印同样成立）

| 状态 | 除了颜色以外还变了什么 |
|---|---|
| 选中（分段 / 标签页） | 形状：凸起 → 凹陷；多一条下沿亮线 |
| 选中（卡片 / 列表项） | 层叠阴影消失 + 抬升 2px + 编号点亮 |
| 开关 | 手柄位移 22–26px + 端部指示灯亮 / 灭 |
| 悬停 | 抬升 2px + 层叠收紧 |
| 聚焦 | 描边 + 隔离环（几何，不是色相） |
| 禁用 / 示例 | 接缝变虚线 + 编号与动作符熄灭 |
| 失败 | 双闪 + 描边转 warn |

### 8.5 降级

`prefers-reduced-motion: reduce` 与 `data-kami-motion="off"` 均执行：所有时长 1ms、停用循环动画、`--kami-enter-y: 0px`、`--kami-stagger: 0ms`。此时界面等价于「断电但刻度齐全」的形态，所有信息与所有状态仍然可读。

## 9. 主动「不做」的三件事

**① 不做扫描线 / 噪点 / 颗粒叠加。**
扫描线是「辉光管的照片」里才有的东西，不是辉光管本身；它还是最廉价的「复古科技」符号。代价与收益也不成立：它会让每个聊天楼层都多背一层覆盖整个面板的纹理，在移动端高 DPI 屏上产生摩尔纹与细密抖动，长时间阅读最伤眼。**我们唯一的「网」是物理上的阳极网**（竖直金属丝），它有物理依据、单向、无摩尔纹，看起来是「隔着东西看」，而不是「信号有毛病」。
*放弃的是*：一个几乎零成本、立刻被认出「哦这是复古」的捷径。

**② 不做玻璃拟态与大面积模糊（`--kami-blur: 0px`）。**
性能层：这份 CSS 会注入每一个聊天楼层，`backdrop-filter` 会让浏览器为每块面板单独合成并重采样其**背后的整个页面**——楼层越多，代价越线性放大。设计层更关键：玻璃是当下 UI 的通用语，它会让这台 1960 年代的仪器瞬间变成一张 app 卡片，把「光落在自己的金属板上」的整个叙事抽掉。**玻璃感用 1px 顶部高光 + 内壁暗角 + 一根灯丝实现**，成本几乎为零，而且更像玻璃。令牌保留，只在一个极小的目标（面板内浮层提示）上兑现。
*放弃的是*：现代 UI 的「高级感」快捷方式，以及背景若隐若现的通透。

**③ 不做药丸圆角与悬浮胶囊（`--kami-r-pill: 2px`、`--kami-r-lg: 6px`）。**
圆润是消费级 app 的默认语法，也是「默认好看」的模板组合里最难摆脱的一环。六十年代的仪器没有一个是胶囊形的：边是铣出来的，角是倒角的，键是方的。放弃药丸之后，皮肤立刻获得「仪器」的身份，而且与另外两套皮肤在**任何一张截图**上都能区分。
*放弃的是*：柔和友好的第一印象，以及一点触屏上的「柔软」暗示（用 40px 触控高度和明确的行程反馈补偿）。

## 10. 自我批评与已做的实质修改

以创意总监身份做了两轮审查，以下每条都导致了实际改动（不是改文案或调色号）。

### 批评 A：第一稿全是暗字，第一眼会「没精神」，手机强光下尤其糟
第一稿把「蚀刻」用得太彻底：标题、副信息、徽章、说明全是暗金属色，整块面板是一团暗的东西上偶尔亮一下。在 320px 手机上，用户第一眼看到的会是一块「没加载完」的板子。
**修改（结构性）**：引入**曝光规则**。每个组件内部允许且只允许一个「亮部中心」：头部是读数窗口；卡片列表是悬停 / 聚焦的那一张；面板是选中的标签页与其下沿亮线；正文是左侧那道 3px 亮条。同时把 `.kami-card-title` 从蚀刻改为**正文级亮色**（12:1），确保「能读的东西一定比装饰亮」。并给底板加了一个从上到下的极缓明度梯度（顶亮 4%），让面板有「被顶光照到」的方向感。

### 批评 B：辉光无处不在——这是换了个颜色的同一个俗套
第一稿在灯珠、标题、读数、按钮、分段、边框、卡片上都有光。这恰恰是我要避免的「黑底橙光」的病，只是换了载体：满屏发光会让发光失去意义，也会让每个楼层的重绘面积成倍增长。
**修改（结构性）**：定下**辉光预算**：
- 每个组件最多 **3 个发光体**（灯珠、读数、一个主操作）；
- 文字光 `text-shadow` 半径 ≤4px、alpha ≤.35；
- 面板级光只允许**向下偏 1–3px**，永不对称；
- 不在这三个位置上的元素 **alpha 为 0 的光**——它们要么蚀刻，要么靠形状表达状态。
这条规则让「亮」变成稀缺资源，也因此让「一次只亮一个」真正成立。收尾时逐个复查发光点，删掉了徽章光、卡片常态光、边框光（共 6 处）。

### 批评 C：编号 + 徽章 + 标题在 320px 下挤成一团
`counter` 的编号放在卡片头部行里时，320px 下标题只剩不到 130px，长标题会截成两个字。
**修改（结构性）**：把编号从「行内」改成**左侧独立编号槽**（`grid-template-columns` + 1px 竖向接缝），并用**容器查询**在 `≤21rem` 时整槽隐藏。同时把 `.kami-card-body` 从「截断」改为「不截断」（正文是内容本体，宁可多两行），只保留标题单行截断。

### 批评 D：逐段错峰的长文本动画是「看起来很努力」的错误
原本给 `.kami-md` 的前 8 个块级元素设计了渐次出现的阶梯延迟。复查时发现两个问题：① 每个段落都在动画，成本随文本长度线性增长（而这份 CSS 是每个楼层一份）；② 人读第二段时第七段才亮起来，观感是卡顿而非精美。
**修改（结构性）**：**整条删除**。长文本唯一的动效就是那一次起辉前缘。省下来的「设计预算」转投排版：行高 1.68、`text-wrap: pretty`、`overflow-wrap: anywhere`、正文块专用最暗底色 `--kami-card-2`。同时明确禁用 `content-visibility: auto`（会破坏 iframe 高度测量）与滚动驱动动画（内嵌前端不滚动）。

### 批评 E：收起动画原本想做高度动画，「看起来更完整」
如果给 `.kami-collapse-body` 做 `grid-template-rows: 0fr → 1fr` 的高度动画，楼层 iframe 的高度会在 300ms 内持续变化，下方消息全程抖动。
**修改（结构性）**：改成**断电模型**——收起时正文立即消失，只有壳体余辉用 340ms 过渡退掉。这个决定同时解决了一个技术限制（`hidden` 元素无法播放退出动画）和一个概念问题（断电本来就是瞬时的）。**限制变成了规则**，这是本轮修改里我最满意的一处。

### 批评 F：亮色模式原本是「顺手做的反色」
最初只打算把颜色反一下。但辉光在白板上根本不可见，「亮 = 发光」这条主规则会直接失效。
**修改（结构性）**：把亮色模式重新定义为**另一台仪器**（日光下的搪瓷面板）：通电的定义反转为「实心琥珀底 + 深色字」，辉光半径压到 2px，蚀刻改为「深棕冲压」。两种极性共享同一条抽象规则（亮 = 相对底板的最大局部对比），所以它不是换色，而是同一套状态语法的对偶。同时明确声明亮色为次要模式，优先级低于暗色。

### 批评 G：动效种类仍然偏多
第一稿里还有「卡片按压缩放 0.99」「面板打开时缩放进入」「箭头悬停右移 2px」。
**修改**：全部删除。缩放入场归零（`--kami-enter-scale: 1`），箭头改为**点亮**而不是位移（位移动画是通用 app 语言，而指示灯点亮是本皮肤的母题）。最终全皮肤只有三种运动：**起辉前缘（一次性主运动）、状态过渡（≤170ms）、灯珠呼吸（唯一循环）**。开关的 200ms 弹簧过冲是刻意保留的**唯一例外**——正因为别处从不过冲，那一下「咔哒」才能被听见。

### 仍然存在、我不打算在这一版解决的
- 亮色模式与暗色的气质差异较大，用户在两台设备上分别使用会有「不是同一套皮肤」的第一印象。我认为这个风险值得承担（它给了亮色模式一个真正的存在理由），但这是本方案最可能被否决的一条。
- 阴极编号（`counter`）依赖纯 CSS 计数器。若前端把多组选项渲染进同一个容器，或将来列表结构变化，编号可能不符合直觉——因此它默认关闭，且不影响任何信息。
- 容器查询 `@container` 是窄屏下最关键的技术依赖，已写明降级预案（§8.1）。

## 11. 与另外两套皮肤的差异声明

三套皮肤在同一个聊天里可能被用户来回切换，因此差异必须一眼可辨，且不能是「同一种美学的换色」。

**① 本皮肤是唯一一套「灰度可辨识」的皮肤。**
把三套皮肤各自截图后完全去色：如果一个皮肤的状态语言主要建立在**色相与色块**上，去色后它会退化成一片灰卡片；而辉光管的状态语言建立在**亮 / 暗两极 + 光照方向 + 凸起 / 凹陷**上——去色之后，你仍然能看出「这个亮了、那个没通电」「光是从上面打下来的」「这个键是压进去的」。这不是自我标榜而是一个可执行验收测试：**本方案承诺在灰度下与另外两套无法混淆。**

**② 已知 / 预期的邻位，以及本皮肤主动让出的地盘。**
- **奈亚子的TRPG**（id `trpg`，皮肤管理默认皮肤）的任务书点明了「宇宙恐怖 × 轻小说喜剧的张力」，并且行动选项在叙事上就是「跑团给玩家的选项」、思维链是「KP 的幕后思考」。那套皮肤几乎必然使用**游戏化 HUD 语言**：更强的图形化、更活泼的色相、更直接的骰子 / 理智 / 回合符号。本皮肤从这条路上**完全退出**：不使用任何游戏化进度、图表、数值条或角色符号，唯一的「数值」是等宽读数；整套界面没有情绪起伏设计，只有仪器的稳态。**TRPG 演的是「故事正在发生」，辉光管演的是「仪器正在工作」。**
- **恋雨**（id `rain`）的任务书指向私密、潮湿、聚散与呼吸。那套皮肤几乎必然走向**柔和、流动、有湿气与温度**的材质（模糊、渐变、曲线、缓慢呼吸）。本皮肤在每一点上都与之相反：**硬边、不透明、无模糊、零曲线（全皮肤没有一个药丸圆角）、光照方向恒定且永远向下**。**恋雨用「流动」表达情绪，辉光管用「通电」表达状态。** 即使恋雨的主题色恰好也偏暖，两者的形状语法（柔软流动 vs 铣削倒角）在任何一块 100×100px 的局部上都不会混。

**③ 一个反过来的差异：本皮肤也许是最「不适合被注意到」的一套。**
TRPG 与恋雨都在争取「氛围感染用户」，而辉光管的整个取向是**让容器退后**：面板大部分是暗的、没有情绪色、不透明，不发光的地方就真的是暗的。它的记忆点只在两个瞬间（起辉、层叠抽出），其余时间它是一座安静的仪器。这是三套皮肤里唯一一套「以退为进」的策略，也是一句可以拿来验收的话：**另外两套让人想截图，这一套让人想读下去。**

## 附录 A · 需要前端 / 皮肤管理脚本确认的接口请求

本方案落在契约之内，但有 5 处依赖契约未写死的行为，实施前需确认（任一不成立都有已写明的降级路径）：

1. **`.kami-collapse-body` 的收起实现**：皮肤计划完全接管 `[data-kami-open="0"]` 时的隐藏（`display: none`）。若前端也要用 `hidden` 属性，请保证两者语义一致，避免出现「属性说开着、CSS 说关着」。
2. **复制成功后的状态**：希望复制成功后给 `.kami-btn[data-kami-act="copy"]` 加 `.is-on` 保持约 800ms，皮肤据此把这次操作变成「键帽亮一下」。未实现则退化为按下态反馈。
3. **行动的「已完成」状态**：旧版前端用过 `.is-done`，新契约未登记。建议复用 `.is-on`（皮肤渲染成「这一片阴极已经通电并保持」）。否则点了卡片之后只有 `:focus` 的微温状态。
4. **`.kami-range` 的当前值**：若前端能写入 `--kami-value`（0–1），滑杆就能画出「已通电区段」（本皮肤招牌之一）。未实现则退化为纯机械滑轨。
5. **面板容器尺寸**：`.kami-drop` 用 `height: var(--kami-panel-h); max-height: 100%`，且不使用任何视口高度单位。请保证 `.kami-root[data-kami-comp="panel"]` 被放在一个至少覆盖视口高度的定位容器中。

另建议在皮肤管理面板中为每套皮肤提供一行「效果」开关（`effects` 数组已按契约声明）与「动效档位」（含本皮肤建议新增的 `calm` 档）。
