# 恋雨 · 皮肤设计方案（rain）

> 皮肤 id：`rain` ｜ 面板名称：**恋雨** ｜ 按钮短名：**恋雨**（按钮整体文案 = `🎨恋雨`）
> 建议明暗方案：`dark`（夜雨）／完整提供 `light`（雾白）两套
> 适用：显式思维链 / 行动选项 / 皮肤管理面板 / 预设设置面板 / 引导面板
> 本文件只描述设计与实现思路，不含任何可执行 CSS 代码。

---

## 1. 核心概念

**一块从内侧看的窗玻璃。**

外面在下雨，里面是你。玻璃把世界分成干与湿：模型的心事在外侧——它先起雾，你擦开一小块才看得见，擦过的地方会慢慢重新蒙上；你的抉择在内侧——是递到你干手上的东西，哑光、裁得利落。

所有动作都服从重力：**擦、渗、聚、落下**。

> 「恋雨」不是喜欢雨，是喜欢**雨把世界关在外面，只剩这一小块干的地方**。

## 2. 用户体验路径

**① 第一次遇到（0.5 秒内形成的记忆点）**
用户在一屏酒馆聊天里往下读，模型回复的末尾出现了两个东西。一个是别处都没有的形状：**一条窄窄的、像被人用手掌擦过的横条**——湿灰的底、左端一小截 3px 的暖色竖线、写着「思维链 · 1,842 字」。它看起来**比周围安静**：在满屏头像、彩色 Markdown、按钮和图片里，它是唯一一个"没有被点亮"的东西。
**记忆点来自"更暗、更哑、更有厚度"，而不是更亮。** 这是整套皮肤的第一决策。

**② 理解（一次点击教会整套语言）**
用户点开它。不是弹开——是**雾被擦掉**：一层水汽在 200ms 内从中间往两边退去，玻璃后面浮出正文。正文是**衬线**的，和酒馆里所有其它字都不一样，读起来像纸。
同时他注意到左缘那条暖色短线**沿着左边往下长**了一截——它变长了，说明"这里面有多少东西"。用户此刻不需要任何人教就懂了两件事：**衬线的地方是"有人在对你说的话"，无衬线的地方是"器物的标签"**。

**③ 使用（一次选择教会重力）**
往下看到「行动选项」。这里的卡片是**干的**：实色、闭合描边、裁得利落。鼠标移上去时，卡片**向下沉 1px**，影子收紧，左缘渗开一小片湿痕，右端的箭头往下挪了 2px。（别处的卡片都往上飘，这里的往下沉——用户会记住这个反向。）
他点了一张。一道 1.5px 的细水线从卡片顶端落到底端，落到底的瞬间卡片底边亮起一条暖色渐隐线，接着从卡片底部**渗上来**一条提示。整套动作没有一个"打勾变绿"。

**④ 记住**
三天后他不会记得配色。他会记得两件事：**同一屏里有两块材质**，以及**这里的东西都往下走**。
第五次使用时他会关掉「起雾」特效——因为他已经懂了，不再需要雾。这是设计允许的告别方式。

## 3. 视觉语言

### 3.1 色彩体系与理由

**主调不是蓝。** 雨水本身是无色的；把城市的光洗过一遍之后，玻璃上是**灰绿**——湿沥青、路灯下的树叶、阴天的窗。蓝渐变加水滴是"雨的图标"，不是"雨的体验"。因此：

- **底**：极低饱和的**湿灰绿**（暗色 `#101415` / `#191E1F`），不是蓝黑、不是紫黑、不是纯黑。它读起来"冷"，但不"科技"。
- **字**：**骨白** `#E9E4DA`。一间亮着灯的屋子从里面看出去的颜色——比纯白暖、比米黄冷。用骨白而不是 `#FFF`，是为了让这套界面**晒不进太阳**。
- **全屏只有一个色相**：一枚**朱橙**（暗色 `#EC7C4A` / 亮色 `#AD3F1B`）。它是窗外那盏钠灯、是烟头、是门缝漏出的光，是这套皮肤里唯一的**体温**。所有强调、选中、主要按钮都用它。
- **强调底上的文字是暗的，不是白的**（`--kami-accent-fg: #14100C`）。像真实的灯箱：暖色底 + 深色字。这既保证对比度（6.81:1），又是一个**和"亮色按钮配白字"的通用做法明显不同的选择**。
- **语义色不是 7 种彩虹**。7 个 `--kami-kind-*` 是"同一种湿灰绿在 7 个气温下的样子"。识别主要靠**徽章左侧那枚 2px 竖向色条**（窄面积纯色，允许更饱和）；正文与卡片标题**永远不用 kind 色**。这条规则让一屏 7 张卡不会变成调色板。

**明暗两套不是反相：**
- `dark = 夜雨`：玻璃外是黑的，室内一盏暖灯。
- `light = 雾白`：阴天的乳白玻璃、被雨浸过的纸（底色 `#E7E4DC`，不是纯白）。亮色方案里"湿"照样成立，因为**湿的载体是灰度的层次，不是黑色**。

**实测对比度**（正文落在卡片/内层正文块上）：

| | 主文字 | 次要 | 最弱 | 强调底+强调字 | 最低的 kind |
|---|---|---|---|---|---|
| dark | 13.29:1 | 7.89:1 | 4.88:1 | 6.81:1 | nsfw 5.18:1 |
| light | 13.64:1 | 6.41:1 | 5.35:1 | 5.61:1 | fun 4.87:1 |

全部 ≥ 4.5:1，最弱令牌也留了余量。

### 3.2 字体栈与理由

**核心排版主张：衬线 = 有人在对你说的话；无衬线 = 器物的标签。**
这条二分法贯穿全部 5 个界面，是"私密感"在排版上的真正落点。

- `--kami-font`（界面/正文）：`system-ui, -apple-system, "PingFang SC", "HarmonyOS Sans SC", "Source Han Sans SC", "Noto Sans SC", "Microsoft YaHei", sans-serif`
- `--kami-font-title`（标题）：`Georgia, "Songti SC", "Source Han Serif SC", "Noto Serif SC", "STSong", SimSun, serif`
- `.kami-md`（思维链正文）：**强制走衬线栈**（与标题同族）——这是"一段话"，不是"一段数据"。
- `--kami-font-mono`：`ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, "Liberation Mono", monospace`——用于 `.kami-raw` 原文、计数、滑杆数值、数字输入。
- 字重只用 **400 / 600**，没有 700 与 900。雨夜里没有人在喊。
- `--kami-title-transform: full-width`：**标题按全角格排**。中文字符天然占满一格，配合 `.14em` 字距，标题看起来像**落在稿纸格子里的雨点**。（这是一笔有风险的排版投资，回退路径见 §10-C4。）
- 全部为系统栈，零外部字体、零 `@import`，符合纯 CSS 约束。

### 3.3 材质与图形语言

**三条材质律，回答"什么是湿、什么是干"：**

1. **湿 = 边缘不闭合。** 湿的容器（思维链外壳、内层正文块）左右两端各 12px 的描边**化开消失**（对描边层做水平方向的渐隐遮罩）；上缘的"玻璃反光"高线只覆盖中段，两端不闭合。**干 = 边缘闭合**：实线描边、规整四角、底边另加一条 1px 的暗线（"纸的厚度"）。
   → 这个差异是**结构性的**，与颜色无关、与屏幕宽度无关、色盲用户也能分辨（同时满足 §8 的可达性要求）。

2. **干 = 纸；湿 = 玻璃。** 干的表面是哑光实色 + 一层极细的**斜向雨丝**（78° 的 1px 重复渐变，alpha ≈ .012）——那不是纸纹，是**你隔着玻璃看纸时，玻璃上那层雨丝**。所以整块界面始终在下雨，只是"干"的那部分你摸得到。

3. **重力是唯一方向。** 所有元素的圆角**上大下小**（`14px 14px 4px 4px`）；阴影下方重、上方几乎为零；悬停向下沉；水位线向下生长；成功的水线向下落。**没有一处元素向上漂浮。**

**图形母题：**

- **水位线**（`--kami-accent-mark`）：每个面左缘那截 3px 宽的暖色竖条。折叠时它很短；展开后沿左缘**向下长到接近底部**。它不是装饰——它是**状态**：告诉你这里面有多少东西、以及"水还在不在"。
- **水印格徽章**：`.kami-chip` / `.kami-badge` **不是圆角 pill**，而是一枚**印记**：左侧 2px 竖色条 + 全角字距的文字 + 一个极浅的内凹（像被按进湿纸里）+ 底部略亮的一道边。像盖在湿纸上的章。
- **玻璃厚度**：`.kami-surface` 内侧有一道比外框更亮的 1px 内线——让你意识到自己在玻璃的**这一侧**。这是"内侧"这个概念在每一块界面上的物理证据。
- **窗格栅**（仅面板、引导卡片）：面板 body 用一层极淡的 1px 竖线背景，间隔约等于 `--kami-items-min` 的 1/4，暗示窗框的分格。**内嵌前端里不用这层**——那里已经很窄，多加一层就是噪音。
- **接地影**：所有可交互面下方都有一层**独立的软影层**（不是 `box-shadow`，是 `.kami-root` 上的一个径向渐变层）。它的存在让"下沉/贴紧"可以被动画，而不必逐帧重绘阴影。

### 3.4 留白与节奏

雨的节奏是**均匀、细密、不间断**的，不是"疏朗的大留白"。所以：

- **密的行距、松的内衬**：`--kami-gap: 7px`（块间距小而恒定），`--kami-pad-lg-x: 14px` / `--kami-pad-lg-y: 12px`（块内慷慨）。
  读起来像站在屋檐下：雨帘是密的，但你站的地方是干的。
- **段落之间不做大跳跃**：段间距压到 `.5em`，呼吸由 `--kami-lh: 1.72` 的宽松行高承担。这是**湿块的读法**——不靠留白断句，靠行间的水汽。
- **三级字号的间隔是压缩的**（`.74 / .86 / 1 / 1.14`）：信息层级靠**材质与位置**区分，不靠字号拉开。一屏里字号的落差越大，越像"仪表盘"；这里要的是**连续的、同一张纸上的层次**。

### 3.5 概念 → 设计的三条映射（不是口号）

| 概念 | 视觉落地 | 交互落地 |
|---|---|---|
| 玻璃有内外侧 | 每个面上有一道"玻璃厚度"内亮线；边缘一圈极轻的框影 | 焦点环带一层向外洇散的水痕环（`--kami-glow` 的唯一用途） |
| 湿／干是两种材质 | 湿：描边两端 12px 渐隐、圆角上大下小极端化、偏透明；干：闭合实线、纸的哑光、底边一条"纸厚"暗线 | 悬停不"浮起来"，而是**向下沉 1px**、影子收紧——东西变重 |
| 重力是唯一方向 | 圆角上大下小；阴影下方重上方几乎无；水位线自顶向下生长 | 卡片按下沉 2px；成功是水线自上而下贯穿；toast 从下方渗上来 |

## 4. 组件设计

> 全部外观由皮肤承担；前端 DOM 与类名严格按契约 §4/§5，不新增类名。

### 4.1 外壳 `.kami-shell.kami-surface`

- 底：`--kami-bg`（半透明）+ `--kami-texture`（斜向雨丝 + 竖向流痕的多层渐变）。
- 描边：`--kami-border-w` 1px + `--kami-line`；**内侧再加一道**比外框更亮的 1px 内线（"玻璃厚度"）。
- 圆角：`--kami-r-lg --kami-r-lg --kami-r-xs --kami-r-xs`（**上大下小**，下方方角＝坐在桌上）。
- 阴影：`--kami-shadow`（下方重）+ `.kami-root::before` 的接地影层。
- 左缘水位线由 `.kami-body` 的一个装饰层承担：`transform: scaleY(0)` → `scaleY(1)`，`transform-origin: top`。展开时它像水一样**沿着左缘流下去**。
- 湿/干由 `data-kami-comp` 分流：`think`（湿：描边两端渐隐、上缘高线不闭合）／`options`、`panel`（干：闭合实线 + 底边暗线）。

### 4.2 头部 `.kami-head` / `.kami-collapse-head`

- 三段式：状态点 + 标题 + 副信息，右侧动作区。内边距 `8px 12px`。
- **分隔线不是整条**：头部底边只有左半段有一条 1px 的线（从左端渐隐到 62% 处消失）——像窗框上一道没擦干的水。整条实线是模板做法，这里不取。
- 悬停（仅 `@media (hover:hover)`）：头部底色**加深一档**（不是变亮），分隔线延长到 88%。
- 折叠头是 `role=button`，`:focus-visible` 用与卡片同款的焦点环。

### 4.3 状态点 `.kami-dot`

- 一枚 6px 的**水珠**：不是正圆，是略呈梨形（上下半径不对称），因为挂在玻璃上的水滴是**下坠**的。
- 静止时是暗的（`--kami-fg-mute`）。`[data-kami-on="1"]` 时变成朱橙并**向下拉长 1px**——**它不发光，它变重。**
  这是本皮肤对"状态点"的重新定义：其它皮肤用它表示"亮/活跃"，这里用它表示"有东西滴下来了/正在积聚"。

### 4.4 标题与副信息 `.kami-title` / `.kami-sub`

- 标题：衬线栈 + `full-width` + `--kami-ls-title: .14em` + `--kami-fw-title: 600` + `--kami-fs-lg`。**不描边、不发光、不渐变**——它的分量来自字体本身。
- 副信息：等宽栈 + `--kami-fs-xs` + `--kami-fg-mute` + `font-variant-numeric: tabular-nums`，数字**不跳动**（切换视图时字数不变形）。
- 层级关系：**标题是"话说给你听"，副信息是"仪表读数"**——一个衬线一个等宽，同一行里就有材质对比。

### 4.5 按钮层级 `.kami-btn` / `.kami-icon-btn`

三级不是靠"亮度"分，而是靠**湿度**分：

- **`.kami-btn--primary`（干）**：实色朱橙底 + **暗色**文字（`--kami-accent-fg`）+ 无描边 + 上大下小圆角 + 底边一条更暗的 1px（纸的厚度）。悬停时底色**向下加深**（底部叠一层 18% 黑），不是变亮。按下时 `translateY(1px)`——**沉下去**。
- **`.kami-btn--ghost`（半干）**：透明底 + `--kami-line-strong` 描边，**描边两端渐隐**（湿律）；悬停时描边收成闭合实线并渗入 `--kami-accent-soft` 底——**从湿变干**，正好是它的语义（"我准备要用了"）。文字 `--kami-fg-dim` → `--kami-fg`。
- **`.kami-icon-btn`（只有字形）**：无底无边；悬停时背后渗出一小片圆形湿痕（`scale(.6)`→`1` + opacity，140ms）。`aria-pressed="true"` 时湿痕常驻，且字形带 1px 的下沉暗影——**像被按进玻璃里**。
- 全部 `min-height: --kami-row-h`（42px）、`touch-action: manipulation`、`-webkit-tap-highlight-color: transparent`。`.is-on`（选中）＝该按钮的湿痕常驻 + 文字变 `--kami-fg`。

### 4.6 分段切换 `.kami-seg` / `.kami-seg-item`

**不做"滑动 pill"**（滑动胶囊是通用模板，一眼就是组件库）。这里做成两个并排的**水位刻度**：

- `.kami-seg` 是一道 1px 内凹的槽（内阴影 1px），未选中项**完全透明**（只是槽里的一行字，低对比）。
- 选中 `.is-on` 时**从底部"积水"**：一条朱橙薄层自底升起（`scaleY(0→1)`，`transform-origin: bottom`，160ms），文字变为 `--kami-fg` 并微加重。**不发光、不描边、不用描边内阴影**。
- 悬停未选中项：它的底部先出现 2px 的极淡水线（`scaleY(.25)`）——**预告它会被填起来**。
- 语义：`填入/发送`、`渲染/原文` 都是"你选哪一层水面"。切换时一升一降（新项升起、旧项退回），**两个方向同时在动，这就是切换的全部节奏**，不需要额外提示。

### 4.7 卡片 `.kami-card` / `.kami-item`（行动选项的核心，整卡即按钮）

它是 `<button>`，外观是**干纸**：`--kami-card` 实色 + 闭合 `--kami-line` 描边 + 上大下小圆角 + 顶部一道微亮内线（纸被灯照到的上缘）。

- **它比周围沉**：静态就带 `--kami-shadow-sm` 与接地影。
- **悬停**（`@media (hover:hover)`）：`translateY(1px)` **下沉**；接地影 `scale(.985)` + opacity 加深（影子离得更近，说明它更贴桌）；左缘渗开一道湿痕（装饰层 `scaleX(0→1)`，`transform-origin: left`，180ms，朱橙淡染到透明的横向渐变）；右端 `↵/→` **向下位移 2px** 并变实（雨往下，不是往右）。
- **聚焦**：湿痕 **0ms 立即出现**并保留（键盘用户不该等动画），焦点环 120ms 出现。
- **按下**：`translateY(2px)`，接地影 opacity 降到 0.2（影子被压扁）。
- **成功 `.is-done`**：一道 1.5px 的水线从卡片顶端落到底端（`scaleY(0→1)`，`transform-origin: top`，220ms），落底瞬间卡片底边亮起一条朱橙渐隐线（80ms）。**不打勾、不变绿。**
- **失败**：卡片底边瞬时出现一条**断开的锯齿线**（3px 实 / 4px 空 的重复渐变，1px 高）+ 一次 140ms 的 ±1px 横向抖动。**不闪红、不放大、不延迟**（错误必须立刻可见）。
- **示例 `.is-demo`**：整体 `opacity .55`，右端箭头缩成一条 6px 的短横（"停住"、不指向任何地方），`cursor: default`。**不置灰到底**——示例也要能读。
- **`.kami-card-head` / `.kami-card-title` / `.kami-card-note` / `.kami-card-body`**：
  - head 是 flex 行：徽章 + 标题 + 右端箭头。标题**允许不换行**（`text-overflow: ellipsis`），因为下方还有 body。
  - title 用 `--kami-fs` + 600 字重，**不用衬线**——它是"选项的名字"，属于器物。
  - note 是极弱的一行（`--kami-fs-xs` + `--kami-fg-mute`），用来放"来源/代价"这类边角信息。
  - body 是正文：`--kami-fs-sm` + `--kami-lh` + `--kami-fg-dim`，**最多 3 行截断**（`-webkit-line-clamp`，带 `max-height` 兜底）。

### 4.8 列表与网格 `.kami-list` / `.kami-grid`

- `--kami-list-dir: column`、`--kami-justify: stretch`、`--kami-items-min: 260px`。
- 网格：`repeat(auto-fill, minmax(var(--kami-items-min), 1fr))`。**320px → 1 列；≥560px 的聊天宽度 → 2 列**。禁止固定像素宽。
- 项间距 = `--kami-gap`（7px）：小而恒定，这是**雨点的间距**，不是"卡片间距"。
- `.kami-item-main`（主体）允许收缩、`.kami-item-side`（侧栏）**永不收缩**（`flex: none`）——侧栏里放箭头/序号，它必须是"钉住"的。

### 4.9 徽章 `.kami-chip` / `.kami-badge`（"水印格"）

- 结构：`inline-flex`；左侧一枚 **2px × 1em 的竖色条**（颜色 = 该 kind 的色）；文字 `--kami-fs-xs` + `.16em` 字距。
- 底：`--kami-kind` 的 12% 淡染（叠在 `--kami-t1` 之上做兜底）；内凹 1px 阴影；底边略亮。
- **7 种 kind 的区分主力是那枚色条，不是文字颜色**。文字色只在 `.kami-badge` 内使用 kind 色，且统一校准到 ≥4.5:1。
- **`nsfw` 特殊处理**（"私密"的一部分）：**主动降低**饱和度（`saturate(.85)`）而不是加艳。它是"我知道你知道"的低语，不是霓虹招牌。

### 4.10 折叠区 `.kami-collapse`

- `[data-kami-open="0"]`：只显示头部；头部底边只在**左端 24px** 有一段朱橙细线——"还没干的一小段"。
- `[data-kami-open="1"]`：正文出现。正文块上缘一条 1px 高光**从中心向两侧散开**（`scaleX(0→1)`，`transform-origin: center`，240ms），像擦开时手的方向。
- `.kami-chev`（`▸`）旋转 90°，160ms，**唯一允许的轻微过冲缓动**——那是"一滴水落到玻璃上停住"的一下。
- **不做高度动画**（理由见 §5）。收起时正文立即消失，水位线以 `transform-origin: bottom` 退回，160ms。

### 4.11 表单控件

- **`.kami-field`**：一行一条。左侧 `.kami-field-label`（**无衬线** `--kami-fs-sm` + `--kami-fg-dim`——标签是器物）；右侧 `.kami-field-value`（等宽 + `tabular-nums` + `--kami-fg`）。窄屏下自动换行成上下两段（见 §8）。
- **`.kami-range`（滑杆）——本皮肤的签名控件**：不做常见的"圆点 + 灰条"，做成**一根挂着水珠的线**。
  - 轨道 2px，`--kami-t3` 底；Firefox 用 `::-moz-range-progress` 给已填充段上朱橙；WebKit 无法分段，改为**悬停/聚焦时整条轨道染上低对比朱橙**，并让 thumb 更大更明确——**用 thumb 承担状态，而不是假装能画出填充段**（诚实的取舍）。
  - thumb 是**一枚梨形水珠**（18×20px，上下半径不对称），朱橙实色 + 底部一道内阴影（让它有厚度）。
  - 拖拽（`:active`）时水珠**向下拉长**（`scaleY(1.12)`，`transform-origin: bottom`）并在下方渗出一小片水渍（外阴影模拟），140ms——**它在被拖着走，所以它变形。**
  - `:focus-visible`：轨道两端各出现 2px 的朱橙端点，明确、可数、无需动画。
- **`.kami-number`（数字输入）**：**无边框，只有一条底线**；等宽、右对齐、`tabular-nums`。聚焦时底线**从左向右被水浸透**（底线色块宽度 0→100%，`transform-origin: left`，200ms）。不用边框光圈。
- **`.kami-switch`（开关）**：不做 iOS 胶囊。做成**一道闸**：
  - track 是一条 2px 的水平窄槽（34px 宽）；knob 是一枚 10px 的水滴。
  - **关**：knob 停在左端，是一枚**灰色小圆**（干）。
  - **开**：knob 向右**滑落**（180ms，带唯一允许的过冲），同时**从圆变成梨形水珠并染上朱橙**——`border-radius` 与背景同时过渡，这是"**水聚起来**"的形变；track 左段亮起一条朱橙细线。
  - `.kami-switch-input` 用 `position:absolute; opacity:0`，焦点环画在 `.kami-switch-track` 上（`:focus-visible +` 选择器）。
  - `:disabled`：knob 变成 `opacity .35` 的**空心圆**——"干了"。

### 4.12 标签页 `.kami-tabs` / `.kami-tab`

- 不是"下划线跟随"的通用做法。每个 tab 是一段**窗格**：底边 1px 的 `--kami-line`；`[aria-selected="true"]` 时底边被一段**朱橙实线替换并从中间向两侧长开**（`scaleX(0→1)`，`transform-origin: center`，180ms），同时文字由 `--kami-fg-dim` → `--kami-fg`。
- 未选中的 tab 悬停时底边出现一段 40% 宽的暗线——"还没轮到它亮"。

### 4.13 面板与抽屉 `.kami-drop` / `.kami-resize`

- **`.kami-drop` 是全套皮肤里唯一允许使用 `backdrop-filter: blur(var(--kami-blur))` 的地方。** 理由见 §9-2：酒馆页面上只有一个实例；而它正是"你贴在窗上的那一块"，是整个隐喻唯一一次**真的模糊**。内嵌前端一律不模糊（已经有 88% 不透明底，够用）。
- 尺寸：`--kami-panel-w: 420px`、`--kami-panel-h: 460px`，超出用内部滚动。**不用 vh/vw**（契约硬约束），不用 `position: fixed` 铺满。
- 形状：上大下小圆角（它"坐在"页面上）；顶部一条**不闭合的**亮线（中段 40% 的反光）。
- 入场：`translateY(6px)` + `scale(.985)` → 归位，300ms（**不弹、不缩到 0.8**）。
- `.kami-resize`（尺寸把手）：右下角两段 1px 短斜线，悬停变朱橙，`cursor: nwse-resize`。

### 4.14 滚动条 `.kami-scroll`

- Firefox：`scrollbar-width: thin`；WebKit：8px 宽、**无箭头按钮**。
- thumb 是**一段竖直的湿痕**：上下两端渐隐的深色条（用渐变实现，不依赖 mask），悬停时变为朱橙渐隐条。
- 轨道透明——**不做凹槽、不做圆角套圆角**。

### 4.15 空态 `.kami-empty`

- **不用大图标、不用插画**。用**一片干了的渍**：一个 24px 的圆形区域，由一圈**断断续续的浅色弧**构成（径向渐变画出环、再用锥形渐变把环打断成不均匀的弧）。这正好是"水来过、又走了"的痕迹。
- 文字 `--kami-fs-sm` + `--kami-fg-mute` + 居中 + `max-width: 34ch`。

### 4.16 内联提示 `.kami-toast`

- **从下面"渗"上来**：`position: absolute` 于 `.kami-shell` 内（shell 为 `position: relative`），贴在底部内边距处；`translateY(8px)` + opacity 0 → 归位，200ms，`--kami-ease-out`。
- 形状：不是 pill，是**一枚贴在卡片底边上的印记**：小圆角、两侧描边渐隐、左端一枚 2px 竖条（颜色 = 语义色：成功用朱橙，失败用 `--kami-warn`）。
- `.is-bad`：底色叠 12% `--kami-warn` 淡染，左竖条换色，并**附一次 120ms 的 ±1px 横向抖动**。
- `pointer-events: none`（绝不能挡住下一张卡片），层级高于卡片列表。

### 4.17 原文/渲染块 `.kami-md` / `.kami-raw`

- `.kami-md`：衬线栈 + `--kami-lh`；标题层级用**字号压缩 + 行前留白**区分（不靠粗细堆叠）；`code` 用等宽 + `--kami-accent-soft` 底 + `.06em` 内边距；`hr` 是一条**两端渐隐**的细线（湿律）；引用块用**左缘水位线**而不是灰色底；列表 marker 用朱橙的小方块（不是圆点——圆点在雨里太软）。
- `.kami-raw`：等宽 + `--kami-fs-xs` + `white-space: pre-wrap` + `word-break: break-word`（长 token 不能撑破 iframe）+ `--kami-line` 左缘一道细线。
- 二者的共同原则：**阅读区不做 hover 反应**（文字不动，人才读得下去）。

### 4.18 皮肤预览 `.kami-preview`

- 一个 16:9 的小方块：底色 = `--kami-card`，上面叠两笔——一笔是**灰绿的天空**（对角渐变），一笔是**一抹朱橙**（右下角的小块，像远处的灯）。
- 它不需要画出"恋雨长什么样"，只需要让用户在管理面板里**一眼认出"那个灰绿底、一点橙"的**。
- 选中态：预览块左缘的水位线长满整条边。

## 5. 动效编舞

### 5.0 编舞纪律（第一原则）

> **每一屏在同一时刻只有一个运动主体。**

要么外框在动（面板/抽屉入场），要么内容在动（卡片列表的雨点节奏），**绝不重叠**。
（这条是 §10-C3 的产物。它既是美学纪律，也直接降低了每个楼层的合成开销。）

### 5.1 时间刻度与缓动

- `--kami-dur-fast: 140ms` —— 悬停、按下、图标反馈。
- `--kami-dur: 200ms` —— 状态切换、渗开、toast 渗出。
- `--kami-dur-slow: 300ms` —— 面板入场、雾散。
- `--kami-ease: cubic-bezier(.32,.72,.28,1)` —— 主缓动，"**水被推着走**"：起步稍慢、中段快、尾巴极长。**没有回弹。**
- `--kami-ease-out: cubic-bezier(.16,.84,.28,1)` —— 出场，"渗开"。
- **唯一允许过冲的地方**：`.kami-chev` 的旋转与开关 knob 的滑动（`cubic-bezier(.34,1.28,.64,1)`）。因为"一滴水落到玻璃上会弹一下"。**其余一切绝不弹跳**——水是重的。
  （`data-kami-motion="calm"` 时连这一处也改为 `--kami-ease`。）

### 5.2 入场（消息楼层会按楼层各跑一次，因此必须省）

- `.kami-surface` 以"更湿"的状态开始：自定义属性 `--kami-wetness: 1.55`（用 `@property` 注册为 `<number>`，可插值），260ms 内落到 `1`。这个数值**直接驱动雾层的 opacity**——所以整个"雾散"过程是**一个合成层的不透明度插值**，没有 `filter`、没有逐帧重绘。
- `.kami-surface` **不位移**（位移权交给列表项，见纪律 5.0）。接地影层 opacity `0 → .55`，180ms。
- **卡片列表 = 雨点节奏**（本皮肤的标志性入场）：
  - **不是线性错峰**。用 `:nth-child(1..12)` 显式给出**非等距延迟**：`0 / 40 / 90 / 130 / 210 / 250 / 320 / 360 / 440 / 480 / 570 / 610 ms`——间隔**递增**，像雨由疏到密。
  - 每项起始位置略有差异（奇数项 `-4px`、偶数项 `-6px`），并带 `±.15deg` 的轻微旋转——**落点不同**，这是雨，不是队列。150ms 落定，`--kami-ease-out`。
  - **第 13 项及以后不做任何动画**（直接呈现）。长列表的绘制预算优先于仪式感。
- **面板/抽屉入场**：外框 `translateY(6px) scale(.985)` → 归位（300ms，`--kami-ease-out`），湿度从 `1.25` 收敛；**内容不做错峰**（一屏只有一个运动主体）。

### 5.3 状态切换（填入⇄发送、渲染⇄原文）

- 新选项的"积水"自底升起（160ms），旧选项的水面**同步退回底部**。两个方向同时对向运动——这就是切换的全部节奏，不需要额外的提示动画。
- 前端替换箭头字符（`↵ / →`）后，箭头做一次 120ms 的 `translateY(3px)` 进入——**"新的一滴落下来"**。

### 5.4 悬停与聚焦

- 卡片：湿痕 `scaleX(0→1)` 180ms `--kami-ease-out`；下沉 `translateY(1px)` 140ms `--kami-ease`；接地影同步 140ms。
- 聚焦（`:focus-visible`）：湿痕 **0ms 直接呈现**（键盘用户不该等动画），焦点环 120ms 淡入。
- 按钮：底色加深 120ms；图标按钮的湿痕 `scale(.6→1)` 140ms。
- **全部悬停效果包在 `@media (hover: hover) and (pointer: fine)` 内**——手机上不"粘住"。

### 5.5 展开与收起

- **绝不做高度过渡。** 理由有三：① iframe 高度由 `body.scrollHeight` 决定，高度动画会让宿主反复重排、楼层高度抖动；② `height: auto` 本来就不可动画；③ 契约禁止依赖滚动。所以高度变化是**瞬时**的，皮肤只负责"雾"。
- **展开（200ms）**：整体雾由"擦开前"（湿度 `.9`）到"擦净"（`0`）；同时正文块上缘一条被斜切过的高光条在 220ms 内**横扫而过**（`translateX(-40% → 120%)`，`mix-blend-mode: screen`，透明度峰值 .35）——那是手掌擦过玻璃留下的一道痕。**擦的是玻璃，不是字**（所以正文本身永远不模糊，这既更真实，也避开了"filter 不得出现在每一帧上"的性能红线）。
- **收起（160ms）**：雾用 `cubic-bezier(.4,.05,.9,.2)` **不均匀地回来**（先慢后快），像雾重新蒙上；正文立即消失；水位线以 `transform-origin: bottom` 退回。
- `.kami-chev` 旋转 160ms + 过冲缓动。

### 5.6 成功与失败反馈

- **成功是一条有先后的链**（总长约 480ms）：
  水线自顶落到底（220ms）→ 触底瞬间卡片底边亮起朱橙渐隐线（80ms）→ 延迟 60ms 后 toast 从下方渗上来（200ms）。**有先后关系，不是同时发生**——这是"落下 → 溅起 → 消息"的物理顺序。
- **失败是瞬时的**：卡片底边锯齿线 0ms 出现，140ms 的 ±1px 横向抖动（两个来回），toast 同时渗上来。**错误不延迟。**
- 颜色不加戏：成功用朱橙（本来就是暖的），失败用 `--kami-warn`。**不用绿色**——雨夜里没有绿灯。

### 5.7 长文本渲染

- `.kami-md` 的**前 6 个直接子元素**做极轻的入场（opacity + `translateY(-2px)→0`，140ms，间隔 `30/60/90/120/150/180ms`）；**第 7 个及以后不做任何动画**。
- **不做**打字机、逐字、逐行显现、滚动驱动动画（滚动驱动在不能滚动的 iframe 里没有意义——主动排除）。
- **动效只发生在容器的表面上**（雾、水位线、边框、接地影），**永远不发生在字上**。

### 5.8 降级

| 档位 | 行为 |
|---|---|
| `full` | 全部启用（默认） |
| `calm` | 停止所有循环动画（含雾的 12s 微呼吸、`runnel`）；`--kami-enter-y: -2px`；`--kami-stagger: 0ms`（列表项同时落定，保留 150ms 的落定动作）；**`.kami-chev` 与开关 knob 的过冲改为 `--kami-ease`**；状态切换与悬停时长不变 |
| `off` / `prefers-reduced-motion: reduce` | 按契约把 `--kami-dur-fast/dur/dur-slow` 置 `1ms`、`--kami-enter-y: 0px`、`--kami-enter-scale: 1`、`--kami-stagger: 0ms`；**并额外对 `.kami-root` 下所有动画元素写 `animation: none !important`**（比只依赖令牌更彻底）；水线/水位线的**终态直接呈现**（`transform: none` + 静态样式），保证状态不丢、信息不缺 |

## 6. 高级特效清单

四个特效**全部只作用在 `.kami-surface`**（严格按契约 §4.2 的"特效承载面"），彼此**互不冲突**：`fog` 占 `::before`、`runnel` 占 `::after`、`beading`/`longexposure` 占元素自身 `background-image` 的附加层。
**全部关闭时界面依然完整**（特效只负责氛围，不承担任何信息）。

| id | 中文名 | 默认 | 作用在 `.kami-surface` 上的实现思路 | 性能代价 | 与概念的关系 |
|---|---|---|---|---|---|
| `fog` | **起雾** | **开** | `::before` 铺满（严格 `inset: 0`，**不含外发光**）的三层径向渐变：一大团弥散的雾 + 两处靠近边缘的浓结核；其 `opacity` 直接绑定自定义属性 `--kami-wetness`（`@property` 注册为 `<number>`，可插值）。入场时从 `1.55` 收敛到 `1`，展开时从 `.9` 收敛到 `0`。另含一个 **12s 的极慢呼吸**（opacity `1 → .94 → 1`，`ease-in-out`），只在 `.kami-shell` 上 | 1 个合成层的 opacity 动画；**无 filter、无逐帧重绘**。12s 循环只有合成器在做纹理合成，CPU 占用近似为零。`calm/off` 档停止 | **整套皮肤的第一眼就是它。** 雾 = 心事的外壳；"擦开"= 阅读模型的内心。雾不是装饰，是本皮肤的交互语法 |
| `beading` | **挂水** | **开** | 一枚内联 SVG 的 `data:URI`（约 340 字节，由静态路径描述十几颗大小不一的水珠，**不使用 feTurbulence/feGaussianBlur**），作为 `.kami-surface` 的**第二个 `background-image` 层**，`repeat`，`96px 96px`，整体不透明度 ≈ .05，`background-blend-mode: overlay` 让它跟着底色明暗变化 | **一次性栅格化、静态层、零动画**。但它是"每张卡片一份"的背景层 → 因此**设上限**：`:nth-child(n+13)` 与 `.is-demo` 的卡片不再携带该背景（见 §10-C5）。面积被限制在卡片内，不含外扩 | "玻璃上有水"的最小、最省的说法。它**不是雨滴贴纸**——它是表面的疏水颗粒，你要凑近才看得见。默认开，是因为它定义了这套皮肤的"手感" |

| id | label | desc |
|---|---|---|
| `fog` | 起雾 | 玻璃上的一层水汽：展开时被擦开，收起后慢慢重新蒙上。这是整套皮肤的第一眼。 |

## 8. 响应式与可达性

### 8.1 宿主的响应式差异（关键工程判断）

- **消息 iframe 有自己的视口，宽度 ≈ 聊天宽度**，所以 `@media (max-width: …)` 在楼层里**按前端宽度生效**——这是可靠的。
- **脚本面板住在酒馆页面里**，它的 `@media` 按**整个页面宽度**生效（桌面永远很宽），面板自己缩窄时媒体查询不会跟随。
- **结论：面板内部的自适应必须用 `@container`**（在 `.kami-drop` 上声明 `container-type: inline-size`），不能靠 `@media`。这条差异如果不处理，面板被拖窄后布局就会崩。

### 8.2 320px（手机，硬底线）

- `--kami-items-min: 260px` → 卡片网格 **1 列**；`--kami-maxw: none`（铺满）。
- 头部在 `≤ 360px` 时 `flex-wrap: wrap`：标题与动作区各占一行；`.kami-sub`（计数）用 `order: 3` + `flex-basis: 100%` 掉到第三行最左。**计数不是可聚焦元素，`order` 不会破坏 tab 顺序。**
- 触摸目标：按钮 `≥ 42px` 高，卡片整卡可点（高度 `> 64px`）。
- 所有悬停效果被 `@media (hover: hover) and (pointer: fine)` 关掉，避免"粘住"。
- 正文 `--kami-fs: 15px` 起步 + `--kami-lh: 1.72`；`.kami-raw` 的 `word-break: break-word` 保证长 token 不撑破 iframe（撑破会让整层 iframe 宽度异常）。

### 8.3 平板（约 560–900px 的聊天宽度）

- 卡片网格自动变成 **2 列**（`auto-fill` + `minmax(260px, 1fr)`），无需断点。
- `--kami-pad-lg-x` 提到 `16px`；`--kami-gap-lg` 提到 `14px`。
- 头部不再换行（`< 360px` 的规则自然失效）。

### 8.4 桌面

- `--kami-maxw: 92ch`，`.kami-shell` 居中（`margin-inline: auto`），避免超宽行——中文一行超过 ~40 字就开始丢行。
- 面板内部用 `@container (min-width: 380px)`：`.kami-field` 变成"标签左、控件右"的两列；更窄时自动上下堆叠。
- 悬停效果全量启用。

### 8.5 键盘

- 不夺取任何原生行为：所有可点元素都是原生 `<button>` / `<input>`；选择器**只做外观**。
- `:focus-visible` 统一：`outline: 2px solid var(--kami-accent)` + `outline-offset: 3px`，外侧再叠一圈 `--kami-glow` 的洇散环（这是 `--kami-glow` 的唯一用途）。**不用 `outline: none` 的任何变体**。
- `.kami-collapse-head`（前端给了 `role=button tabindex=0`）与卡片用同款焦点环——**折叠头必须看起来和卡片一样可聚焦**。
- `.kami-range` / `.kami-switch`：真实 input 用 `opacity: 0` 定位覆盖时，焦点环画在 `+ .kami-switch-track` / 轨道上；绝不出现"能 Tab 到但看不见焦点"的情况。
- 视觉顺序 = DOM 顺序（`order` 只用在不可聚焦的计数上）。

### 8.6 对比度

- 正文最低 4.88:1（dark 的 `fg-mute`），主文字 13.29:1，次要 7.89:1；light 分别 5.35 / 13.64 / 6.41。全部 ≥ 4.5:1，且是对**实际合成色**（`--kami-card` / `--kami-card-2`）计算的。
- **湿/干、kind 类别都不以颜色为唯一识别手段**：湿干靠**描边闭合与否 + 圆角形状**（结构差异），kind 靠**色条位置 + 徽章文字**（同色盲下仍可读的文字仍在）。
- 强调色上的文字用**深色**（`--kami-accent-fg`），实测 6.81:1（dark）/ 5.61:1（light）。

### 8.7 reduced-motion 与契约兜底

- CSS 中必须同时包含 `@media (prefers-reduced-motion: reduce)` 与 `html[data-kami-motion="off"]` 两个兜底块（§7-5 的校验项），二者内容一致：令牌置 1ms / 0px，外加 `animation: none`。
- 另外提供 `calm` 档（见 §5.8）——**"我不想全关，只想安静一点"是一个真实存在的用户需求**，契约虽然只要求 off 兜底，但提供 calm 是这套皮肤的加分项。
- `off` 下所有终态直接呈现（水线落到底、水位线长满），**信息不丢**。

## 9. 主动"不做"的三件事

### ① 不做任何"水滴形状"的装饰元素（雨滴图标、雨伞 emoji、水滴分隔符、雨滴形状的 loading）
雨不是贴纸。一旦画出水滴，这套设计就降级成"雨天主题包"——所有推理都会变成"哦，下雨了"。
在这套皮肤里，雨只允许以**表面状态**出现：雾、湿痕、水位、水线、渍。**它不可以被画成一个东西。**

### ② 不做玻璃拟态的全场化
`backdrop-filter` 只出现在唯一的 `.kami-drop` 上。每个聊天楼层都开模糊，在长会话里是线性放大的成本；更重要的是——**二十个楼层的模糊玻璃堆在一起，"玻璃"这个概念本身就被稀释了**。只留一块真的玻璃，它才有分量。
同理拒绝任何循环的 `filter: blur()` 动画（包括"雾气呼吸"这种看起来很美的做法）：雾的呼吸**只用 opacity**，因为模糊必须逐帧重绘，而不透明度只需要合成器。

### ③ 不做长文的逐行/逐字显现
思维链常常上千字。任何"文字在动"的效果都会把**阅读**变成**等待**。
长文的第一原则是立刻可读：动效只允许发生在**容器的表面**（雾、水位线、边框、接地影），**永远不发生在字上**。因此也顺带排除了打字机、逐行淡入、滚动驱动文字——**字不动，人才读得下去。**

## 10. 自我批评与已做的实质修改

我以创意总监身份把自己的初稿审了一遍，以下五条批评中，M1–M5 都导致了**结构性修改**（不是改配色与文案）。

### 批评 C1：概念在最小尺度上失效
> 初版把"湿/干"交给颜色与透明度（湿 = 半透明、干 = 实色）。在 320px、每屏 300 字的真实阅读里，这两者几乎无法分辨——**"两块材质"这个核心概念在第一眼就丢掉了**，剩下的只是一套低饱和配色。

**修改 M1（结构性）：把湿/干从"颜色"搬到"边缘语法"。**
湿 = 描边两端 12px 渐隐 + 上缘高线不闭合 + 圆角上大下小极端化（14px → 4px）+ 内层正文块偏透明；干 = 闭合实线 + 规整四角 + 底边一条"纸厚"暗线 + 哑光实色。
差异现在是**结构性的**：与颜色无关、与屏幕宽度无关、缩小到 320px 依然成立，而且**是纯形状差异**，顺带解决了色盲可达性（§8.6）。这是本次修改里最重要的一条。
