# 皮肤设计简报：色块（`grokbot`）—— 当前默认皮肤

> 简报原文见 `design/_prompts/grokbot.md`（派给实现 subagent 的那一份，保留作历史）。
> 这一份记的是**概念与定稿后的取舍**，给后来改这套皮肤的人看。

## 一、概念

用户点名的方向：**Grok Bot 图标风格**。主 agent 联网找图、亲眼看过两张参考（在本地 `design/reference/grokbot/`，仅本地存在）：

- **Grok Bot.app 的应用图标**：一块深炭色圆角方板，板上坐一大块**哑光黏土白的有机 blob**（占下半部约 2/3，不对称、下缘更圆鼓），blob 上两只**深炭色倾斜胶囊眼**。没有描边、没有纹理、没有第二种颜色，体积感全靠上亮下暗的柔光。
- **登录页角色**：同一套语言，纯黑 blob + 两只白胶囊眼。

一句话：**无彩色、无描边、大圆角、黏土柔光。**

> ⚠️ **2026-09-21 用户裁定：眼睛一处不留。** 参考图那两只胶囊眼是原设计的身份符号，用户看过真机后要求
> 全部删掉。现在这套皮肤的身份只靠「大圆角块 × 炭白两级明度 × 纯平面」立住，记号一律用方块 / 圆角块
> （状态点、类型记号、开关旋钮、空态、预览缩略图）。`--kami-gb-eye-tilt` / `--kami-gb-eye` 令牌、
> `eyes` 特效、`eye-tilt` 参数、`kami-grokbot-blink` 关键帧**全部删除**，文案表里那句
> 「上面只有两只朝同侧倾斜的黑胶囊眼」也换掉了（新句子见 §五）。

## 三、这套皮肤踩过的坑（改它之前先看）

1. **令牌翻转漏项**：这套皮肤有两套令牌（炭底一套 / 黏土白本体一套），靠 `.kami-card` / `.kami-item` / `.kami-card-note` / `.kami-shell` 上的**令牌重映射**切换。
   漏掉任何一个令牌（比如 `--kami-accent-fg`）就会出现「强调底和它上面的字同色」= **1.00:1 完全看不见**（用户真机报的就是这个）。
   **改令牌表时，两套必须成对补齐。**
2. **令牌重映射要覆盖到「消息楼层的外壳」**：`.kami-shell` / `.kami-surface` 也要进重映射块（组件里到处是显式 `color: var(--kami-*)`，只靠 `color` 继承挡不住）。
   漏了就是「聊天楼层里标题白字压白底」。
3. **内边距别叠两层**：那条给「分组卡」补内边距的规则必须写成 `.kami-card:not(.kami-item)` ——
   条目卡自己有 12px 内边距，再叠一层 16/20 会把条目名挤到只剩 44px 宽，被逐字折断成竖排。
   反过来说：**卡自己该有内边距**（16/20 与消息楼层一致）。第六轮之前的做法是把面板里 `.kami-card` 的
   padding 清零、只补给卡头/标题/注释，正文块与字段行没人管 —— 实测文字墨水盒离圆角内缘 -4.7px。
4. **未选中卡片不能和容器同色**：面板里的卡是套着的，内外两层都吃 `--kami-card` 时会**完全同色**。
   现在的做法是「换一档明度的填充 + 一条看得见的边」，全程只用平面色块与实线。
5. **亮色方案（`data-kami-scheme="light"`）**：改动涉及的色值都是字面量，**只做过推算、没实测**（预览台跑的是暗色）。要动它请补一轮实测。
6. **「结构判据」要把子元素种类列全**（第六轮踩的）：面板网格的密集判据写的是
   `.kami-grid:has(> .kami-item)`，而带注释的条目卡外面多包一层 `.kami-item-note` ——
   只要一组里每张卡都带注释，判据就整条落空，退回 `--kami-items-min: 15rem`，367px 只排得下**一列**。
   现在写成 `:has(> .kami-item, > .kami-item-note)`。**改网格判据后要用预览台的列数探针逐格核对。**
7. **选中态的底换了，字就得跟着翻**（第六轮，第三次同型）：`.kami-item.is-on` / `.kami-btn.is-on`
   的底是墨块，而卡作用域里的 `--kami-fg` 也是墨 —— 1.00:1。`.kami-btn.is-on` 现在把
   `--kami-fg` / `--kami-fg-dim` / `--kami-fg-mute` / `--kami-line` / `--kami-line-strong` 一族整体翻成
   `--kami-accent-fg`。**新增任何「选中换底」的状态，先问一句：字翻了吗？**

## 四、当前实测（2026-09-21 第六轮后）

- `node build/lint-skins.mjs grokbot` PASS（97KB，100 个令牌；眼睛令牌与特效删掉后少了 2 个）。
- 暗色下最差对比度：开关关态旋钮 vs 轨道（**靠 2px 边达标**）、未选中卡 vs 外层白卡（靠边达标）、深底开关轨道 vs 面板（靠边达标）；正文与次要文字最低 5.11:1。
- **面板内的圆角余量（文字墨水盒到圆角内缘）**：🎨 卡 / 🌟 组卡 / 📜 卡 **15.3px**（改前 -4.7px，与行动选项前端的 16/20 完全同档）；
  🌟 条目卡 8.5px（条目卡自己 12px 内边距 + r=12，面板里一屏上百张卡，不再加大）；
  「显示」那张条状容器里的标签离卡左缘 **20.6px**（改前 2.6px）。
- **带注释的网格**：同页 9 个可见网格全部「3 列 卡 117px」（改前「💕 色色选项」是「1 列 367px」）。
- **引导面板**：皮肤页选中卡 字 #16161a 压底 rgb(242,241,238) = **15.98:1**（改前 ≈1.00:1）；
  模型页选中标题栏 字 rgb(242,241,238) 压底 rgb(22,22,26) = **15.98:1**（改前 1.00:1）；
  预览容器与预览 iframe 的 `pointer-events` 都是 **none**（改前 iframe 把点击吃掉）。
- **面板内溢出 0**（1280 与 375 两处）。

**第七轮（同日，用户提了 3 条）**：含条目网格的卡片（🌟 的卡片组与模型卡、引导模型页的模型卡）
左右内边距从 `0` 改成 **12px** —— 用户原话「预设面板和引导面板模型页的卡片内部卡片就和父容器卡片
没有内边距」，实测引导模型页里卡内条目卡离卡左缘只有 **1px**，改后 **13px**。
代价：🌟 面板网格 367→343px、条目卡 117→109px，最长的条目名「DS/GLM底部破限」从 2 行变 3 行
（仍未竖排，可接受）。这条改动同时**推翻**了下面 §三第 3 条里「卡里装网格就不要再留内边距」的旧结论 ——
旧结论是为了防「两层内边距把名字挤竖排」，现在改成留一档 12px 之后两层加起来仍在安全区。
