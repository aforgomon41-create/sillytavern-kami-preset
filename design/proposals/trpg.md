## 1. 核心概念

**「手作到一半的桌面」—— 一局还没开始的跑团。**

这套皮肤画的不是克苏鲁，也不是复古做旧，而是**一局跑团开场前的那三分钟**：GM 刚从草稿本上撕下一页纸摊在桌上，把骰子往角落一放，牌堆还没码齐。

所以整个界面只有四种**真实材质**，没有第五种：

1. **纸**（撕边、哑光、有稿纸格与随手涂鸦）—— 所有「大面」；
2. **硬纸板**（有厚度、切面看得见）—— 只出现在卡牌的底边上；
3. **卡纸**（更硬、更白、有底边厚度、角上被洗牌磨白）—— 所有「可以拿起来的东西」；
4. **骰子**（半立体的 d20 面片，一直在慢慢翻）—— 唯一的 3D，唯一会自己动的东西。

**基调是「清新」而不是「恐怖」**：奶油纸 + 藤绿墨水 + 一点点朱砂，没有一处发光。恐怖不在这套皮肤的职责里——**干净、手作、让人想动手点**，才是它要交付的东西。

## 2. 用户体验路径

**① 遇见（0–2 秒）**　回复读完，底部出现一张**浅色、边缘毛糙**的纸。这一眼的关键不是"好看"，是**材质越界**：聊天窗口里所有东西都是圆角、无衬线、悬浮的 UI，只有它是一张**撕下来的纸**——四条边都有不规则缺口，底下还压着第二张同形状的纸（厚度）。

**② 认出（2–5 秒）**　标题栏左边一颗**绿色的二十面体在慢慢翻面**：它一眼说明"这是桌上的一颗骰子，这一局开始了"。右边那行字（思维链）就写在纸上——楷体标题、藤绿点缀；没有卡片、没有底板，纸的毛边、稿纸格与随手涂鸦就在字旁边。

**③ 使用（第一次交互）**　展开思维链：正文头部出现一条操作行（渲染/原文 + 复制），下面是一张干净的纸：左边一道红铅笔线，格线被纸块盖住。

**④ 动手（行动选项）**　选项不是列表，是**一叠硬纸卡牌**：每张有底边厚度、左上角一枚歪着盖上去的类型章（用语义色）、右上角一个 ↵。悬停时整张卡**被拿起来 2px**（厚度阴影跟着变长）；按下时**被按进纸里 2px**（厚度消失）。点下去，卡面被荧光笔划过一遍。

**⑤ 长期**　它**愿意被关小**：关掉 `doodle`/`tape`/`wear` 退化成一张干净的打印纸；调到 `motion=off` 骰子**彻底停住**（不是减速）并停在同一个姿势，界面依然完整可读。

## 3. 视觉语言

### 3.1 色彩 —— 「一沓新纸 + 一管藤绿墨水」

- **纸**：容器 `#faf7ef`、卡纸 `#f4ecda`、正文纸 `#fffdf7`。是廉价影印纸的暖白，**不是牛皮纸的黄**（做旧 = 怀旧，不是这套皮肤要的东西）。
- **墨**：`#2c3444` 蓝黑。纸上的墨从来不是纯黑，用蓝黑能立刻摆脱"屏幕 UI"的塑料感，同时保住 12:1 的正文对比度。
- **藤绿 `#2f8f7a`**：唯一的强调色。它同时是**骰子的颜色**、选中态的底色、主按钮的底——骰子与 UI 共用一管墨水，这是这套皮肤"手作"的证明。
- **语义色只出现在卡牌的类型章上**，不进结构线、不进装饰。
- **暗色不是反色**：纸变成暖褐灰 `#23262c`（像被搬到台灯照不到的桌角），墨变成暖白，藤绿提亮到 `#4fb79a`；涂鸦图层由 `multiply` 换成 `screen`（**同一份墨，变成在深色桌上用粉笔画的**）。纸的物理属性（不透明、有撕边、有网格）完全不随明暗改变。

### 3.2 字体 —— 正文无衬线，标题楷体

正文必须是**干净的无衬线**（要读得下去、跨端一致）。**标题与类型章用楷体栈**（`Kaiti SC / STKaiti / KaiTi / LiSu`）：标题在这套皮肤里的身份是"**人写上去的标签**"，而楷体是唯一一个中文系统里稳定存在的"手写感"字体。安卓上没有楷体会优雅回落到无衬线——只影响标题，不影响正文。

### 3.3 材质与图形语言（会被反复使用）

撕边 · 纸叠厚度 · 稿纸格 · 手绘涂鸦（含简笔小人）· 胶带 · 卡纸底边 · 磨白的卡角 · 盖歪的章 · 红铅笔页边线

## 4. 组件设计

### 4.1 大面板 = 撕下来的草稿纸

- **撕边**：`--kami-surface-clip` 是一条 **38 点 polygon**，每条边 8–10 个缺口，缺口的深度全部写成 `calc(var(--kami-trpg-jag) * 0.15 ~ 1)` —— 所以缺口是**绝对像素**，纸无论多高多宽，毛边都不会被拉成一排大锯齿（这是用 `%` 画锯齿最常翻车的地方）。
- **纸叠厚度**：`.kami-root::before` 是一张**同形状、下沉 3px** 的深色纸，从外壳的撕边后面露出来 → 有厚度，而且比 `box-shadow` 便宜（**clip-path 会把 box-shadow 裁掉**，这是撕边纸必须付的代价，我用第二张纸把它换回来了）。
- **涂鸦**：**一层** `data:` 内联 SVG（460×340 的图块，约 2.3KB）画了 15 组东西——手绘 d20、箭头、圈注（双线）、框选（角上画出界）、波浪下划线、咖啡渍、排线、小 d6、星号、页码横线、一条随手勾的弧，以及**四个简笔小人**：拿剑的冒险者（圆头 + 举剑 + 十字护手）、多眼怪物（歪圆身体 + 三根尖角 + 三只眼 + 锯齿嘴）、戴帽枪手（宽檐帽 + 前伸手臂 + 长管 + 握把）、提灯调查员（高礼帽 + 大衣 + 提灯与两道光）。线条刻意手绘：头是三四段弧拼的、不闭合，线宽在 1.3–2.3 之间故意不齐。它作为**一个背景层**贴在纸面上，配 `background-blend-mode: multiply`（暗色 `screen`），**没有第二个元素、没有额外重绘**。
- **不干扰正文**：涂鸦只出现在纸面（padding、卡与卡之间、标题栏空白处）；所有正文块（`.kami-md` / `.kami-raw` / `.kami-card`）都是**不透明**的，字永远压在干净纸上。
- **其余两层**：稿纸格 = 一个 `radial-gradient` 点阵（间距 = 用户参数）；纸纹 = 一条 `repeating-linear-gradient`（3.5% 透明度）。合计 **4 层背景、一次画完、之后一次都不再重绘**。

### 4.2 思维链标题（本轮把「三折帷幕」整套删除）

**已删除**：用户看过实现之后认为"效果不佳"，本轮把折页（`::before` / `::after`）、`perspective` 翻面、展开换色、以及为它加的左右内边距补偿**全部移除**，配套令牌（`--kami-trpg-wing` / `-fold` / `-slope` / `-persp` / `-board-*`）一并删掉。

现在思维链标题**不写任何规则**，直接用通用 `.kami-title`：点 + 标题（左）+ 字数与箭头（右），字体（楷体）/字距/省略号截断沿用本皮肤，"纸感"由标题背后的纸面（撕边、稿纸格、涂鸦）承担。**不再做立体折板。**

> 仍有效的硬要求：**375px 下标题栏实测 347×67 = 一行**（骰子 36px + 标题 + 字数 + 箭头）。

- **唯一保留的一条经验**：折页当初坐在 `.kami-title` 的左右内边距里（而不是伸到盒子外面），标题栏才能用 `overflow: hidden` 走省略号 —— **超长标题实测 13 字时截断为 `奈亚子的DM帷幕与模组…`，标题栏仍是一行 62px**，不会压到右边的字数与箭头上。这条在通用 `.kami-title` 里继续成立。

### 4.3 左侧装饰 = 3D d20（见 §6 的性能论证）

### 4.4 卡牌 = 桌游硬纸卡

- 卡纸底 + **底边一道 3px 硬影**（纸板断面，不是柔光）+ 小圆角 4px。
- **磨损**（`wear`）：右上角一块磨白（对角渐变切角）、左下角一道压痕。
- **类型章**：`.kami-badge` 用 `currentColor` 上色 + 一层 82% 白的叠加（像印在白纸上），并 `rotate(-1.4°)` —— **歪的章才是手盖的**；悬停时它转正 0°（有人用手按平了）。
- **拿起来**：hover `translateY(-2px)` 且厚度阴影加长；active `translateY(+2px)` 且厚度消失（被按进纸里）。
- 布局：`--kami-items-min: 15.5rem` → 820px 宽是 **3 列**（像手里的一把牌），375px 是 **1 列**。

### 4.5 面板 = 摊开的最大一张纸

- 同款撕纸 + 涂鸦 + 稿纸格；标签页做成**卡片索引凸耳**（只有选中的那张"抽出来"：底色变成纸色 + 顶部一道藤绿）。
- 滑杆 = 一把尺（轨道上有刻度线、滑块是一小块木头）；开关 = 一枚硬纸片推子（方块，不是胶囊——**本皮肤没有药丸形**）。
- 窄屏贴底抽屉由脚本的 `!important` 几何保证；皮肤只负责外观。

## 5. 动效编舞

| 场合 | 动作 | 手法 |
|---|---|---|
| 展开正文 | 纸被放下来 | `translateY(-5px) → 0` + 淡入，`--kami-ease-out`，320ms |
| 折叠箭头 | 转 90° 并变成藤绿 | `transform: rotate(90deg)` |
| 卡牌悬停 | 被拿起来 2px，侧边 ↵ 右移 2px 并变清晰 | `transform` + `box-shadow` |
| 卡牌按下 | 被按进纸里 2px，厚度消失 | 同上（回弹方向相反） |
| 类型章悬停 | 从歪 1.4° 转正 | `transform: rotate(0)` |
| 骰子 | 一直在桌面上慢慢翻面（17s 一轮，四个姿势） | 只动 `transform`，见 §6 |
| 复制/填入成功 | 按钮变成藤绿描边（`.is-done`） | 颜色 + 底色 |

**没有一处动画碰 `filter` / `backdrop-filter` / `box-shadow` 的每一帧**（厚度阴影的过渡只发生在 hover/active 两个端点，不是循环）。

## 6. 高级特效 & 3D d20 的性能论证

### 6.1 为什么不是"真正的二十面体"

真正的 CSS 3D d20 = `preserve-3d` 容器 + **20 个三角面**。成本是乘法：这套 CSS 注入到**每一个聊天楼层**，同一楼层里骰子要出现在**思维链标题栏、行动选项标题栏、皮肤管理面板标题栏**三处，一屏轻松 4–6 个实例 —— 那就是 **80–120 个合成层**，滚动与流式生成时全部要参与合成。这个量级不可接受。

### 6.2 实现：半立体面片精灵 + 真 3D 容器

    <span class="kami-deco" data-kami-deco="d20" aria-hidden="true"></span>

- **容器**（`.kami-deco`）：`perspective`（= 5.6em，随字号缩放）+ `transform-style: preserve-3d` + `will-change: transform`（**全皮肤唯一一处 will-change**）+ `pointer-events: none`；`width/height = calc(var(--kami-fs) * 2.4 * var(--kami-trpg-die))`（面板里 3.4 倍），骰子尺寸跟着字号缩放走，不是写死的 px。
- **面片精灵**（`::before`）：`clip-path: polygon(六边形)` + **一层 conic-gradient 六瓣明暗**（每瓣之间夹 0.9° 的暗色折线 = 棱）+ 一层整体受光渐变。
- **中心面**（`::after`）：`clip-path: polygon(三角)`，就是"正对镜头的那一面"，比周围亮一档。它的三个顶点正好压在三条棱上 → 棱从中心面的三个顶点向外射到六边形的三个顶点，**这就是 d20 图标的标准分解**。
- 两个伪元素的 `transform` 每帧同步（同一组 `@keyframes`、同一个 delay），在容器的 perspective 里做 `rotateX(-21°~-5°) rotateY(-26°~+29°) rotateZ(-4°~+6°)` 的**有界自转**：**刻意不做整圈 360°**——一片平面转满一圈必然有两次侧对镜头（会"消失"），有界自转在小尺寸下读起来才是"骰子在桌上被拨动"。
- **合成层预算**：每个实例 = **容器 1 层（will-change）+ 一个 3D 渲染上下文**（两个伪元素共享同一套 3D 空间，浏览器按上下文合成，不是 2 层）。对比 20 面方案的 20+ 层，**降了一个数量级**；且每帧只重算 `transform`，没有重绘、没有重新栅格化。
- **多实例错相**：`animation-delay` 按容器分别设成 **-0.4s / -6.3s / -11.6s / -3.1s**（思维链 / 行动选项 / 面板 / 面板内预览），否则一屏里几颗骰子会像一排同步闪的灯。
- **停得住**：`data-kami-motion="off"`、`calm`、`prefers-reduced-motion` 三处都是 `animation: none`（**实测 `animation-name: none`**），骰子停在 `translateZ(2px) rotateX(-14deg) rotateY(-26deg)` 这个静态姿势上——不是一个转得慢的骰子。
- 容器底下还有一层**桌面接触影**（一个 11% 高的椭圆渐变），骰子浮在影子上，所以"在桌上"这件事成立。

## 7. 令牌映射（契约 §3 全覆盖，共 108 个）

- **色彩**：`--kami-bg/card/card-2` 三档纸；`--kami-line/-strong` 用蓝黑低透明；`--kami-t1/t2/t3` 三级叠加；`--kami-accent` = 骰子色 = 藤绿。

- **风格性文案**（契约 §3.7，只有三处）：`--kami-label-think-title` / `--kami-label-think-title-open` / `--kami-label-options-title`，本轮**一律中性占位**（「思维链」「行动选项」），措辞交给文案 Agent 统一重写。功能性文案（渲染/原文、填入/发送、复制、N 项、N 字）皮肤一个都没有提供、也没有覆盖。

## 8. 响应式与可达性

- **320px 起成立**。标题栏 `flex-wrap: nowrap` + 标题 `text-overflow: ellipsis`：**标题再长也只截断不换行**（上一套「记事本」就是在这里翻车的）。
- 375px 实测：思维链 iframe **347×67 = 一行**，行动选项 **347×679**（1 列）；820px 实测：67px / 336px（3 列）。
- 面板窄屏是**贴底抽屉**（脚本下发 `bottom:0 / height:78% !important`），皮肤只改外观；抽屉贴底时撕边只剩左右与上边可见，符合"纸压在桌沿上"。
- **焦点可见**：`:focus-visible` 统一给 2px **虚线**藤绿描边（虚线跟手作基调一致，也区别于任何"发光"）。
- **对比度**：正文墨 `#2c3444` 对纸 `#fffdf7` ≈ 12:1；暗色方案 `#e2dbc9` 对 `#23262c` ≈ 11:1；次级文字对卡纸 ≈ 5.1:1。
- **装饰**：`.kami-deco` 是 `aria-hidden` + `pointer-events: none`，绝不吃点击、不进无障树。
- **不依赖滚动、不用 vh、不用 `position: fixed` 铺满**；消息楼层里**不使用 `filter` / `backdrop-filter`**。

## 9. 主动「不做」的三件事

1. **不做整圈 360° 自转**——一片平面转满一圈会有两次"消失"，看起来像闪烁，而不是骰子在滚；有界自转更贵气也更真。
2. **不做位图/序列帧/WebGL 骰子**——皮肤不能有外部资源，而且按楼层线性付费；位图骰子在任何 DPR 下都不如渐变清晰。
3. **不做彩色投影与辉光**——这套皮肤的可信度来自"纸与纸板"，一旦有东西发光，材质立刻变成屏幕 UI。

## 10. 自我批评与已做的实质修改

- **踩坑一（已修）**：`.kami-shell` 与 `.kami-surface` 是**同一个元素**。我一度在 `.kami-shell` 里写了 `background: transparent` 想把兜底皮肤的背景清掉——**简写连 `background-image` / `background-color` 一起重置**，于是四层纸面在计算样式里全变成 `none`，整张纸塌成灰底。现在那里只留 `max-width / border / border-radius / box-shadow` 四条，并在注释里写明"这里绝不能写 background 简写"。
- **踩坑二（已修）**：`.kami-surface` 的 `position: relative`（特异性 0,2,1）**盖过了脚本几何层的 `.kami-drop{position:absolute}`（0,1,0）**。宽屏看不出来（relative + left/top 恰好落在同一个位置），**窄屏抽屉立刻塌到屏幕顶部**——探针读出 `面板 0,0,375,521`（top 应该是 147）才抓到。现在 `.kami-drop` 显式写回 `position: absolute`。**这两条建议同步给其它皮肤的负责人。**
- **主动收敛**：涂鸦第一版线条透明度 0.5、纸纹 0.05，看着有点"花"；现在压到 **0.42 / 0.035**，让它只在纸的边缘说话，正文区域干净。
- **主动收敛**：卡牌的厚度阴影第一版给到 4px，卡片显得"发胖"；现在 3px 硬影 + 一层更远的柔影，卡片立起来但不变厚。
