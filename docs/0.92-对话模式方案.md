## 三、待拍板（三项）

### ① 开关卡片放哪儿

`[模型类型]` 卡片不存在，所以三种放法：

- **A（推荐）**：放进 `🤖 [模型类型]` 组，**这会顺带让那张卡片重新出现**（组里不再"全是模型专属条目"，
  降级规则不触发）。好处：开关就在模型旁边，符合"对话模式是模型侧的运行模式"这个直觉。
  代价：`🪓 神秘咒语` 会因此多出一个 tab，面板上多一页。
- **B**：新建一个独立卡片（例如 `💬 [运行模式] 任选`），放在 `🪓 神秘咒语` 层级里。
  好处：不动模型类型那条单选的语义；代价：多一张卡片。
- **C**：放进 `🧠 推理选项` 层级，与推理格式并列。

⚠️ `[模型类型]` 是**单选**（DS/GLM/Gemini/KIMI 四选一）。把"对话模式"塞进去，
如果它也被当成该单选组的成员，**打开对话模式会把当前选中的模型关掉**。
A 方案必须先确认/解决这一条（例如给对话模式条目做成"不属于该单选组"的写法，或改该组为多选）。

### ② 状态保存在哪

- **推荐**：脚本变量 `kami-preset.dialog.saved`，存 `{ [identifier]: enabled }`；
  另存 `kami-preset.dialog.on` 记住对话模式开关。
  理由：这是**用户本机的开关状态**，不是预设内容，不该写进预设文件；
  而且脚本变量跟着预设走（换预设不串）。
- 备选：存进预设条目里（会污染预设、且别人导入你的预设会带上你的开关组合）——**不推荐**。

### ③ 对话模式条目本身归哪组、开/关由谁控制

用户说"新增一个条目，放到推理格式里"。但 `🤔 [推理格式]` 是**单选**（DeepSeek强强 / GLM偷偷 / Gemini糖糖），
把一个对话模式条目加进去会破坏单选语义（打开对话模式会顶掉推理格式）。

三种做法：

- **甲（推荐）**：条目**不做成可选条目**，而是用 `{{setvar::dialog_mode::…}}` 变量注入 ——
  卡片开关只负责往变量里写/清空那段"元讨论"提示词，不碰推理格式的单选。
  代价：模型侧看不到"对话模式"这条的可视开关（但面板卡片就是它的开关）。
- **乙**：条目放进 `🤔 [推理格式]` 组但**不属于该单选**（需要确认解析器怎么表达"裸放条目在单选组里"），
  风险是单选逻辑可能连带关掉它。
- **丙**：条目独立成一个新卡片（比如 `💬 [对话模式] 任选`），开关就是它自己的条目开关 ——
  最简单、语义最干净，但卡片数与用户描述的位置略有出入。

## 四、我建议的落地形态

卡片 A + 状态 ①② + 条目 丙 的组合最稳：

1. 预设里加一个 `🪓 神秘咒语` 层级下的 `💬 [对话模式] 任选` 卡片（或放进 `[模型类型]` 组，看用户选 A/B），
   卡片下一张条目「💬 对话模式」，正文就是那段"跳出跑团、进入元讨论"的提示词。
2. 卡片开关打开时：把 ①节 列出的组**当前状态**存进脚本变量 → 关掉那些组的条目。
3. 关闭时：从脚本变量恢复。
4. 用户手动改过某条目后，以手动为准（不再被对话模式反复覆盖）—— 具体口径待定：
   是"每次关闭都恢复进入前的快照"，还是"只在快照存在时恢复一次"。
