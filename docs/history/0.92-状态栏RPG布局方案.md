## 一、页面结构（九页 · 每页都有子 tab）

> **子 tab 是用户 2026-10-07 追加的要求，并且明确要求"每页都要"。**
> 主角因为 `items` / `wealth` / `mount` / `skills` / `traits` / `special_stats` 全在一棵子树里，
> 塞一页会变成很长的滚动条；其余页同理（数据一多就翻不完）。

| 主 tab | 子 tab | 子 tab 装什么 |
|---|---|---|
| **① 主角** | 概览 / 背包 / 技能 | 身份+生理+属性+驱动力 / 货币+装备槽+物品 / 主动+被动+专有机制 |
| **② 角色** | 在场 / 全部 | 按 `present_chars` 分；在场是在这个场景里的人 |
| **③ 地图** | 节点图 / 地点详情 | 拓扑图 / 区域层级与地点清单 |
| **④ 势力** | 声望 / 外交 / 组织 | 逐角色声望（最差排前）/ 势力间关系 / 领袖+范围+目标+计划 |
| **⑤ 剧情线** | 主线 / 支线 / 个人 | 按 `priority` 分（main / side / personal） |
| **⑥ 任务** | 进行中 / 待办 / 已结束 | 按 `status` 分（active / pending / done+failed） |
| **⑦ 不动产** | 自有 / 按类型 / 未探明 | 归属我的 / 按 `type` 分 / `is_found=false` |
| **⑧ 设定集** | 按 `category` 分档 | 世界法则 / 种族文化 / 魔法科技 / 历史事件 / 宗教信仰 / 禁忌秘闻 |
| **⑨ 设置** | 模块 / 显示 / 关于 | 模块开关 / 显示选项 / 版本信息+检查更新 |

**三条设计规则**：

1. **子 tab 按状态分组，不是按字段筛选**。状态分组（进行中/已完成、主线/支线）本身就是信息架构；
   而"按类型/按名称"这种排序与字段筛选留在**筛选条**里（子 tab 下面那一行），两者不重复；
2. **子 tab ≤ 5 个**（设定集六个分类除外 —— 分类是数据自带的，不可合并）。
   超出就在子 tab 条里横滑，不换行、不折行；
3. **只显示有内容的子 tab**，计数为 0 的不出（设定集只显示实际有词条的类目）。
   全部为空时整行子 tab 不显示。

> 地图页的"地点详情"子 tab **不是**用户否掉的"层级列表"的复活：用户否的是
> **用列表代替图**；图是主视图（默认），详情页只是区域→地点清单的查询入口。

## 三、子 tab 架构

### 3.1 交互与状态

- 子 tab 条紧贴在主标签行**下方**，是**分段控件**（圆角胶囊 + 当前项带下沿强调线），不换行、横滑；
- **当前子 tab 按主 tab 分别记忆**（`uiState.sub[主tab]`），切到别的页再回来仍在原处；
- **只有 2 个及以上子 tab 时才显示这一行**（只有 1 个就直接省掉，少一行占屏）；
- 子 tab 与主 tab 都是**纯逻辑**产出：`subTabsOf(stat, mainTab)`，DOM 只画。

### 3.2 子 tab 按数据存在与否动态出现

| 子 tab | 出现条件 |
|---|---|
| 概览 | **恒有**（主角的身份/属性/驱动力本来就该有） |
| 背包 | `items` 非空 **或** `wealth` 非空 |
| 技能 | `skills` / `traits` / `special_stats` 任一非空 |

这条是为非 RPG 场景留的：恋爱/日常题材的主角可能一件装备都没有，
**不许给用户看三个空页**。数据没有就不出这一页；全空时只剩"概览"。

## 四、主角 › 背包

### 4.1 从上到下

    筛选条   全部 6 | 装备 2 | 道具 1 | 消耗 1 | 关键 1 | 杂物 1
    货币行   ⊙ 金币 12 · 银币 45                      ← wealth，货币名:数值
    已装备   ┌────────┐┌────────┐┌────────┐
             │ 武器   ││ 护甲   ││ 饰品   │          ← 装备槽：已占用亮起，空槽画成凹槽
             │精钢猎弓││磨损皮甲││  —     │
             └────────┘└────────┘└────────┘
    随身物品
      ┌────────────────────────────────────┐
      │ [剑] 精钢猎弓 equip [已装备]    ×1 ＋│   ← 折叠态：图标 + 名 + 类型 + 数量
      │      一把做工扎实的猎弓…             │
      └────────────────────────────────────┘
      展开后多出：真相（real_desc，仅剧透开关开）/ 类型 / 数量

### 4.2 三条设计决定

1. **装备槽不按"部位"分**。数据里只有 `equipped: true`，**没有部位字段**，
   所以槽位画成三格通用槽（武器/护甲/饰品只是展示名），有几件已装备就点亮几格；
   要真正的部位系统就得给变量加字段（见第十节待你定）。
2. **`real_desc` 是剧透**：只有"显示剧透内容"打开时才渲染，与设定集的 `truth` 走同一个开关。
   实测示例数据里 6 件物品有 2 件带 `real_desc`。
3. **类型 → 图标与配色**（一眼分辨类别）：

   | type | 图标 | 槽色 |
   |---|---|---|
   | `equip` 装备 | 剑 | 琥珀（金） |
   | `prop` 道具 | 药瓶 | 苔绿 |
   | `consume` 消耗 | 药瓶 | 苔绿（数量常 >1） |
   | `key` 关键 | 钥匙 | 紫 |
   | `misc` 杂物 | 卡片 | 中性灰 |

### 4.3 坐骑（`mount`）放哪

`mount` 是可选字段，形状与 items 同族。**放背包页底部单独一节**（名称 + 类型 + 状态 + 是否骑乘），
不塞进物品清单 —— 它不是"一件东西"，有 `status`（健康良好）这种活的属性。

    筛选条   全部 5 | 主动 2 | 被动 2 | 机制 1
    主动技能  ⚡ 连珠射击    瞬间搭上两支箭连续射击        ＋
              ⚡ 盾击        用盾牌撞击敌人造成短暂眩晕     ＋

## 六、② 角色（NPC）

**只展示 NPC**：`characters` 里排除 `is_user: true` 的那一个。

### 6.1 顶部筛选条

    在场 2 | 全部 6 | 核心 2 | 配角 3                          6 人

- **在场**（默认）：`status.present_chars` 里列出的；
- **全部**：所有 NPC；
- **核心 / 配角**：按 `role` 分（`core` / `major` / `minor`）；
- 筛选是**纯逻辑**：`npcListOf(stat, filter)` 写在 `_status-view.js`，DOM 只画结果；
- 筛选项**带计数**，且计数为 0 的档位不显示（免得点出一个空列表）。

### 6.2 卡片：默认折叠，展开才看细节

    折叠态  ┌───────────────────────────────┐

            │        白鸦 · 本场景            │
            │ 状态良好 · 好感 +8              │  ← 一行摘要
            └───────────────────────────────┘
    展开态  ┌───────────────────────────────┐
            │ [头像] 艾莉丝  [core]       －  │
            │        白鸦 · 本场景            │
            │ ● 状态良好                      │
            │ 身份不明的少女，随身携带一枚旧徽记│

- **折叠状态要记住**（`uiState.folds`，写进脚本变量），这是差异更新的收益之一；

- 头像无图时按名字取色相（已有），本次只换形状与描边。

## 七、③ 地图（节点图）

### 7.1 数据 → 图的映射

| 数据 | 图上是什么 |
|---|---|
| `map_nodes[realm]` | 一个大区**分组**（底色分区 + 左上角区名） |
| `areas[area]` | **一个节点**（圆） |
| `areas[*].connections[]` | **一条边**（无向；同一对只画一条） |
| `is_found` | 未探明 = 虚线空心圆 + 名字换 `？？？` |
| `status.location.area` | **当前所在节点**：加一圈光环 + 填充加重 |
| `spots[]` | 不画成节点（太密），点开节点后在下方列出来 |

### 7.2 布局算法（**纯逻辑，可单测**）

    mapGraphOf(stat) → { nodes: [{id,name,found,current,realm,x,y}], edges: [{a,b,found}] }

- 位置计算用**种子化的环形 + 力导向微调**：同一个 ID 永远得到同一个坐标（可复现、可断言）；
- 同一大区内：**当前所在地放中心**，其余已探明区域按 ID 哈希散在圆周上；
- 未连通（`connections` 指不到）的区域放**外圈**，虚线描边；
- 边：两端都探明 = 实线；任一端未探明 = **虚线**；
- 坐标归一化到 `viewBox`，由 CSS 自适应缩放（手机与 PC 共用一套坐标）。

### 7.3 交互与退化

- 点节点 → 下方展开该区域的地点列表（`spots`）；
- **视图切换**：图 / 列表。默认：PC 图，手机在节点数 > 8 时默认列表（手机画不下）；
- 筛选：全部 / 已探明 / 未探明；
- 图例常驻在底部：当前所在 / 已探明 / 未探明 / 未探明通路。

**为什么必须给列表退化**：一屏 14 个区域时节点图会挤成一团，圆点小于可点尺寸。
给用户一个明确的切换，比硬画一张看不清的图好。

## 八、④–⑧ 其余五页：子 tab + 筛选条两层

**统一模板**：

    主标签行    [主角][角色][地图]…                     ← 图标，当前项带文字
    子 tab 条   （ 声望 ）（外交）（组织）                ← 分段控件，当前项带下沿强调线
    筛选条      （按声望升序）（按名称）                  ← 排序 / 字段筛选，横滑
    卡片区      卡片默认折叠，展开才看细节                ← 再深一层仍然折叠

**"子 tab"与"筛选条"的分工**（这是本稿新增的一条纪律，避免两套东西打架）：

| | 管什么 | 例子 |
|---|---|---|
| **子 tab** | **状态分组**（互斥的整体切换） | 进行中 / 待办 / 已结束；主线 / 支线 / 个人；声望 / 外交 / 组织 |
| **筛选条** | **排序与字段筛选**（同组内的收窄） | 按声望升序 / 按名称；赏金委托 / 阵营征召；住宅 / 据点 / 商铺 |

各页的子 tab 与筛选条：

| 页 | 子 tab | 子 tab 内的筛选条 |
|---|---|---|
| ④ 势力 | 声望 / 外交 / 组织 | 声望页：按声望升序（默认，最差排前）/ 按名称 |
| ⑤ 剧情线 | 主线 / 支线 / 个人 | 全部 / 未完结 / 已完结 |
| ⑥ 任务 | 进行中 / 待办 / 已结束 | 按 `type`：主线使命 / 赏金委托 / 阵营征召 / 突发机缘 |
| ⑦ 不动产 | 自有 / 按类型 / 未探明 | 按 `type`：住宅 / 据点 / 商铺 / 要塞 / 庄园 / 工坊 |
| ⑧ 设定集 | 按 `category` 六个分类 | 无（分类本身就是子 tab） |

**默认落在哪一档**：势力→声望（用户此前点名"我最差的排前面"）；剧情线→主线；
任务→进行中；不动产→自有；设定集→第一个有内容的分类。

**"声望/外交/组织"三分是有数据依据的**：`factions[*]` 里有三块互不相干的数据 ——
`rep`（逐角色声望，带 `title` 头衔与 `key_event`）、`diplomacy`（对其他势力的关系与动向）、
`leader`+`domain`+`goals`+`plan`（组织本身）。三块塞一张卡就是一条长滚动条。

## 九、⑨ 设置：三个子 tab

    模块    八个模块的显示开关 + 一句说明（"关掉的模块不会出现在标签行里，也不再读取它的数据"）
    显示    有数据时展开标题栏 / 显示剧透内容 / 无数据时显示示例 / 恢复默认位置
    关于    预设版本（含构建号）/ 酒馆版本 / 酒馆助手版本 + 「检查更新」按钮

**"关于"从别处收进来的**：40 号「预设设置」面板里早就有"关于"页（版本三个读数 + 检查更新），
状态栏这边此前没有。收进设置的子 tab 之后，两处保持一致的口径。

## 十、组件规范（通用件，四个面板共用）

| 组件 | 结构 | 必守规则 |
|---|---|---|
| 卡 | `.kami-card` | `display:flex;flex-direction:column;min-width:0` |
| 折叠卡 | `.kami-card.is-folded` | 折叠态只留头部 + 一行摘要；状态存 `uiState` |
| 筛选条 | `.kami-fbar` | 横滑不换行；选中项带计数；计数为 0 不显示 |
| 条 | `.kami-w-bar` | 轨道是**凹陷槽**（内阴影 + 内描边）；填充渐变 + 顶部 1px 高光 |
| 双向条 | `.is-signed` | 零点刻度 50%；负段另配色；`left/width` 由脚本算 |
| 档位菱形 | `.kami-w-rank` | 外框 `rotate(45deg)` + 内部反向旋转的文字 |
| 状态环形 | `.kami-w-badge` | 6px 色点 + 胶囊底 |
| 旗帜标 | `.kami-flag` | `clip-path` 右侧斜切；任务与优先级专用 |
| 标签片 | `.kami-w-chip` | 小圆角矩形，不与胶囊混用 |
| 区块标题 | `.kami-ia-sec-t` | 左侧 3px 强调竖条 + 图标 +（右侧可挂计数） |

## 十三、风险

1. 节点图在区域多时挤成一团 → 给列表退化 + 节点数阈值；
2. 折叠/筛选状态丢失 → 状态进 `uiState` 明账（不是读 DOM）；
3. 手机画不下 → 抽屉单列 + 节点数 > 8 默认列表；
4. 18 套皮肤同时改 → 逐套截图 + 浅色六套单独复核；
5. 文字被压 → `min-width:0` 进规范与守卫；
6. **装备槽是"假"的**：数据里只有 `equipped: true`，**没有部位字段**，所以槽位只能画成通用格。
   要做真部位系统（武器/护甲/饰品各一格、穿脱互斥）就得给变量的 `items` 加一个 `slot` 字段 ——
   那是改变量规范的活，**不在本次重构范围内**，见第十节。

## 十四、需要你拍板（七项）

| # | 事项 | 我的建议 | 影响面 |
|---|---|---|---|
| 1 | 子 tab 内的**筛选条默认值** | 角色页子 tab 内**不再加筛选**（子 tab 已经分了在场/全部）；任务页每个子 tab 内默认"全部类型" | 小 |
| 2 | 剧情线**要不要"个人"档** | **要**（`priority` 本来就有 personal）。已有的子 tab 规则：某档 0 条时不显示；全空则整行不显示 | 小 |
| 3 | 地图**默认视图** | PC 默认节点图；手机区域数 > 8 默认列表，并**常驻一个图/列表切换钮** | 中 |
| 4 | **折叠默认态** | 全部卡片默认收起；**折叠态也要显示一行关键摘要**（NPC 给状态+好感、任务给目标、势力给声望） | 中 |
| 5 | 装备槽**要不要真部位** | 本次**不做**。要做得给 `items` 加 `slot` 字段 + 改 MVU schema，属于另一条线 | **大**（改变量规范） |
| 6 | **货币显示规则** | 主货币优先 + 其余收起，同族零值折叠（`金币12/银币45` → `金币 12 · 银币 45`）；非数值的等价物（如"三枚旧银币"）按原样显示 | 小 |
| 7 | 手机端**筛选条是否默认折叠** | **默认折叠成一个筛选图标**，点了才展开 | 中 |

### 逐条说明

**1 · 筛选条默认值。** 子 tab 已经承担了状态分组，如果再在子 tab 内放一排"按类型/按名称"，
第一屏会被两排横滑占满。我的意见：任务页保留（类型确实多），其余页只在需要时加。

**2 · 剧情线"个人"档。** 数据里 `priority` 三档都在，做出来不额外花钱。
但要接受一个后果：**如果某档 0 条，那个子 tab 不显示**；如果三档全 0，整行子 tab 消失。

**3 · 地图默认视图。** 这条最需要你定，因为它决定了地图页的"第一印象"。
手机上一屏 14 个节点会挤成一团、圆点小于可点尺寸，所以给列表退化；
但如果你希望手机上**永远看图**，我就改成"图里只画已探明 + 当前连通的那一圈"，其余进详情页。

**4 · 折叠默认态。** 我推荐全收起，但**必须**配一条：折叠态要带一行摘要，
否则收起后全是一模一样的标题条，扫不出信息（那样折叠就白做了）。
主角页的"主角块"例外 —— 只有一张卡，默认展开。

**5 · 装备槽真部位。** 这是七项里唯一会**动变量规范**的。现在 `items[*]` 只有
`equipped: true/false`（`手写变量结构.yaml` 第 117–124 行），没有部位。
加 `slot` 字段意味着：改 yaml 规范 → 改 MVU schema（`01-mvu-zod.js`）→ 改示例数据 →
改 111 条字段标签表。**建议单独开一轮做，不塞进本次重构。**

**6 · 货币显示规则。** `wealth` 是自由键值对，可能有三四种货币，
也可能出现 `等价物名: "三枚旧银币"` 这种非数值。规则要能兜住两种情况。

**7 · 手机筛选条折叠。** 手机上会有三层横滑（主标签 / 子 tab / 筛选条），
我担心第一屏被吃掉太多。**这条我没渲染验证过**，你定了我就去验证。
