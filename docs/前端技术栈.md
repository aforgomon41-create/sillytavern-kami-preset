# 前端技术栈（0.93）

> 2026-10-27 整理：由原《0.92-技术栈迁移》改写。原文是迁移过程的流水记录，前后段落互相矛盾（同一份里既写「其余 7 个面板仍是老写法」又写「全部完成」；
> 「Radix 开关会打断皮肤、先别换」也已被 2026-10-26 的提交推翻）。本文只写**现在的样子**；迁移经过看 `git log`（2026-10-26 那批提交）。
>
> 用户裁定（2026-10-26）：交互组件不自研，用成熟的无头组件库（Radix）；框架用 React，只打包一份共享运行库；样式用纯 CSS 变量 + `@layer`。

## 一、总览

```
酒馆主页面（宿主 window）
├─ HOST.KamiRuntime ← 「🧩 运行库」脚本注册（React 18 + ReactDOM + 14 个 Radix 原语 + 组件层 + 老组件核心 + 基础样式）
├─ 面板脚本（各自跑在酒馆助手的脚本 iframe 里，DOM 画在宿主文档上）
│    30 皮肤管理 / 40 预设设置 / 50 引导 / 60 工具箱：骨架与内容页全部由 React 渲染
│    70 远程更新：只有进度窗口一处界面，React 渲染
└─ 消息 iframe（正则替换出的前端：思维链 / 行动选项 / 搜索资料）
     通过取用 shim 沿父窗口链拿到 KamiRuntime.createKamiUi
```

- 装没装上：宿主 `<html>` 上有 `data-kami-runtime="1.0.0"`。
- 运行库是普通脚本，必须**开启并排第一**。关掉后所有面板提示「运行库未加载」，消息里的行动选项等前端也无法渲染（用户裁定：默认开启，关掉是用户自己的选择）。

## 二、运行库（`src/runtime/` → `00-运行库.js`）

源码：`index.js`（入口与 API）、`ui.jsx`（Radix 组件层）、`host.js`（沿 window 链找酒馆主页面）、`ready.js`（ready / waitFor）。
`node build/build-runtime.mjs` 用 esbuild 打成 IIFE → `src/runtime/bundle.js`（约 370KB，**提交进仓库**），构建时由 `expandRuntime` 内联进 `00-运行库.js` 的 `/* @@KAMI_RUNTIME@@ */`。
基础样式（`foundation.css` + `base.css` 的令牌默认值）在打包时作为字符串注入。

> ⚠️ 改了 `src/runtime/`、`src/ui/core.js`、`src/ui/foundation.css` 或 `base.css` 的令牌后**必须重跑** `build-runtime.mjs`。`node build/build-runtime.mjs --check` 只报告是否过期。

`HOST.KamiRuntime` 的 API：

| 成员 | 用途 |
|---|---|
| `version` | 运行库版本（`1.0.0`，独立于预设版本） |
| `React` / `ReactDOM` / `createRoot` / `flushSync` | React 本体。`flushSync` 取自 `react-dom`（`react-dom/client` 里没有） |
| `UI` | Radix 组件层，见第三节 |
| `primitives` | 14 个 Radix 原语原样导出 |
| `createKamiUi` / `KAMI_UI_CSS` | 老组件核心与基础样式，见第四节 |
| `mount` / `unmount` / `createMountPoint` | 往宿主文档挂 / 卸一棵 React 树 |
| `createControl` / `makeSwitch` / `makeSelect` | 给**命令式代码**产一个 React/Radix 控件，返回 `{ el, update/setChecked/setValue, destroy }`；`update` 内部用 flushSync |
| `classProps` / `classifyTree` | 补 `data-kami-ui` 属性（见第五节第 4 条） |
| `ready(fn)` / `waitFor(timeout)` | 等运行库就绪 |
| `host` / `document` | 宿主 window 与 document |

## 三、组件层（`RT.UI`，`src/runtime/ui.jsx`）

原则：交互行为全部用 Radix，**类名仍是 `.kami-*`**，令牌仍是 `--kami-*`；Radix 只管行为与可访问性，不带任何样式。

| 类别 | 组件 |
|---|---|
| 表现层（无交互） | Dot / Badge / Chip / Title / Sub / Note / Empty / Spinner / Divider（Separator） / Grid / Scroll / Shell / Card / Field |
| 按钮 | Button / IconButton |
| Radix 交互 | TabsRoot / TabsList / Tab / TabPanel、Modal（Dialog）、Select、SwitchToggle、Collapse（Collapsible）、AccordionRoot / AccordionItem、Check（Checkbox）、Radios（RadioGroup）、Segmented（ToggleGroup）、Menu（DropdownMenu）、Pop（Popover）、Hint（Tooltip）、Bar（Progress） |
| 原生结构兼容 | NativeSwitch / NativeSelect / NativeCheck / NativeButton：迁移过渡期用来保持原生 DOM 结构，**目前脚本里已无调用** |

Radix 控件渲染出的结构（皮肤按这个写）：

- 开关 `SwitchToggle` / `makeSwitch`：`button.kami-switch[role=switch][data-state="checked|unchecked"] > span.kami-switch-thumb`
- 下拉 `Select` / `makeSelect`：触发器 `.kami-select`，弹层 `.kami-select-content.kami-drop`（portal 到宿主 `body`），选项 `.kami-select-item[data-state]`
- 页签：`.kami-tab[aria-selected="true"]`；折叠：`.kami-collapse[data-kami-open]`

## 四、老组件核心（`createKamiUi`，`src/ui/core.js`）

45 项工厂（30 基础 + 12 组合 + 3 容器，清单 `src/ui/catalog.json`，用法见 [组件库](ui-components.md)）。现在**只在运行库里有一份**，
各处通过构建期展开的取用 shim（`/* @@KAMI_UI@@ */` → `build/kami-doc.mjs` 的 `UI_SHIM`）拿到它。shim 按 `HOST` → 本窗口 → 父窗口链的顺序找运行库，
找不到就抛「运行库未加载」的人话错误。

仍在使用它的地方：三个正则前端（建节点、搜索资料整页）、`_compress-ui.js`、`_search-service.js`、`_search-manual-ui.js`、`_preset-cards.js`、`_toolbox-tabs.js`、
`_custom-style-ui.js`、`_llm-ui.js`、`_search-native-probe.js`。其中模型连接与提示词编辑器是组合组件适配器，React 面板里用**挂载点**承载
（React 排位置，老渲染器画，画完 `adoptCard` 把子节点收养进 React 容器，节点身份不变）。

core.js 的开关 / 下拉是**原生结构**：`label.kami-switch > input.kami-switch-input + span.kami-switch-track > span.kami-switch-knob`、`select.kami-select`。
所以 21 套皮肤同时保留两套规则：Radix 的 `data-state` / `-thumb` 写法（2026-10-26 提交 `80e9408` 补齐）和原生的 `.kami-switch-input:checked + …` 写法。

## 五、在面板里写 React 的套路（踩过的坑）

1. **骨架**：`createRoot(panelDrop)` + `flushSync(render)`。必须 flushSync，否则 ref 还是 null，拖拽 / 按钮拿不到节点。
2. **内容页各自一个根**：`createRoot(box)`，重画就是重新 `render`，不再 `textContent=''` 再拼。
3. **销毁**：面板关闭时统一 `unmount()`；页内容根必须跟面板生命周期一起清空（否则重开面板后 React 往已移除的容器里渲染）。
   React 页与命令式页共用容器时，切回命令式前先 `unmount()`，不能只清 DOM（否则下一次渲染 `removeChild` 报错）。
4. **渲染后补 `data-kami-ui`**：`rt.classifyTree(root)`，或建元素时用 `rt.classProps('kami-field')`。皮肤按这个属性写规则，
   漏了不报错，只是样式静默失效。映射表在 `src/runtime/index.js` 的 `KAMI_UI_OF`，与 `core.js` 的 `classify()` 逐项一致，**改一处要改两处**。
5. **运行库不可用时要有命令式兜底**：单测沙箱没有 React，骨架必须有 else 分支，否则单测全红。
6. **状态要跟着数据变的控件，直接渲染成 React 组件**。往 React 渲染出的节点里命令式塞控件时，React 会复用同一个 DOM 节点，
   `__mounted` 守卫不再触发，控件状态永远停在第一次挂载时的值。
7. **闭包状态过期**：事件里读到的是渲染那一刻的快照，需要最新值时从外部状态读。
8. 受控组件在 jsdom 测试里要用 `.click()`；直接改 `.checked` 再派发 change，React 认不出用户操作。

## 六、样式分层

皮肤管理（`30-皮肤管理.js` 的 `skinCssText`）下发到宿主的样式按这个顺序拼：

```css
@layer kami.base, kami.component, kami.skin;
@layer kami.base      { /* KAMI_UI_CSS：foundation.css + 令牌默认值 */ }
@layer kami.component { /* STRUCT_CSS：结构性兜底 */ }
/* GEOMETRY_CSS：面板几何 —— 不分层 */
/* 当前皮肤 CSS —— 不分层，永远压过分层的规则 */
/* 共享图片资源（--kami-asset-*） */
```

- **几何不进 `@layer`**（2026-10-26 真机修）：CSS 规定「分层里的 `!important` 压过不分层里的 `!important`」，几何层进了分层，就会把引导面板的全屏规则压成 78% 抽屉；
  反过来，分层里的普通声明又会输给皮肤里不分层的普通声明（`.kami-surface{position:relative}` 顶掉 `absolute`，抽屉悬空）。
- **手机贴底抽屉**只认脚本下发的 `data-kami-layout="sheet"`（`sheetMode()` 跟随酒馆自己的 ≤1000px 单栏判断），不再靠 600px 媒体查询（601–1000px 的手机会两头落空）。
  `foundation.css` 里那条 sheet 规则带 `!important` 钉死 `position` 与四边。
- **引导面板**是全屏向导，几何用**内联 `!important`** 钉死（`50-引导.js`，舞台 `100dvh`），改的时候要连 `GUIDE_CSS` 里的两条 `#id` 规则一起看。
- 消息 iframe 里的正则前端直接内联兜底样式（`baseCss()` = `uiCss()` + `base.css`），皮肤 CSS 由皮肤管理同步进各 iframe。
- 皮肤规则的写法与禁区见 [皮肤契约](皮肤契约.md)。

## 七、已知问题与技术债

1. **两套组件体系并存**：React 组件层与老 `createKamiUi` 同时在用（第四节），开关 / 下拉因此有两种 DOM 结构，皮肤要写两套规则；`KAMI_UI_OF` 映射表在两处各维护一份。
2. **原生结构兼容控件**（NativeSwitch / NativeSelect / NativeCheck / NativeButton）已无调用，可清理。
3. **面板几何靠多层 `!important` 压制**：sheet 规则、引导的内联 `!important`、皮肤里的覆盖互相角力，最近两次真机修复都是在加码；需要统一的几何方案。
4. **`.kami-card` 同时用作容器和操作按钮**，宽泛的后代选择器容易误伤嵌套组件；`data-kami-comp="panel"` 存在固定舞台坐标假设（[frontend-design](frontend-design.md) 记为「下一版处理」）。
5. **`classifyTree` 依赖手动调用**，漏调用只会静默掉样式（第五节第 4 条）。
6. **消息前端硬依赖运行库**（0.93 起）：运行库关掉或加载失败时，行动选项等无法渲染。0.92 是整份内联 core.js，没有这个依赖。
7. **`verify-runtime` 的「已迁移 N 个 / shim M 个」统计**只看脚本里还有没有 `@@KAMI_UI@@` 占位，会报「已迁移 1 个」，与「四面板已 React 化（但内部仍用到老核心）」的实际情况说法不一致，看结论时注意。
8. **单文件过大**：`40-预设设置.js` 约 4300 行，`50-引导.js`、`60-工具箱.js`、`_status-view.js` 各约 2700 行。
