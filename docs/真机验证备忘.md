## 一、部署一个新产物（两步，缺一不可）

1. 把构建产物复制进预设目录：
   D:\sillytavern-software\SillyTavern Launcher GUI\data\st_data\default-user\OpenAI Settings\
2. **必须在酒馆界面里把它选为当前预设**。只复制文件是不够的 —— 实测踩过：
   - settings.json 里的 preset_settings_openai 仍指向旧版本；
   - 更隐蔽的是 extension_settings.preset_allowed_regex.openai 里**没有新预设的名字**，
     而它决定了这个预设的正则能不能生效 —— 这一步没做，等于新产物没上。

切换路径（无头操作也可行，供 subagent 参考）：
- 打开「AI 响应配置」抽屉：顶部那排图标里 title 为 AI 响应配置 的那个（id=leftNavDrawerIcon），
  **用 browser_interact focus + press Enter**（坐标点击会被「Agent 正在控制」浮标挡住）；
- 预设下拉：#settings_preset_openai（select2 的原生 select 不可 focus），
  用 focus(下拉) + ArrowDown 若干次 + Enter 选中；
- 会弹确认框，用 Enter 通过，或 focus 确认按钮再 Enter；
- 最后硬刷新页面。

**三步里踩出来的三个细节（2026-09-18 补，修窄屏面板时实测）：**

3. **预设下拉的 `option.value` 是「序号」，不是预设名**（`public/scripts/openai.js:4226-4234`：
   `option.value = i; option.text = item;`），所以 `browser_interact select` 只能传序号。
   序号的算法要复刻服务端：`src/endpoints/settings.js:79 sortByName = (a,b) => a.localeCompare(b)`，
   作用在**带 .json 的完整文件名**上，再 `.filter(扩展名 === '.json')`。
   （核对办法：当前生效的 `settings.json → oai_settings.preset_settings_openai` 应该是那个序号对应的名字。）
4. **酒馆助手（JS-Slash-Runner）是按预设闸门放行脚本的**：`settings.json` 里
   `extension_settings.tavern_helper.script.enabled.presets` 必须**包含新预设名**，否则在该预设下
   **一个脚本都不跑** —— 症状是 🎨 按钮直接消失、控制台里连 `[皮肤] 启动` 都没有
   （很容易误判成脚本坏了）。注意这跟 `preset_allowed_regex.openai` 是**两道独立的闸门**：
   后者只决定正则，前者决定脚本。新增名字的办法：趁酒馆开着直接改 `settings.json`（用 write/edit 工具，
   别用 pwsh 内联命令），加完**马上硬刷新**；刷新后 ST 会自己把这份设置存回去，改动能留住。
5. `#leftNavDrawerIcon` / `#rightNavDrawerIcon` 是 `div`，坐标点击会被「Agent 正在控制」浮标挡住，
   而 `browser_interact action=press` 会先去 focus —— 对 `div` focus 会**静默失败**，
   Enter 于是打在上一个焦点元素上（表现：你以为开了抽屉，其实把 🎨 面板开关按了一下）。
   必须显式 `focus(<选择器>)` 看到 `focused=true`，再 `press Enter`；抽屉是 toggle，状态不明时按两次。

## 二、酒馆正则引擎的真实语义（**别再用 native 语义想当然**）

public/scripts/extensions/regex/engine.js:419-445：

    rawString.replace(findRegex, function (match) {
      const replaceString = regexScript.replaceString.replace(/{{match}}/gi, '$0');
      const replaceWithGroups = replaceString.replaceAll(/\$(\d+)|\$<([^>]+)>/g, ...);
      return substituteParams(replaceWithGroups);
    });

- 只认 $n 与 $<name>；**从不把两个连续的美元号还原成一个美元号**；
- 替换结果最后还会过一遍 substituteParams（会把 {{char}} 之类当宏吃掉）。

因此前端文档里：不得出现美元号后跟数字、不得做「美元号双写」转义、不得出现双花括号宏写法。
验证命令：node build/verify-frontends.mjs（已接进 build，不通过则 build 退出码 1）。

## 三、消息 iframe 的高度机制（别再假设它坏了）

酒馆助手注入的 iframe 里，高度只由父窗口的 ResizeObserver(body) ->
frameElement.style.height = body.scrollHeight 驱动；没有 MutationObserver、没有轮询。
iframe 内 html,body 是 overflow:hidden，所以「高度没重测」会表现为「内容看不见 / 点了没反应」。
**实测结论：这套机制是好的，前端不需要自己 syncHeight。**
（如果真要自己量，只许用 body.scrollHeight；documentElement.scrollHeight 至少等于视口高度，会让 iframe 只增不减。）
2026-09-21 补：这句话的意思是「前端**不许自己维护高度**」。**启动期那一次兜底是允许的**，
它登记在 [皮肤契约](皮肤契约.md) §9.5；行动选项前端原先自己挂的那枚 ResizeObserver 属于重复劳动，已删除。

### 4.1 真机验证的正确打开方式（2026-09-18 用户亲口确认，别再用 borrow）

**`browser_tabs borrow` 需要用户在电脑前点「同意」，用户不在电脑前就会一直超时。** 我们因此白等了两次（两个 subagent 各一次，都报 `Timed out waiting for tab borrow confirmation`）。

**正确做法：直接新开一个标签页，这不需要用户批准。**
- 用 `browser_session action=start` 带 `url=http://localhost:11451/`，或 `browser_tabs action=create`。
- 新标签页是同一个浏览器 profile，登录态与 `settings.json` 都共享，所以打开就是当前预设的真实环境。
- **不要**再对用户已有的酒馆标签页用 `borrow`（那要授权）；用完也不需要 `return`，关掉自己的标签页即可。

**顺带记住两条部署前提**（真机验收前必须满足，否则看到的还是旧的）：
1. 新产物要先**复制进 `OpenAI Settings\`**，**并在界面里切为当前预设**（两步都要）。
2. `extension_settings.tavern_helper.script.enabled.presets` 不含该预设名时，**该预设下所有脚本都不跑**（症状：🎨 / 🌟 按钮直接消失）。这是与 `preset_allowed_regex` 并列的第二道闸门。

**切预设的可靠做法**（2026-09-19 实测）：打开「AI 响应配置」抽屉（`press Enter target=#leftNavDrawerIcon`）→
`browser_inspect action=html ref=<combobox的ref>` 读 `#settings_preset_openai` 的选项列表（**option 的 value 就是序号**）→
`browser_interact action=select target=#settings_preset_openai values=["<序号>"]`。比在下拉里数着箭头往下按可靠得多。
换产物名后跑 `node test/harness/add-preset-gate.mjs kami-v<版本>-<N>-<日期>`（先备份 settings.json，脚本/正则两道名单一起加）；
**确认弹窗每个会话只问一次**，别指望它每次都弹。
**面板与按钮的一切交互走键盘路径**（focus / fill / press Enter；开面板用 `[data-hub-btn="🌟卡密预设"]`）——
坐标点击会被「中断」浮标吃掉，还会把 Agent 自己的操作打断（见 §五第 1 条）。**用户手机不受影响。**

### 4.2 2026-09-21 补的两条实操细节

**① 切预设的下拉序号要自己算，而且每加一个产物就会变。**
`#settings_preset_openai` 的 `option.value` 是序号，算法 = 把 `OpenAI Settings\` 下的文件名
**按 `localeCompare` 排序后取 `.json` 的下标**（复刻 `src/endpoints/settings.js:79`）。
`dist/` 每出一个新产物、又复制进预设目录，后面所有序号都会往后挪一位 —— **每次都要重算，别记死数字**。
一条命令算出来：

    node -e "const fs=require('fs');const d='D:/sillytavern-software/SillyTavern Launcher GUI/data/st_data/default-user/OpenAI Settings';const f=fs.readdirSync(d).filter(x=>x.toLowerCase().endsWith('.json')).sort((a,b)=>a.localeCompare(b));console.log(f.indexOf('kami-v0.90-<N>-<日期>.json'))"

流程是三步，缺一不可：**开抽屉（`focus` + `press Enter`，它是 toggle，状态不明时按两次）→ `select` 选序号 → 再 `press Enter` 过确认框**。
选完立刻读 `settings.json → oai_settings.preset_settings_openai` 核对，别靠界面判断。

**② 真机截图会长时间超时，别把截图当唯一证据。**
2026-09-21 那天 `browser_inspect action=screenshot` 连续十几次 30 秒 RPC 超时（页面楼层多、又有全屏覆盖层时最容易触发），
而同一时刻 `observe` / `html` 都正常。**结论以 DOM 取证为准**：`observe` 读结构与文案、
`browser_inspect action=html ref=@eN` 读真实标签与属性 —— 「引导里的 ⓘ 与预设面板逐属性同构」就是这么取证的。
要截图时：**先补一次 `browser_interact action=wheel`（deltaY=1）再截**，否则会拿到上一帧；
`browser_assist action=resize` 容易把会话卡死，要看窄屏请 `browser_session action=start` 时直接带 `width=375&height=812`。

## 五、已知的坑（都踩过）

1. 坐标点击会被「Agent 正在控制 / 中断」浮标挡住 -> 用 focus + press Enter。
   **比"被挡住"更严重（实测升级）**：那个浮标正好压在酒馆助手的 QR 按钮条上，点击会打到浮标上的「中断」，
   **把 Agent 自己的操作也打断掉**（浮标显示"中断中…"）。有 agent 连吃两次。
   所以真机上点 QR 按钮**一律用「键盘聚焦 + Enter」**（酒馆 `keyboard.js` 会替 `.interactable` 触发 click）。
   **用户手点不受影响**（浮标只在 Agent 控制期间存在）。
2. 截图是异步合成的，会返回上一帧 -> 结论以 observe / 预览台的 #diag 读数为准，图上不符就再截一次。
3. 本工作区写文件时反斜杠转义不可靠（例如 \s 会被吞成 s）-> 写脚本时用占位符再还原，或干脆不写反斜杠。
4. 预览台曾经"太贴心"（属性一变就重测高度），把真机里才暴露的 bug 掩盖掉了 -> 现在只保留与真机一致的 ResizeObserver(body)。
