# 前端重构 · 消息前端方案（讨论稿，2026-10-28）

> 回答用户的三个问题：正文前端要不要框、四个消息前端怎么协调（一 4），对白与心理描写的渲染（一 2），思维链 / 行动选项 / 搜索资料的形态（七）。
> 第五节 A–F 已于 2026-10-28 由用户拍板（结论见第六节），下一步出消息前端预览。

## 一、现状

| 前端 | 现在怎么渲染 | 问题 |
|---|---|---|
| 正文 | 45 号脚本在酒馆的消息 DOM 里给 `<content>` 套一层卡片外壳（标题「正文」+ 字数 + 渲染 / 原文 + 复制） | 故事正文被框起来，沉浸感打折；正文本身由酒馆的 Markdown 渲染，排版不归我们管 |
| 思维链 | 46 号脚本把思维链搬进酒馆原生思维链块，并装饰成卡片 | 展开后和正文一样醒目，抢正文的注意力 |
| 行动选项 | 正则替换成 iframe（酒馆助手渲染），卡片网格 | 每条消息一个 iframe，样式各自内联 |
| 搜索资料 | 同上，iframe，默认折叠 | 同上 |

预设对输出格式的要求（`📌 输入解析` / `📌 输出规范` 等条目）：

- 对白用全角日式引号「」包裹；
- `*星号*` 包裹的是角色的内心想法（酒馆会渲染成斜体 `<em>`）；
- 段首全角空格缩进「　　」；
- 每个步骤前有一行 `<!-- 步骤[n]/Token[m] -->` 注释；
- 指代一律写作【名称】（全角方括号）。

## 二、建议：正文也由我们渲染

把正文从「酒馆渲染 + 我们套壳」改成「我们直接渲染」（消息挂载，契约 8.3）：载荷取自聊天原始数据，自己做段落与行内排版，渲染在 Shadow DOM 里。好处：

1. **排版完全可控、分设备**：用 5.7 的阅读令牌（电脑限制行长约 42 字、行高 1.8；手机铺满、行高 1.75）。
2. **按预设格式加强渲染**（回答一 2），每一种都是皮肤可以单独设计的部件：

   | 原文 | 渲染成 | 部件钩子 | 「碎光」的默认处理（建议） |
   |---|---|---|---|
   | 「……」 | 对白 | `[data-k-part="dialogue"]` | 正文色，字重略重；引号本身用次要色 |
   | `*……*` | 心理描写 | `[data-k-part="thought"]` | 次要色 + 楷体（外链字体，失败时退回系统楷体 / 衬线） |
   | 其余文字 | 叙述 | `[data-k-part="narration"]` | 正文 |
   | 【名称】 | 专有名词 | `[data-k-part="term"]` | 极淡的强调色下划线 |
   | `<!-- 步骤… -->` | 不显示 | — | 原文视图里仍可见 |
   | 段首「　　」 | 首行缩进 | — | ~~电脑保留两字缩进；手机改用段距~~ → **电脑、手机都两字缩进**（用户拍板 C） |

3. **复制、原文视图照样有**：工具不再常驻在正文上方，电脑上悬停时淡入，手机上长按出现。

代价与风险：

- 酒馆和其他插件对 `<content>` 里内容的处理（例如别的插件给正文加的效果）不再生效；只影响 `<content>` 内部，消息的其余部分照旧。
- **流式生成**：正则要等 `</content>` 闭合才匹配，生成期间显示的是酒馆渲染的原文，结束后切成我们的排版，会有一次切换。可选做法见第五节问题 E。

## 三、四个前端怎么协调（回答一 4）

不需要「全都有框」或「全都无框」二选一。平台只规定**结构与节奏**，框不框由皮肤决定：

1. **同一条对齐轴**：四个前端左右边界一致，都受正文行长约束（电脑上不会出现正文窄、选项卡片撑满宽的情况）。
2. **同一套间距节奏**：彼此之间用 `--k-gap-group`，内部用 `--k-pad-card`，圆角用同一档。
3. **三种存在感**（平台给结构，皮肤给外观）：

   | 层级 | 前端 | 定位 |
   |---|---|---|
   | 主体 | 正文 | 阅读区，最安静 |
   | 边注 | 思维链、搜索资料 | 退后：默认收起成一行摘要（「思考了 49 字：先确认场景……」「参考了 3 个来源」） |
   | 操作 | 行动选项 | 可交互：轻量列表，按下时才有存在感 |

4. **框是皮肤的事**：每个前端都有自己的组件钩子（`msg-body` / `msg-think` / `msg-search` / `msg-options`），皮肤用部件 CSS 决定有没有框、框长什么样。
   - 「碎光」：正文无框；边注用一条左侧细线 + 次要色；选项是无框列表。
   - 喜欢卡片的皮肤：给四个都加卡片；因为对齐轴、间距、圆角是共用的，四张卡片自然协调。
   - 也可以只给正文加纸张感的底，边注保持细线。

## 四、各前端的形态（第七条）

| 前端 | 收起时 | 展开 / 交互时 |
|---|---|---|
| 思维链 | 一行：图标 + 「思考了 N 字」+ 首句摘要（截断） | 次要色、略小字号的 Markdown；渲染 / 原文 / 复制；酒馆原生的编辑 / 删除按钮保留 |
| 搜索资料 | 一行：「参考了 N 个来源」+ 来源站点名 | 编号事实列表 + 来源表 |
| 行动选项 | 直接列出选项（每项：类型小标 + 标题 + 一行内容） | 点按：电脑上悬停预览完整内容；按下即填入或发送（沿用现在的「填入 / 发送」切换）；按下时局部碎裂 |

## 五、请用户拍板的问题

- **A. 正文改由我们渲染吗？**（建议：是。不改的话，对白 / 心理描写的加强渲染只能有限地做，而且受酒馆的 Markdown 规则左右。）
- **B. 对白、心理描写、专有名词的默认处理**：上表的建议可以吗？要不要更明显一些（例如对白用强调色）？
- **C. 段首缩进**：电脑保留两字缩进、手机改用段距，可以吗？
- **D. 行动选项的位置**：留在消息末尾（现在的做法），还是只在最新一条消息出现、贴在输入框上方？
- **E. 流式生成**，三选一：
  1. 生成期间看酒馆的原文，结束后切换（最简单，有一次切换）；
  2. 生成期间就用我们的排版逐步渲染（体验最好；要在流式更新时增量挂载，工作量最大）；
  3. 生成期间显示一个轻量的「正在书写」占位，结束后一次性出现（没有切换，但看不到逐字输出）。
- **F. 思维链默认收起成一行摘要**，可以吗？

拍板后先出消息前端的预览（四个前端放在一条真实消息里，电脑 / 手机两种排版，碎光的三档配色）。

## 六、用户拍板结果（2026-10-28）

| 问题 | 结论 |
|---|---|
| A. 正文由我们渲染 | **是**（第二节方案） |
| B. 对白 / 心理描写 / 专有名词 | **按第二节表格的建议**（对白正文色略加粗、引号次要色；心理描写次要色 + 楷体；专有名词淡强调色下划线） |
| C. 段首缩进 | **电脑、手机都两字缩进**（不改段距） |
| D. 行动选项位置 | **留在消息末尾，但只有最新一条回复渲染**；旧消息里的行动选项不显示 |
| E. 流式生成 | **选 2**：生成期间就用我们的排版逐步渲染（流式更新时增量挂载） |
| F. 思维链 | **默认折叠**，收起时显示字数（第四节的「图标 + 思考了 N 字」，首句摘要不是必需） |
