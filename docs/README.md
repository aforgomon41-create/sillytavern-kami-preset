## 维护约定

- **新知识写进已有文档，不开新的散文档**（散文档最容易过期）：
  - 状态 / 待办 / 进度 → 交接.md 第〇、四节（**每次收尾都刷新第〇节**）
  - 前端架构、运行库、写法套路 → 前端技术栈.md
  - 前端与皮肤的协议 → 前端契约.md（改了要更新它的版本与变更记录）
  - 做皮肤的步骤与坑 → 皮肤制作流程.md（新系统）
  - 实机测试脚本与用法 → test/st/README.md
  - 环境、部署、真机踩坑 → 真机验证备忘.md
  - 「东西在哪、该复用谁」→ 功能复用.md
  - 用户确认过的设计 → frontend-design.md
  - 一次性的验收报告 → 验收/（文件名带日期）
- 「当前版本 / 最新正式版」这类会变的事实**只写在交接.md 第〇节**，其他文档引用它，不各自抄一份。
- 改动 `src/` 之后**不要手改 dist**：跑 `node build/build.mjs`，产物构建号自增。`dist/` 不进 git。
- 本机 `dist/` 只保留「已发布的产物 + 当前版本的构建 + 备份文件 + 台账」，清理前先跟 GitHub Releases 对一遍。
  ⚠️ 三个 `_preset.base.*` 是**备份不是构建产物**，`build-manifest.json` 是台账，**都不许删**。
- **暂停的功能两处留痕**：`src/scripts/meta.json` 的名字带「🚧 制作中」且 `enabled: false`（已进守卫断言）；相关文档加暂停横幅。
- 交付给作者时，永远写明**要下载哪个文件**。
- 文本文件一律 LF（`.gitattributes` 已钉死）；构建发现工作区有 CRLF 会提示重新检出。
