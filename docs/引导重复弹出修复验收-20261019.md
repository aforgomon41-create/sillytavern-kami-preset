# 引导重复弹出修复验收（2026-10-19）

## 结果

已修复56与62中“只有关闭或完成才保存已读、立即刷新可能丢失记录”的问题。当前为本地测试包 v0.92-66，尚未发布；公开最新版仍为62。63、64、65为中间构建，不分发。

引导面板成功显示后即记录完整版本，刷新、切换预设或同页重载不依赖是否点过关闭。展示、明确确认、完成三个状态分别保存；手动重看与重置仍可用。完成不会代替用户的明确确认。

## 保存方式

- 构建常量 SELF_NAME 提供完整版本，用户改预设名不影响判断。不同主版本即使构建号相同也不会互相误判；重新使用已经看过的版本不重复弹出。
- 脚本变量与同步本机存储互为兜底；本机记录按同源酒馆账号隔离，不使用共用匿名键。身份查询有5秒超时，脚本关闭会取消。
- 记录带单调递增的更新时间，两处记录取较新者；reset 保存明确的未展示状态，避免旧磁盘状态恢复后覆盖重置。系统时钟回退、一个存储通道暂时失效也有回归覆盖。
- 身份未知时不采用带其他已验证账号的记录，退回当前脚本作用域；不会往匿名本机键写数据。账号信息仅通过同源 /api/users/me 读取。
- 两处保存都失败时显示一次现有警告提示；浏览器清空站点数据且服务器记录也不可用时无法恢复丢失的记录。
- 安装包不再携带历史 seen=130；酒馆助手导出引导脚本时也不携带个人已读数据。保留脚本ID、seen读数和原有open/close/reset/status/shutdown接口。
- 账号读取复用新提取的 _user-scope.js，与网络搜索的密钥命名空间使用同一实现，不新增运行脚本。
