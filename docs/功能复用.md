# 功能复用与扩展点（新东西往哪加）

> 这份文档回答两个问题：**「这个功能是不是已经有一份了？」** 和 **「我要加新东西，该往哪加、加完要做什么？」**
> 它不替代 [皮肤契约](皮肤契约.md)（那是接口规范），它是**地图**：告诉你有哪些现成的零件、它们在哪、谁在用。

---

## 〇、一条硬规则

**新增任何 UI 之前，先在本文件里找现成的。找不到才新写，写完必须回本文件登记。**

为什么这条是硬规则 —— 同一枚组件被写了两遍，本项目已经因此出过**三次真机 bug**：

| 次数 | 组件 | 分叉的后果 |
|---|---|---|
| 1 | 注释标记 `ⓘ` | 引导脚本自己造了个没登记的类名，皮肤规则又锁在预设面板的 id 下 → 引导里的 ⓘ 一枚样式都吃不到，长得跟预设面板完全不一样 |
| 2 | 开关卡片高亮 | 三套皮肤的选择器少一个空格，引导里开着的卡片不亮，压缩脚本只好自己注入一段 CSS 兜底 |
| 3 | 模型卡结构 | 引导与预设面板各写一套 DOM，用户一眼看出「不一样」；改的时候还连带把条目名挤成竖排单字 |

三次的根因是同一个：**同一枚组件在两个地方各写一套**。所以现在的规矩是「一份实现，多处调用」。

## 一、共享模块（构建期内联，**不是**独立脚本）

这些文件**不在** `src/scripts/meta.json` 里、也不会各自变成酒馆助手里的一个脚本。构建时它们被整段内联进调用方。

| 模块 | 导出 | 谁在用 | 内联用的占位符 |
|---|---|---|---|
| `src/scripts/_panel-gestures.js` | `bindPanelGestures(cfg)` | 皮肤管理面板、预设设置面板（压缩面板与引导面板按需） | `/* @@KAMI_PANEL_GESTURES@@ */` |
| `src/scripts/_preset-cards.js` | `buildModelCard` / `buildItemsGrid` / `buildItemCard` / `noteMarkEl` / `noteBoxEl` | 预设设置面板（模型 tab）、引导面板（模型页） | `/* @@KAMI_PRESET_CARDS@@ */` |
| `test/harness/preset-parse.mjs` | `parsePreset()` 等 | 预设设置面板、引导面板（运行时解析当前预设） | `/* @@KAMI_PRESET_PARSE@@ */` |
| `src/skin/base.css` | 兜底皮肤整份 CSS | 皮肤管理没跑时，所有面板与前端都吃它 | `/* @@KAMI_BASE_CSS_JS@@ */` |
| `src/decor/d20.js` | `window.KamiD20 = { mount, destroy }` | 皮肤管理脚本按皮肤声明注入 | `/* @@KAMI_DECOR_D20@@ */` |

**内联机制**：`build/kami-doc.mjs` 里的 `expand*` 系列函数（`expandPanelGestures` / `expandPresetCards` / `expandPresetParse` / `expandBaseCssJs` / `expandDecor` / `expandGuideCopy` / `expandRegexList`）。
注意 `expandPanelGestures` 内部会先跑一遍 `expandPresetCards`（幂等空操作），所以老脚本不用改。

**新增一个共享模块要动三处**：
1. 写 `src/scripts/_<名字>.js`，函数用 `export function`（内联时会去掉行首 `export `）；
2. 在 `build/kami-doc.mjs` 加 `expand<名字>()`，并挂进 `expandPanelGestures`（或让 `build.mjs` / `server.mjs` 显式调用它）；
3. **调用方源码里留占位注释**，并且 **`test/harness/index.html` 的 `loadGuide()` 也要补一行手动展开** —— harness 不走 `kami-doc.mjs`，漏了就是「脚本能启动但功能全空」的假象。

> ⚠️ 模块源码里**不许出现占位符字面量**（哪怕写在注释里）：二次展开会自我复制。`kami-doc.mjs` 里有硬检查会拦住。

## 二、面板骨架（四块面板共用一套）

现有四块面板：🎨 皮肤管理（`30-皮肤管理.js`）、🌟 预设设置（`40-预设设置.js`）、🧭 引导（`50-引导.js`）、📜 压缩（`60-压缩.js`）。

**要新加一块面板，照 `40-预设设置.js` 抄**（它是最完整的一份），骨架是契约 §4.4 的那套：

- 根：`.kami-root[data-kami-comp="panel"]`（脚本保证它是铺满视口的舞台）+ 自己的面板 id + `z-index: 30000`；
- 面板本体：`.kami-drop.kami-surface`，位置尺寸走四个令牌 `--kami-panel-x/-y/-w/-h`；
- 三段：`.kami-head`（标题 + 动作区）/ `.kami-tabs` + `.kami-body.kami-scroll` / `.kami-foot`；
- 缩放把手：`.kami-resize[data-kami-act="resize"]`；
- 窄屏必须变成**贴底抽屉**（跟随酒馆自己的单栏状态，`data-kami-layout="sheet"`）；
- 手势：`bindPanelGestures({ root, handle, pane, tabs, isSheet, onClose, onStep })`；
- 注销：面板 DOM、注入的样式、按钮登记、全局 API、监听器、定时器**全部收回**（契约 §6）。

**面板里的排版规则一律不得挂面板 id**（契约 §4.4 硬规则）—— 组件长什么样只写到 `.kami-root[data-kami-comp="panel"]` 这一层。

## 三、组件级复用（DOM 契约）

| 要做的组件 | 用现成的这个 | 关键属性 / 类名 |
|---|---|---|
| 条目卡（整卡即开关） | `buildItemCard()` | `button.kami-item.kami-card` + `.is-on` + `aria-pressed` + `data-kami-item`；有注释时外面包 `.kami-item-note` |
| 卡片角标（emoji） | `buildItemCard()` 内建 | `.kami-badge[data-kami-corner="tl\|tr\|bl\|br"]`（最多 4 枚，只占高度不占宽度） |
| 注释标记 `ⓘ` | `noteMarkEl()` | `span.kami-card-note[data-kami-note-mark]` + `role=button` + `tabindex=0` + `aria-expanded`；**Enter 与 Space 都要认**，点击必须 `stopPropagation()` |
| 注释正文容器 | `noteBoxEl()` | `div.kami-card-note[data-kami-note]`，靠 `hidden` 属性切换，**始终留在 DOM** |
| 模型卡（一个模型一张卡） | `buildModelCard()` | `div.kami-card[data-kami-card-key]` + 卡头 `button.kami-card-head.kami-btn.kami-btn--ghost[data-kami-model]` + 卡内 `.kami-card-body > .kami-grid` |
| 折叠区 | 契约 §4.3 的写法 | `.kami-collapse[data-kami-open="0\|1"]` + `.kami-head.kami-collapse-head`；**折叠体始终在 DOM，只切属性**，显隐与动画全归皮肤 |
| 分段切换 | `.kami-seg` / `.kami-seg-item` | 选中加 `.is-on` |
| 设置项一行 | `.kami-field` / `.kami-field-label` / `.kami-field-value` | **四类控件各归各类**（契约 §4.2）：数字框 `.kami-number`（只有它右对齐）／单行文本 `.kami-text`／多行 `.kami-textarea`／下拉 `.kami-select`。别再让文本或下拉借用 `.kami-number` —— 那条 `text-align:right` 会被它们一起吃掉 |
| 开关 | `.kami-switch` 系列 | `input.kami-switch-input` + `.kami-switch-track` + `.kami-switch-knob` |
| 进度点（分步界面） | `.kami-dots` + 子元素 `.kami-dot` | 当前页 `[data-kami-on="1"]` |
| 浮动层 | `.kami-drop` | `[data-kami-open="1"]` |

**按钮登记**：任何脚本都**不自己向酒馆助手注册按钮**，而是往中转站登记：
`HOST.__hubDefs.push({ name, order, tip, label, get, ready, click, absent })`，或 `window.__hub.register({...})`。
登记名之间**不许互为前缀**（中转站有 `nameConflicts()` 自检，前缀包含会串台）。

## 四、三条流水线

### 1. 文案（风格性文案**只从表里来**）

| 内容 | 真相来源 | 落地 | 校验 |
|---|---|---|---|
| 皮肤的 tagline / 三个槽位标题 / effects 与 params 的措辞 | `design/copy/copy-table.json` | `node build/apply-copy.mjs` | `node build/lint-copy.mjs` |
| 预设条目与卡片的注释（`{{//}}`） | `design/copy/comment-updates.json` | `node build/apply-comments.mjs` | `node build/check-copy-updates.mjs` |
| 引导面板的 35 个键 | `design/copy/guide-copy.json` | 构建期内联（`expandGuideCopy`） | 同上 |

- **落地脚本绝不重打文案，只读表**；改文案 = 改表 → 跑脚本，不许手改 `src/preset.base.json`。
- 措辞一律交**专职文案 subagent**（Gemini 系列），实现类 subagent 不写文案。
- 字数与禁用字符限制见 `lint-copy.mjs`（label ≤8 格、desc ≤60 格、group ≤4 格、unit ≤2 格；不许出现美元号 / 反斜杠 / 分号 / 花括号 / 引号 / 换行）。
- ⚠️ `params[].unit` **会被直接拼进 CSS 值**，必须是合法 CSS 单位或空串 —— 写 `×` 或 `°` 会让整条声明被丢弃。

### 2. 皮肤

加一套皮肤 = 建 `src/skins/<id>/`（`skin.json` + `skin.css`）→ **三处 `SKIN_IDS` 硬编码数组要同步加**（`build/apply-copy.mjs`、`build/lint-copy.mjs`，以及文案表四节）→ `node build/lint-skins.mjs <id>` 必须 PASS。
默认皮肤在 `src/scripts/30-皮肤管理.js` 的 `PREFERRED`。
**新皮肤零维护的地方**：皮肤管理面板与引导面板的皮肤预览、皮肤列表，都是运行时读 `src/skins/`。

### 3. 构建与校验

```
node build/build.mjs          # 装配 → 展开所有占位符 → 跑 verify-frontends → 出 dist/卡密预设v0.09-<N>-<日期>.json
node build/lint-skins.mjs     # 皮肤包校验（含作用域前缀硬规则、令牌全集、decor 字段）
node build/lint-copy.mjs      # 文案表校验
node build/verify-frontends.mjs  # 按酒馆真实正则语义重放两个前端
node test/harness/server.mjs --port 87xx   # 预览台（实时读 src/，改完刷新即可，不用构建）
```

**部署是两步**：复制产物到 `OpenAI Settings\` **之后必须在界面里把它选为当前预设**，再跑 `node test/harness/add-preset-gate.mjs 卡密预设0.9-<N>`（两道放行名单）。细节见 [真机验证备忘](真机验证备忘.md) 第一节。

## 五、扩展检查清单

**加一块面板**：抄 40 的骨架 → 用契约类名（不新造）→ 手势接入 → 注销零残留 → 按钮往中转站登记（名字不与他人互为前缀）→ 契约 §4.4 若有新类名先登记。

**加一个前端**：DOM 只写结构与类名，**不写任何 color/background/border/font/尺寸/动画**（契约 §0）→ 风格性文案走 `data-kami-label` 属性 → 进 `src/regex/list.json` → `verify-frontends.mjs` 必须过（不许出现美元号后跟数字、不许双写美元号、不许出现双花括号宏）。

**加一个装饰模块**：`src/decor/<id>.js`（独立 IIFE，暴露 `window.Kami<Name> = { mount, destroy }`）→ 在 `build/kami-doc.mjs` 登记内联占位 → 皮肤管理里加 `syncDecor` 分支 → 前端留空槽 `span.kami-deco[data-kami-deco="<id>"]` → 回契约 §8 登记类名。

**加一条风格性文案**：前端加一个 `data-kami-label="<slot>"` 属性即可，皮肤写 `--kami-label-<slot>` 就能覆盖，**两边都不用改契约**（槽位命名法见契约 §3.7）。功能性文案（空态 / 字数 / 项数 / 示例 / 已填入 / 未发送…）**写死在前端**，皮肤不许覆盖（禁用令牌清单见契约 §3.7）。

## 六、别重复造的东西（容易被顺手重写一遍）

- **面板骨架与手势**：别在第四块面板里再写一套 pointer 逻辑。
- **卡片与注释标记的 DOM**：一律走 `_preset-cards.js`。
- **预设解析**：别自己写第二套解析器，用 `test/harness/preset-parse.mjs`（40/50 已经内联它）。
- **写预设**：只有一条安全通道 —— 改活的 `chatCompletionSettings.prompts[i].content`，然后点酒馆界面上的 `#update_oai_preset` 按钮。**不许**用 `getPresetManager('openai').savePreset(名字)`（会把预设写成空对象）。细节见 [交接](交接.md) 第五节第 11 条。
- **往用户机器里写一个预设文件**（例如远程更新拉下来的）：用酒馆助手的 `importRawPreset(预设名, 文件文本)`，它等于界面上的「导入预设」，文件原样落进 `OpenAI Settings\` 还会刷新下拉框；`70-远程更新.js` 的 `writePreset()` 是现成实现（含拿不到该函数时的退回路）。**不许**用 `replacePreset` / `updatePresetWith` / `setPreset`（格式转换有损）。细节见交接 §五第 29 条。
- **酒馆原生弹窗**：`callGenericPopup` 不在 `getContext()` 里，脚本要用原生弹窗就走 `triggerSlash('/popup …')`；`70-远程更新.js` 的 `askUpdate()` + `escText()` 是现成实现（按钮文案、`result=true` 取回执、更新说明的可滚动区、斜杠命令的字符净化都写好了）。细节见交接 §五第 30 条。
- **输入框对比度**：皮肤里那几条 `input.kami-number` / `input.kami-text` / `textarea.kami-textarea` / `select.kami-select` 的 `!important` 规则是为了压过用户酒馆的自定义 CSS（它对 select 与 textarea 各有一条深漆），别以为是冗余删掉。写 `background-color` 而不是 `background` 简写 —— 简写会把 `.kami-select` 自绘箭头的 `background-image` 重置掉。
- **面板几何**：位置尺寸一律走四个令牌，别自己写 `left/top/width/height`。
