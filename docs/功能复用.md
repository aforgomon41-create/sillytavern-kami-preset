# 功能复用与扩展点（新东西往哪加）

> 这份文档回答两个问题：**「这个功能是不是已经有一份了？」** 和 **「我要加新东西，该往哪加、加完要做什么？」**
> 它不替代 [皮肤契约](皮肤契约.md)（那是接口规范），它是**地图**：告诉你有哪些现成的零件、它们在哪、谁在用。

---

## 〇、一条硬规则

**新增任何 UI 之前，先在本文件里找现成的。找不到才新写，写完必须回本文件登记。**

为什么这条是硬规则 —— 同一枚组件被写了两遍，本项目已经因此出过**三次真机 bug**：

  次数   组件   分叉的后果  
 --- --- --- 
  1   注释标记 `ⓘ`   引导脚本自己造了个没登记的类名，皮肤规则又锁在预设面板的 id 下 → 引导里的 ⓘ 一枚样式都吃不到，长得跟预设面板完全不一样  
  2   开关卡片高亮   三套皮肤的选择器少一个空格，引导里开着的卡片不亮，压缩脚本只好自己注入一段 CSS 兜底  
  3   模型卡结构   引导与预设面板各写一套 DOM，用户一眼看出「不一样」；改的时候还连带把条目名挤成竖排单字  

三次的根因是同一个：**同一枚组件在两个地方各写一套**。所以现在的规矩是「一份实现，多处调用」。

## 共享组件入口（2026-10-19）

更新、继承与脚本整理的设置快照共用 `src/scripts/_preset-snapshot.js`。`snapshotCompletionPreset(live, stored)` 保留缓存扩展并把酒馆8个内部字段转为预设字段；`completionPresetForLive(raw, live)` 供继承交回面板写活设置。不要再直接把 `chatCompletionSettings` 当成预设文件保存，温度等字段名不同。备份使用70号 `writePreset(..., true)` 的后台保存通道，不得导入备份触发切换。完整首跳边界见 [更新循环验收](验收/更新循环修复验收-20261019.md)。

> 2026-10-27：组件的现状（React + Radix 组件层 `RT.UI` 与老组件核心 `createKamiUi` 并存、各自用在哪）以 [前端技术栈](前端技术栈.md) 为准；本节下面是老组件核心的用法。

新增界面先用 [共享组件库](ui-components.md)。实现位于 `src/ui/core.js`，0.93 起由「🧩 运行库」提供唯一一份，脚本里留 `/* @@KAMI_UI@@ */` 占位、构建期展开成取用 shim，调用 `createKamiUi(document)`；同一文档只创建一个实例，不增加脚本项。基础样式 `src/ui/foundation.css` 合并进既有 `baseCss()`，皮肤启用后仍有效。

模型连接和提示词直接复用 `ui.modelConnection({render:renderKamiLlmModel,env})`、`ui.promptEditor({render:renderKamiLlmPrompts,env})`。业务控制器继续使用 `_llm-settings.js`，不复制配置保存或请求流程。预设条目继续用 `_preset-cards.js`；既有面板拖拽仍共用 `_panel-gestures.js`。新增承载容器直接用 `ui.panel` 或 `ui.dialog`。

皮肤契约校验统一复用 `build/skin-contract.mjs`：元数据、作用域、根令牌和导航规则由 `lint-skins` 与组件检查共用，负例为 `test/harness/skin-contract.mjs`，禁止另抄一套判断。

离线检查：`node test/harness/ui-components.mjs`；浏览器检查：启动预览台后运行 `ui-components-browser.mjs` 与 `toolbox-browser.mjs`，通过 `KAMI_PREVIEW_ORIGIN` 指定地址。工具箱检查模拟模型和搜索，不消耗服务额度。

（改之前是客户端手抄一份展开清单，同一个漏补栽过两次：2026-09-30 漏 `_preset-cards.js` / `_tags-pure.js`，
2026-10-03 漏 `_custom-style-ui.js` —— 后者直接导致真机上写作指导页的自带文风被整片抹掉。
  `devScript()` 现在对残留占位做收口断言，展开不全就**发一段会抛的 JS**，把真实原因打到控制台，不再静默。）

**新增一个共享模块要动三处**：
1. 写 `src/scripts/_<名字>.js`，函数用 `export function`（内联时会去掉行首 `export `）；
2. 在 `build/kami-doc.mjs` 加 `expand<名字>()`，并挂进 `expandPanelGestures`（或让 `build.mjs` / `server.mjs` 显式调用它）；
3. **调用方源码里留占位注释**即可。**预览台不用再手补展开**（见上：`index.html` 各分支已统一走 `/dev/` 出口，
   由 `server.mjs` 用同一份 `expandPanelGestures()` 展开；`preview.html` 的 `loadScript()` 里还有 `assertDevExpanded()` 兜底）。
   ⚠️ **服务端展开器改了必须重启 harness server**：Node 启动时就把 `kami-doc.mjs` 读进内存了，改代码不重启等于没改。

> ⚠️ 模块源码里**不许出现占位符字面量**（哪怕写在注释里）：二次展开会自我复制。`kami-doc.mjs` 里有硬检查会拦住。

## 二、面板骨架（四块面板共用一套）

现有四块面板：🎨 皮肤管理（`30-皮肤管理.js`）、🌟 预设设置（`40-预设设置.js`）、🧭 引导（`50-引导.js`）、📜 压缩（`60-工具箱.js`）。

**要新加一块面板，照 `40-预设设置.js` 抄**（它是最完整的一份），骨架是契约 §4.4 的那套：

- 根：`.kami-root[data-kami-comp="panel"]`（脚本保证它是铺满视口的舞台）+ 自己的面板 id + `z-index: 30000`；
- 面板本体：`.kami-drop.kami-surface`，位置尺寸走四个令牌 `--kami-panel-x/-y/-w/-h`；
- 三段：`.kami-head`（标题 + 动作区）/ `.kami-tabs` + `.kami-body.kami-scroll` / `.kami-foot`；
- 缩放把手：`.kami-resize[data-kami-act="resize"]`；
- 窄屏必须变成**贴底抽屉**（跟随酒馆自己的单栏状态，`data-kami-layout="sheet"`）；
- 手势：`bindPanelGestures({ root, handle, pane, tabs, isSheet, onClose, onStep })`；
- 注销：面板 DOM、注入的样式、按钮登记、全局 API、监听器、定时器**全部收回**（契约 §6）。

**面板里的排版规则一律不得挂面板 id**（契约 §4.4 硬规则）—— 组件长什么样只写到 `.kami-root[data-kami-comp="panel"]` 这一层。

- 措辞一律交**专职文案 subagent**（Gemini 系列），实现类 subagent 不写文案。

- ⚠️ `params[].unit` **会被直接拼进 CSS 值**，必须是合法 CSS 单位或空串 —— 写 `×` 或 `°` 会让整条声明被丢弃。

### 2. 皮肤

加一套皮肤 = 建 `src/skins/<id>/`（`skin.json` + `skin.css`），补齐文案表；构建、同步、文案与皮肤校验自动发现目录，不再维护 `SKIN_IDS`。当前要求见 [皮肤契约 v0.3](皮肤契约.md)。
默认皮肤在 `src/scripts/30-皮肤管理.js` 的 `PREFERRED`。
**新皮肤零维护的地方**：皮肤管理面板与引导面板的皮肤预览、皮肤列表，都是运行时读 `src/skins/`。

### 3. 构建与校验

```
node build/build.mjs          # 装配 → 展开所有占位符 → 跑 verify-frontends → 出 dist/kami-v<版本>-<N>-<日期>.json
node build/lint-skins.mjs     # 皮肤包校验（含作用域前缀硬规则、令牌全集、decor 字段）

node test/harness/server.mjs --port 87xx   # 预览台（实时读 src/，改完刷新即可，不用构建）
```

**部署是两步**：复制产物到 `OpenAI Settings\` **之后必须在界面里把它选为当前预设**，再跑 `node test/harness/add-preset-gate.mjs kami-v0.90-<N>-<日期>`（两道放行名单）。细节见 [真机验证备忘](真机验证备忘.md) 第一节。

## 五、扩展检查清单

**加一块面板**：抄 40 的骨架 → 用契约类名（不新造）→ 手势接入 → 注销零残留 → 按钮往中转站登记（名字不与他人互为前缀）→ 契约 §4.4 若有新类名先登记。

**加一个前端**：DOM 只写结构与类名，**不写任何 color/background/border/font/尺寸/动画**（契约 §0）→ 风格性文案走 `data-kami-label` 属性 → 进 `src/regex/list.json` → `verify-frontends.mjs` 必须过（不许出现美元号后跟数字、不许双写美元号、不许出现双花括号宏）。

**加一个装饰模块**：`src/decor/<id>.js`（独立 IIFE，暴露 `window.Kami<Name> = { mount, destroy }`）→ 在 `build/kami-doc.mjs` 登记内联占位 → 皮肤管理里加 `syncDecor` 分支 → 前端留空槽 `span.kami-deco[data-kami-deco="<id>"]` → 回契约 §8 登记类名。

**加一条风格性文案**：前端加一个 `data-kami-label="<slot>"` 属性即可，皮肤写 `--kami-label-<slot>` 就能覆盖，**两边都不用改契约**（槽位命名法见契约 §3.7）。功能性文案（空态 / 字数 / 项数 / 示例 / 已填入 / 未发送…）**写死在前端**，皮肤不许覆盖（禁用令牌清单见契约 §3.7）。

## 六、别重复造的东西（容易被顺手重写一遍）

- **面板骨架与手势**：别在第四块面板里再写一套 pointer 逻辑。
