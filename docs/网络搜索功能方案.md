# 网络搜索功能

用户已批准功能规则，并明确通过工具箱预览。2026-10-18已在11451的独立测试角色/新聊天使用真实Tavily与模型验收，并修复实机发现的问题；其他供应商没有有效密钥，未声称真实联网通过。本轮未发布。详见[实机验收报告](../.audit/网络搜索实机验收-20261018.md)。

## 入口与模式

工具箱共一个按钮，页签顺序为“压缩、网络搜索、其他功能”。搜索默认关闭，按聊天需要开启。设置保存在原工具箱脚本变量中，独立于压缩配置。

头部任务区提供“🌐 网络搜索”条目，开关和完整内容分别与工具箱的能力开关、“头部任务内容”双向同步。原生条目编辑、工具箱编辑和刷新保存复用既有预设读写与通知。旧预设已开启搜索时迁移条目，保留其自定义内容；原先关闭且没有条目时不主动插入。默认任务以`{{//注释}}`说明用途，用`<web_search_task>`包裹，给出分类、固定字段、输出格式、设定优先级和增量规则；已删除空的Gemini思维链占位条目及全部顺序引用。

- 模型自带：只提供能力开关；正常生成时由剧情模型决定是否搜索，不增加独立搜索模型调用，不提供手动入口。
- 搜索服务：当前14个选项，包括Firecrawl免Key及密钥模式、Tavily、SerpApi、Bing、维基百科、SearXNG、KoboldCpp、Serper、Z.AI、DeepSeek、TinyFish、Exa、Serping。尚未选择供应商时默认Firecrawl免Key，已有选择保留；这不会开启搜索或改变原生/服务模式。开启后同时具备自动搜索与手动查询。密钥按渠道保存在酒馆服务端或按账号隔离的本机浏览器，不写入脚本变量、聊天或导出预设；详见[配置与Key入口](搜索服务Key获取.md)。
- 世界、版本与时间由模型根据上下文识别。用户设定、角色卡、世界书与已确认剧情优先；网络只补缺，不覆盖自定义设定，不把隐藏秘密和未来剧情变成角色记忆。

当前酒馆原生搜索路径包括 Gemini/Vertex、OpenRouter、ElectronHub、NanoGPT，以及酒馆已接入的 Claude 型号。连接识别仅检查酒馆接口类型，不代表每个模型/代理都具备联网能力，也不执行付费能力测试。当前酒馆的直连 OpenAI/custom 路径未统一接入原生搜索，可使用搜索服务。

Gemini 原生搜索与反截断的正文工具不兼容，开启原生搜索时该轮优先使用搜索。后台搜索请求不会被反截断脚本改成正文工具请求。

### 真实搜索能力测试（2026-10-19）

“模型联网能力”卡中的“测试真实搜索”会使用当前剧情连接发送一个独立的公开信息查询。不是模型名单判断；没有预设条目、角色、世界书、聊天历史或已保存搜索资料。请求在最终发送前再次收口为两条固定提示；不修改聊天或设置，不创建楼层。

复用酒馆助手 generateRaw 的静默、独立生成编号和连接队列。实际4.11.3调用约定已对照源码：助手保持非流式JSON读法，公共响应管线仅将该次上游请求改为流式，完整读出原始元数据后返回短JSON回执，避免酒馆本地stream常量与响应形态冲突。与普通剧情请求及其他接口流隔离；不复制fetch补丁，不克隆整条响应。

判断依赖提供方结构化字段：
- Gemini：非空的 groundingMetadata.webSearchQueries，结合 groundingChunks 的网页来源。
- Claude：匹配的 server_tool_use / web_search_tool_result，或 usage.server_tool_use.web_search_requests；工具错误单独处理。
- OpenRouter及兼容响应：搜索调用计数，结合结构化引用；普通文字、模型自述、单独URL或引用不能证明执行搜索。

结果分为“已验证搜索成功”“已执行搜索，未返回可核实资料”“无法验证”“测试失败”。HTTP200不代表搜索成功。超时、格式损坏、提前断流与工具报错不伪装成成功。执行记录不证明每条事实正确，也不能鉴别代理是否伪造服务端记录；元数据被代理删除时诚实显示无法验证。

测试有实际模型和搜索费用，只主动点击才运行；不在开面板或切模型时自动发送。显示真实请求/核验阶段，不使用虚构百分比。中断、超时、切聊天、关闭能力或脚本会停止请求，排队调用也要在实际运行前重新校验。连接来源、模型、地址等变化使内存结果失效，旧结果不写入变量、聊天或预设。

自动剧情原生搜索仍按酒馆已接入路径工作，本测试不为不支持的后端擅自加插件或改服务设置。协议与生命周期检查见 test/harness/native-search.mjs，实际工具箱浏览器交互见 native-search-browser.mjs；模拟响应不能宣称供应商实网通过。

## 请求、费用与楼层

服务模式自动搜索采用前置资料请求：正常剧情发送前，搜索模型读取非预设上下文，判断是否需要查询；需要时调用服务，再由搜索模型结合设定、正则处理后的历史、证据和已有事实提取增量。资料注入当前剧情请求，最终由脚本写入同一个 AI 剧情楼层。

这是为满足“不创建中间工具楼层”采用的兼容路径：酒馆标准工具调用会保存额外工具楼层，无法直接复用它实现同样效果。服务模式每轮通常额外增加一次判断请求；实际检索时还增加一次提取请求和按用户查询上限执行的服务请求，自动默认最多两次。因此会增加等待和费用，页面已说明。关闭开关后不再增加这些调用。同一用户楼层的重生成可在五分钟内复用资料，继续生成会重新判断；修改自动限额会清除旧缓存。来源已达到上限时提前结束后续查询。

手动查询使用同一资料流程，成功时只新增一个独立资料楼层，不创建用户楼层、不续写剧情。未检索或未发现资料时显示真实状态，不伪造成功资料。搜索进行中可取消；切聊天、停止生成、关闭脚本、修改配置和超时都会使旧任务失效。

手动搜索按钮位于页首，与压缩操作同位置；“手动搜索设置”默认折叠，内含可选消息栏快捷按钮、手动限额、独立模型卡、独立提示词模板。两个入口打开同一弹窗，先填写本次要求，再确认搜索；弹窗顶部突出当前阶段和查询数量，四个步骤区分已完成/进行中/等待/跳过，底部提供醒目的中断操作，关闭或Escape也中断。没有总耗时依据，不显示百分比。快捷按钮默认关闭，关闭开关时直接调用既有中转站的unregister并使旧定义失活，立即撤下；搜索能力关闭或切至模型自带也撤下，保留用户偏好，恢复服务模式后可重新出现。

压缩与搜索共用既有连接处理，互相避让，避免同时临时切换连接。后台调用使用独立生成编号和静默模式，不占用剧情的停止按钮。

## 搜索模型上下文与配置

复用酒馆助手 generateRaw 的明确内置提示词列表：世界书、用户身份、角色说明/性格/场景、对话示例、经酒馆正则处理后的有效历史。当前摘要在酒馆没有将其包含到历史中时补入。不发送剧情预设条目，不直接用全部原文覆盖历史。

自动搜索始终跟随当前剧情连接和网络搜索头部任务。手动搜索单独选择当前连接、已有酒馆连接，或保存独立自定义接口；模型列表请求与连接恢复复用原实现。模型卡及提示词模板与压缩共用渲染、配置写回控制器，数据独立；手动编辑不改压缩和自动任务。旧搜索连接迁移到手动设置，自定义连接只复制一次，不共享压缩的可变配置。独立提示词支持模板、头部/任务/尾部及条目角色，与摘要提示词相同。最终阶段格式约束位于自定义尾部之后，保证输出可解析。

第二次提取也读取同一份非预设上下文，才能排除与角色卡、世界书、自定义剧情冲突的原作内容及未来剧透；会增加这次独立请求的输入用量，不会把整份网页或额外上下文保存进聊天。网页片段仅作为不可信资料，系统提示词要求忽略网页中的指令。

独立调用通过本任务专用标记识别。部分酒馆助手的 generateRaw 发出 normal 类型事件，另一些版本使用 quiet；两者都不能误触发自动搜索或反截断正文工具。过期任务标记直接拒绝。

任务分类由LLM识别，不增加用户分类选项。头部条目与手动默认提示词共用`webSearchTaskGuide()`：人物全貌按身份、外貌、性格动机、背景、能力限制、关系、言行检索；世界观、地点、规则或物品、事件、事实核对各有固定字段，综合任务按类别分组。仅补某个方面时选“细节补充”，按目标细节、具体设定、限制/版本差异整理，不展开整份人物档案。内部计划含task_type/target/focus并传给提取阶段；最终仍只保存“对象·字段：资料”的短事实与引用，缺失字段不编造或凑数。旧手动模板也会在后台调用收到分类规则，不覆盖用户自定义模板。

## 保存结构与展示

三条路径使用同一标签；自动搜索置于剧情回复已有 introduction 内，手动楼层只含此包装：

```xml
<introduction>
<search_results>
范围：识别的世界｜适用版本与剧情时间
- 对象·字段：新增或更正的事实，必要限制直接写在本句。[1]
[1] https://example.org/reference
</search_results>
</introduction>
```

持久化只保留范围、事实和被引用的来源URL，不保存查询词、时间戳、JSON键名、重复标题或检索日志。必要的限制和修正写在事实句中。原生搜索用“范围（原生）：”首行标明来源由模型提供。旧JSON继续读取和展示，不批量改写用户历史。独立助手在内部判断及提取时仍用短JSON协议，与最终保存格式分开。

服务结果仅保留引用实际返回来源的事实。自动默认8条事实、3个来源、2个查询、1200 token保存预算，任务超时120秒；手动默认20条较详细资料、8个来源、4个查询、4000 token保存预算，任务超时180秒。两套可独立设置：查询1–10个、来源1–20个、资料1–60条、token预算100–16000。数值均为上限，实际结果可以更少；token预算仅限制最终保存的资料，不含搜索模型读取上下文的用量。

任务启动时复制本套限额，贯穿查询计划、来源选择、事实数量和token核对；修改本套设置取消正在执行的本套任务，另一套设置不受影响。每条事实自动最多700字符、手动最多1000字符。独立请求的默认输出上限自动4096、手动8192 token；保存预算提高时，输出上限可随之扩展为“保存预算+2048”，用户原上限更低则不提高。使用低思考档，只改独立请求，不改剧情设置。供应商可能忽略思考参数或按模型名固定强度。可得上下文上限时，额外核算资料及输出预算，余量不足则不挤掉原历史。同轮未执行有效检索时，不保存剧情模型自行生成的成功搜索块。新格式支持最多60条/20来源，前端不截回旧上限。

原生模式使用自动限额，实际查询次数仅通过提示约束；保存新资料时仍核对事实/来源数量和token预算。计数失败或任务停止时清理本轮未核验的新块，保留剧情与之前的增量；异步计数迟到不能重新写回，双结束事件不重复保存。当前酒馆没有统一暴露原生搜索工具记录，无法保证模型提供的来源确实被访问过，不能强制供应商内部调用预算。资料卡继续标为“模型原生搜索 · 来源由模型提供”；长度核验不等于事实和来源访问核验。联网与引用不能保证事实无误。

展示复用现有折叠信息卡及21套皮肤。正文通过文本节点渲染，来源只接受无用户名密码的 HTTP(S) 链接。常量 iframe 从自己对应的聊天楼层读取资料，不把捕获到的原文拼入脚本，避免资料内容破坏文档。继续生成会保留原楼已有资料，再追加新的增量记录；连续记录合并显示在一张卡中。

继续生成若追加另一套完整 out_body，由40号共用回复处理合并中间的外层边界；不改内部文字、资料或增量区块。仅处理当前继续生成对应的新回复，不扫描改写历史聊天；代码示例、HTML卡片、注释中的标签以及不完整或嵌套外壳不猜测处理。这项格式处理不依赖搜索开关。

## 压缩与增量

滚动压缩只保留完整的 summary、char_setting、search_results 块，无论它们是否连续；去掉 introduction 外层、思考和正文。没有这三类标签时不保留内容。HTML 的 summary 与原有规则一样按标签名识别，本轮不改其历史语义。

超限压缩照旧允许概括搜索资料，并隐藏被概括的旧楼层，不额外转存或强制逐字保留来源。

搜索先参考已有事实，模型只提取新增/修正项，程序再去除文字完全相同的事实。更正通过新记录说明差异，不重写旧楼层。语义相同但措辞不同的去重依赖模型，不能声称完全消除重复；长期增长继续由超限压缩管理。

## 代码复用与脚本目录

原60号压缩脚本改名为 60-工具箱.js，脚本 ID、KamiSummarize 接口、压缩配置和世界书账本保持兼容，另提供 KamiToolbox 导航接口。压缩界面、其他功能界面、工具箱导航、搜索服务与纯数据规则分别提取为源码模块，构建时内联，运行脚本仍为12个。

`_llm-ui.js`、`_llm-settings.js` 共用两页的模型/模板编辑，`_search-manual-ui.js` 提供手动查询弹窗与按钮生命周期。原按钮中转站不增加硬编码，复用已有心跳，不新增轮询定时器；停用脚本会撤下快捷按钮和弹窗。

助手页面使用原生一级文件夹：基础与外观 / 功能与设置 / 开发中。三个开发中脚本仍默认关闭。构建、预览、更新合并和检查共用脚本树工具：更新新版代码时保留叶子脚本的启用状态与用户数据，保留用户自加脚本/文件夹；官方脚本采用新版归属，可能留下空的自建文件夹。移出已关闭文件夹的脚本保持关闭，避免更新后意外启动。

## 供应商扩展（2026-10-17）

沿用工具箱现有连接卡，不新增运行脚本。统一目录和适配位于 `_search-providers.js`，服务、UI、请求与检查共用。现在支持7种：

|---|---|---|
| Tavily | 每月1000免费credits，basic每次1credit；需密钥 | 酒馆原生端点 |
| SerpApi | 免费计划每月250次；需密钥 | 酒馆原生端点，organic_results |
| 维基百科 | 匿名只读、免密钥；只检索百科 | 浏览器直连固定中/英/日域名，origin=*、Api-User-Agent，匿名且不发送酒馆校验码；每查询至多3页、每页1200字符摘要 |
