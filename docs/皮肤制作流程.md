# 皮肤制作流程（新系统）

> 2026-11-01 按本支线（`frontend-rewrite`）重写。协议以 [前端契约](前端契约.md) 第 5、6 节为准，本文只写**做一套皮肤的顺序、命令与坑**。
> 旧系统（`src/skins/`、皮肤契约 v0.3、`lint-skins` / 预览台那一套）只在 main 上有效，看 main 上的同名文档。
> 示范皮肤是「碎光」（`src/skins-next/suiguang/`），遇到「这个该怎么写」先看它。

## 1. 先定风格（用户确认后才动手）

- 先跟用户对齐：用途 / 气质、浅色与深色各自的基调和强调色、正文字体、圆角与层次（阴影 / 平面）、要不要特效和装饰、参考图。
- 每套皮肤**必须同时有浅色（`light`）与深色（`dark`）**，可以再加配色（例如碎光的「阅读」）。
- 素材写明来源与授权（`credits`）；程序生成的写生成脚本路径。授权生成素材不等于批准布局。
- 用户确认的结论记进 [frontend-design.md](frontend-design.md)（新一轮）。

## 2. 建皮肤包

```
src/skins-next/<id>/
  skin.json     清单（必需）：id 与目录名一致
  skin.css      部件 CSS（可选）
  assets/       PNG / WebP（可选；单张 ≤ 300KB，全部皮肤合计 ≤ 1.2MB）
```

按四级定制从轻到重做，能在上一级解决的不往下一级走：

1. **L1 种子**（`schemes.<配色>.seeds`）：`neutral`（基调）、`accent`（强调）、`radius`（0~32）、`elevation`（`flat` / `shadow` / `glow` / `outline`）、`contrast`（`standard` / `high`，可选）、`font`（各字体栈**必须以通用族结尾**，如 `serif`）、四种语气色 `danger / warning / success / info`（可选）。
   引擎从种子推出全部成对令牌并检查对比度。
2. **L2 令牌覆盖**（`tokens` / `components`）：只在推导结果不合意时点名改某个令牌或组件配色对（碎光改了 `selected` 和 `badge.tone`）。
3. **L3 部件 CSS**（`skin.css`）：形状、边框、材质、纹理、动效。规则见契约 6.3：
   - 选择器从公开钩子出发（`[data-k="…"]`、`[data-k-part="…"]`，钩子清单 `src/frontend/ds/parts.ts`）；容器组件的部件必须用 `>`。
   - 不写 `@layer`、不写外链和 `@font-face`（外链字体走清单 `fonts`，图片走 `assets`）。
   - 分配色写法：`[data-k-surface][data-k-scheme="dark"] { … }`。
4. **L4 装饰与素材**：`assets`（以 `--k-asset-<名>` 提供）、`ornaments`、`modules`（平台动效：`fracture` / `particles` / `glitch` / `ink` / `trace` / `scan` / `unroll`，参数见契约 6.5）、`effects`（用户可开关的特效）、`params`（可调参数）。
   - 装饰图形用 `mask` + `background: var(--k-accent)` 画（`data:` SVG 做遮罩），颜色就跟着配色走；纹理用 CSS 渐变，不占素材预算。
   - 常驻的循环动画写在 `[data-k-surface][data-k-motion="full"]` 下面，「平静」档自然就停。
5. **外链字体**：皮肤目录写 `fonts.src.json`，`node build/frontend/fetch-fonts.mjs <id>` 生成 `fonts.gen.json`（一起提交）。只取了一个字重的字体**别放进正文字体栈**（整段正文会变成那个字重）。

另外两件**每套都要做**的：

- **消息内容**（契约 6.8）：正文字体写在 `[data-k-content="body"] > *` 上；每个配色给 `--k-msg-dialogue`（对白）、`--k-msg-thought`（心理描写），并自己保证对消息底色 ≥ 4.5 : 1（这两个不经引擎校正）。规则必须以 `[data-k-content` 开头，否则管不到酒馆页面里的正文。
- **图标**：条目名里的 emoji 换图标走清单 `icons`（契约 6.7），**每套皮肤各带一份映射、没有平台默认**。先拷碎光的 `icons`（约 80 条）再按风格换；预设里用到的 emoji 清单在 `src/frontend/ds/icons/preset-emojis.json`（改了条目名后用 `node build/frontend/scan-emojis.mjs` 重扫），构建时会报告还没映射的 emoji。

## 3. 构建期检查（构建自带，失败就不出产物）

`KAMI_ST_ROOT=/workspace/st-test/SillyTavern node build/build.mjs` 会先跑 `build/frontend-build.mjs`，其中 `build/frontend/pack-skins.mjs`：

- 校验清单字段（`validateManifest`）、检查 `skin.css`（`lintSkinCss`：钩子白名单、禁止的写法）；
- **每个配色方案都不许出现自动校正**——引擎要替你改颜色才能达标，就算失败。按报错调种子或 L2 覆盖；
- 检查素材预算，把皮肤打包进「🧩 运行库」和「🎨 显示」「💬 消息前端」用的 `SKINS_NEXT`。

显示面板、引导的皮肤列表与预览都从打包结果生成，**不用登记名单**。

- **登记顺序**：新皮肤要写进 `src/skins-next/series.json`（`default` 是默认皮肤，`series` 里按系列列出其余皮肤）。打包按这个顺序，没登记或登记了却没有目录都会报错；清单的 `series` 字段由打包打上，不要手写。
- **消息颜色**：每个配色方案都要在 `skin.css` 的 `[data-k-surface][data-k-scheme="<配色>"] { … }` 里写十六进制的 `--k-msg-dialogue` / `--k-msg-thought`，打包会算它们对该配色底色的对比度（≥ 4.5 : 1），没写或不达标都失败。

## 4. 给用户看的预览（审阅用，不是验证）

- 新风格先出预览给用户确认：`design/previews/` 下照 `suiguang/` 建一份（`main.tsx` + `index.html`），在 `build/frontend/build-preview.mjs` 的名单里加上，`node build/frontend/build-preview.mjs` 生成 `preview.js`。
- 成系列的皮肤用 `design/previews/worlds/`：读打包结果 `.cache/frontend/skins.json`，总览页每款浅色 / 深色并排，`?skin=<id>` 单款页带真的显示面板（先跑 `pack-skins.mjs` 再 `build-preview.mjs`；直接双击 `index.html` 就能看）。
- 预览只用于审阅外观。**能不能用以实机为准**（预览里脚本与页面同一个窗口，测不出酒馆里才有的问题）。

## 5. 实机验证（唯一的验证依据）

按 [test/st/README.md](../test/st/README.md) 起测试酒馆与假模型，`node test/st/install-preset.mjs dist/<产物>` 装进去，然后电脑 1440 与 `--mobile` 390 各一遍：

- `display-next.mjs`：切皮肤、换配色同时套到面板和消息前端、刷新后设置还在、注销收回；
- `message-next.mjs`：正文排版、对白 / 心理描写颜色、「皮肤字体颜色」开关、思维链 / 搜索资料 / 行动选项、公式；
- 面板对比度：各面板测试里的 `auditInPage`（实际渲染的字与底配对）。

⚠ 现有实机测试大多默认测「碎光」。加新皮肤时要让测试把**每套皮肤 × 每个配色**都切一遍跑对比度审计与消息检查（新增或扩展 `test/st/` 里的脚本），只测碎光不算新皮肤通过。

汇报时写实机结果（电脑 / 手机分开），没在实机测过的明说没测。

## 6. 交付

- 构建 → 把最新产物复制到 `test-builds/`（只留最新一份，见那里的 README）→ 提交推送 `frontend-rewrite`。
- 更新：[frontend-design.md](frontend-design.md)（这一轮确认了什么）、[交接](交接.md) 第〇节、契约有新钩子 / 字段时更新契约与变更记录。

## 新皮肤提交清单

- [ ] 用户确认了风格，frontend-design.md 已记录；素材来源与授权写进 `credits`。
- [ ] 至少 `light` + `dark` 两档，构建零自动校正。
- [ ] `skin.css` 只从公开钩子出发；消息内容规则以 `[data-k-content` 开头；每个配色都有 `--k-msg-dialogue` / `--k-msg-thought` 且达标。
- [ ] 外链字体 / 图片都有包内或通用族兜底。
- [ ] 动效档（完整 / 平静 / 关闭）与系统「减少动态效果」下特效真的停。
- [ ] 已登记进 `src/skins-next/series.json`。
- [ ] 实机：每套 × 每配色，电脑与手机都过了显示 / 消息 / 对比度检查。
