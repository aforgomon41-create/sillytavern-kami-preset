# 皮肤制作流程（给 agent 的操作手册）

> **这份是流程，不是接口规范。**
> 接口（令牌清单、类名、状态钩子、皮肤包字段、构建期校验规则）一律以 [皮肤契约](皮肤契约.md) 为准；
> 「这个零件是不是已经有一份了」看 [功能复用](功能复用.md)。
> 本文只回答一件事：**从零做一套新皮肤（或大改一套旧皮肤），按什么顺序做、每步验什么、哪里最容易翻车。**
>
> 写给谁：接到「做一套新皮肤」任务的 subagent。**照着走，不要跳步。** 本文里每一条坑都对应一次真机返工。

---

## 〇、开工前 10 分钟（必做）

1. 读 [皮肤契约](皮肤契约.md) 的 **§2（皮肤作者八条硬规则）**、**§3（令牌全集）**、**§7（构建期校验）**。
   令牌缺一个就构建失败，选择器写错一个前缀就构建失败 —— 这两件事先知道，能省一轮返工。
2. 读本文 **§五 踩过的坑**。那里是历史上真实翻车过的地方，不是理论。
3. 跑一遍现成的：

       node build/lint-skins.mjs          # 五套皮肤必须全 PASS，先看看「合格长什么样」

4. 起预览台（改完刷新即可，**不用构建**，它实时读 `src/`）：

       node test/harness/server.mjs --port 8790
       # 浏览器打开 http://127.0.0.1:8790/test/harness/preview.html?skin=<你的皮肤id>

## 一、先定「皮肤是什么」，再写一行 CSS

**没有设计简报就直接写 CSS，一定会返工。** 本项目 grokbot 的第一版就是「做完了被用户全盘否掉、推翻重做」。

简报里必须写清四件事，产出到 `design/proposals/<id>.md`：

| 要定的事 | 说明 | 参考 |
|---|---|---|
| **设计语言一句话** | 例：色块 =「无彩色、无描边、大圆角、纯平面」；TRPG =「黄纸 + 打字机 + 手绘骰子」 | `design/proposals/grokbot.md` §一 |
| **身份符号** | 用户一眼认出这套皮肤的那个记号（一个形状 / 一种材质 / 一个动效）。**只留一个**，别堆 | 同上 |
| **配色关系** | 主调占多少面积、允许几种颜色、语义色（`--kami-kind-*`）怎么区分 | 同上 §二 |
| **参考与边界** | 参考图放在 `design/reference/<id>/`（**不进 git**）；**只借语言不抄素材**（别人的 SVG 路径数据不能用） | 同上 §一注 |

> ⚠️ 身份符号在实现后**可能被用户否掉**（grokbot 的「两只胶囊眼」就是做完被点名全删的）。
> 所以：**别把身份只押在一个花哨元素上**，材质、圆角、明度关系这些骨架要能独立立住。

## 二、建包：两个文件，字段照抄

    src/skins/<id>/skin.json     皮肤元数据（面板显示名、按钮短名、特效、参数、装饰声明）
    src/skins/<id>/skin.css      一整份组件 CSS（**作用域前缀必须是 html[data-kami-skin="<id>"] **）

`skin.json` 字段（完整定义见契约 §6；`build/lint-skins.mjs` 会逐项校验）：

| 字段 | 必填 | 约束 |
|---|---|---|
| `id` | ✅ | 必须与目录名一致（lint 会拦） |
| `name` | ✅ | 皮肤管理面板里显示的名字 |
| `button` | ✅ | 脚本按钮上的短名（按钮整体文案 = `🎨` + button） |
| `scheme` | — | 建议的明暗方案 `dark` / `light`（用户仍可覆盖） |
| `decor` | — | 要哪些装饰模块，目前只有 `d20`；**只声明，注入与销毁由皮肤管理负责** |
| `effects` | — | `[{id,label,desc?,default?}]`；每个 `id` 必须在 CSS 里出现 `[data-kami-effects~="<id>"]`，否则 lint FAIL |
| `params` | — | `[{id,label,group,token,unit,min,max,step,value}]`；`value` 必须在 `min..max` 内；**`unit` 必须是合法 CSS 单位或空串**（见 §五-②） |
| `css` | ❌ | **不要写**：CSS 一律放 `skin.css`，写在 json 里 lint 会警告 |

**皮肤包不写 JS。** 会动的装饰（骰子那种）走契约 §8 的装饰模块通道。

## 三、写 CSS 的顺序（按这个顺序写，返工最少）

1. **作用域与令牌块**：先把 `html[data-kami-skin="<id>"] .kami-root { … }` 里的**全部令牌**给全。
   全集 = `src/skin/base.css` 里出现的所有 `--kami-*`（lint 就是拿它当清单比对的，缺一个直接 FAIL）。
   > 兜底皮肤 `base.css` 的令牌表**就是必备令牌表**。要加新令牌：先加到 `base.css`，六份一起补。
2. **档位响应**：`data-kami-scheme`（明暗）、`data-kami-density`（密度）、`data-kami-motion`（动效）、
   `prefers-reduced-motion`。后两个是 **lint 硬要求**，缺了直接 FAIL。
3. **消息楼层组件**（`.kami-root:not([data-kami-comp="panel"])`）：think / options 两个前端。
   这套规则同时作用于**每一个聊天楼层**，所以性能与体积最要紧（见 §五-⑤）。
4. **面板组件**（`.kami-root[data-kami-comp="panel"]`）：卡片、条目、字段、按钮、折叠、角标。
   **不许挂面板 id**（见 §五-①）。
5. **对比度四件套**：`.kami-number` / `.kami-text` / `.kami-textarea` / `.kami-select`（见 §五-②）。
6. **状态钩子**：`.is-on` 高亮（不许只靠颜色）、`.kami-collapse[data-kami-open]`、`.is-done`、`:focus-visible`。
7. **收尾**：`@container` / 窄屏媒体查询、长文本溢出、空态。

## 四、接进工程（五处，漏一处就出问题）

| # | 要改的地方 | 漏了会怎样 |
|---|---|---|
| 1 | `build/apply-copy.mjs` 的 `SKIN_IDS` | 文案落地脚本不认识新皮肤，标题文案永远吃 HTML 默认值 |
| 2 | `build/lint-copy.mjs` 的 `SKIN_IDS` | 文案校验漏掉它，错文案能进产物 |
| 3 | `design/copy/copy-table.json` 的四节（tagline / 三个槽位 / effects / params） | 同上；**新皮肤的文案必须由专职文案 agent 写**，实现 agent 不许自己编 |
| 4 | `src/scripts/30-皮肤管理.js` 的 `PREFERRED` | 只影响「默认皮肤是谁」，新皮肤不一定改 |
| 5 | `docs/皮肤契约.md` §4.2 | **只有在新增类名/令牌时才需要**：没登记就是违规类名，别的皮肤与审计都会漏 |

**不需要改的地方**（运行时读 `src/skins/`）：皮肤管理面板的皮肤列表与预览卡、引导面板的皮肤页。新皮肤加进去自动出现。

## 五、踩过的坑（每条都真机返工过）

### ① 选择器与作用域

1. **每条选择器必须以 `html[data-kami-skin="<id>"] ` 原样开头**（特效规则写 `html[data-kami-skin="<id>"][data-kami-effects~="fx"] `）。
   根因：皮肤管理面板要用「机械替换前缀」生成预览作用域副本。证据：`build/lint-skins.mjs:93-105`（硬拦）。
2. **多面板共用的组件，规则一律不许挂面板 id**。只写到 `.kami-root[data-kami-comp="panel"]` 这一层。
   根因：同一枚组件（卡片 / 条目 / ⓘ / 开关 / 输入框）出现在四块面板里，写死 `#kami-preset-panel` 就必然漏掉后上线的面板。
   历史：ⓘ 与开关高亮就是这么丢的；更早还有一次「选择器少一个空格」（`[data-kami-comp="panel"].kami-card` 要求同一个元素既是面板根又是卡片，永不匹配），
   五套皮肤 + 兜底共修 86 处。证据：`docs/皮肤契约.md` §4.4 硬规则、`nixie/skin.css:1619-1620` 的历史。
3. **每条选择器必须含 `kami`**：绝不裸选酒馆自己的 UI（`#chat` / `.mes` / `body` / `.qr--button`）。证据：`build/lint-skins.mjs:89`。
4. **面板内组件的几何例外只有一处**：面板自己的骨架（舞台、`.kami-drop`、`.kami-resize`、tab 行排布）可以用 id；
   用了必须在皮肤注释里写明是哪一条、为什么。

### ② 令牌与对比度

1. **令牌表有两套时，必须成对补齐**（grokbot 就是炭底一套 / 黏土白本体一套，靠令牌重映射切换）。
   漏一个（例如 `--kami-accent-fg`）就是「强调底 + 同色字」= **1.00:1 完全看不见**。
2. **重映射要覆盖到外壳**：`.kami-shell` / `.kami-surface` 也要进重映射块 —— 组件里到处是显式 `color: var(--kami-*)`，光靠继承挡不住。
   漏了就是「聊天楼层里标题白字压白底」。
3. **选中态换了底，字就得跟着翻**（同型事故出现过三次）：`.kami-item.is-on` / `.kami-btn.is-on` 用墨块底时，
   卡作用域里的 `--kami-fg` 也是墨色 → 1.00:1。**新增任何「选中换底」的状态，先问一句：字翻了吗？**
4. **对比度规则必须四类控件一起写**，而且 `background-color` + `color` + `color-scheme` **三项都要 `!important`**：
   两层东西在抢色 —— ① 用户酒馆的「自定义 CSS」（`power_user.custom_css`）给数字框/文本/下拉各上了深漆且自带 `!important`；
   ② 皮肤头部 `.kami-root input { color: inherit }` 会把文字压成 `--kami-fg-dim`。两层不挡住就是「黑底配深字」（真机实测对比度只有 2.24:1）。
   目标 ≥ 4.5:1。**验证纪律：`getComputedStyle` 的背景是「透明」时，往上层找背景算出来的对比度是假读数** —— 必须确认背景是显式非透明值，并且**在真机上读**（预览台没有酒馆的深色样式与用户自定义 CSS，复现不出来）。
5. **`params[].unit` 不是纯显示字段**：皮肤管理会把它**直接拼进 CSS 值**（`v + (p.unit || '')`）。
   写 `×` 会让 `calc(... * 1×)` 非法 → 整条 `width`/`height` 声明被丢弃（真机表现：骰子宽高归零、压住标题被纸边裁掉）；
   写 `°` 会让 `rotate(-1.2°)` 非法 → 整条 `transform` 变 `none`。**只能是合法 CSS 单位或空串。**
6. **禁用令牌清单**：8 个功能性文案令牌（`--kami-label-empty` / `-chars` / `-unit` / `-demo` / `-filled` / `-noinput` / `-sent` / `-sendfail`）
   **任何皮肤都不许定义** —— 定义了就会顶掉前端写死的文案，四套皮肤的说法立刻不一致。见契约 §3.7。
7. **亮色方案最容易漏测**：预览台默认跑暗色。只做推算的亮色方案 = 没测过（grokbot 至今如此）。

### ③ 面板组件

1. **未选中的卡片不能和容器同色**：面板里的卡是套着的，内外两层都吃 `--kami-card` 会完全同色。
   正解 = 换一档明度的填充 + 一条看得见的边。
2. **内边距别叠两层**：给「分组卡」补内边距的规则必须写成 `.kami-card:not(.kami-item)` ——
   条目卡自己有 12px 内边距，再叠一层会把条目名挤到只剩 44px 宽、被逐字折断成竖排。
3. **结构判据要把子元素种类列全**：面板网格的密集判据写成 `.kami-grid:has(> .kami-item)` 时，
   带注释的条目卡外面多包了一层 `.kami-item-note`，判据整条落空 → 退回 `--kami-items-min: 15rem`，367px 只排得下 1 列。
   现在写成 `:has(> .kami-item, > .kami-item-note)`。**改网格判据后必须用预览台的列数探针逐格核对。**
4. **带注释的条目卡要等高**：`.kami-item-note` 是网格项、会被同行最高的卡拉伸，但**里面的卡片不跟着伸**。
   每套皮肤都要写：

       html[data-kami-skin="<id>"] .kami-root .kami-item-note { display:flex; flex-direction:column; min-width:0; }
       html[data-kami-skin="<id>"] .kami-root .kami-item-note > .kami-card { flex:1 1 auto; }

5. **卡片开关态不许只靠颜色**：形状、边线、字重至少占一样（色觉差异用户与低对比度皮肤上，只靠颜色等于没有反馈）。见契约 §4.2。
6. **ghost 按钮的描边要用「控件档」**（`--kami-line-strong`，约 3:1），不能用「分隔线档」（`--kami-line`，约 1.6:1）：
   底透明 + 分隔线档描边 = 只剩一行字，用户会认不出那是个开关（真机报过：压缩面板里「摘要(小总结)条目的开关情况」字样看不清）。
7. **预览窗必须 `pointer-events:none`**：皮肤卡里嵌的是 `iframe`，它会把点击自己吃掉、不冒泡到父级 button，
   表现是「预览卡点不动」。`.kami-pv` / `.kami-pv-frame`（皮肤面板）与 `.kami-guide-pv` / `.kami-guide-pv-frame`（引导）四处都要。
8. **面板里的卡头别做成胶囊**：卡头是 `button.kami-card-head.kami-btn`，而 `.kami-btn` 默认是胶囊 + 居中 + 按内容收缩宽度，
   放进方形卡片里就是「一枚悬在卡里的小药丸」。面板里改成**与卡同宽的矩形标题条**。

### ④ 几何与定位

1. **`.kami-shell` 与 `.kami-surface` 常常是同一个元素**：在 `.kami-shell` 里写 `background` 简写会把 `.kami-surface` 上叠的纸面/纹理整个重置掉
   （表现：纸突然塌成一块灰底）。要叠加就写 `background-image` / `background-color` 这类长写属性。
   同一条也适用于 `.kami-select` 的自绘箭头：写 `background` 简写会把箭头的 `background-image` 一起重置。
2. **不要给 `.kami-root` / `.kami-surface` 写定位**：面板舞台与 `.kami-drop` 的定位由脚本注入的几何层负责（特异性已抬到 (0,3,0) / (0,4,0)）。
   皮肤只负责「它长什么样」，不负责「它摆在哪」。
3. **不许用 `vh`**：消息 iframe 的高度由 `body.scrollHeight` 决定，且酒馆助手会重写 `min-height:*vh`。lint 硬拦。
4. **不许 `position:fixed` 铺满**：会跑出 iframe 可视区。要浮层就在组件内部做 `position:absolute` + 容器 `position:relative`。
5. **窄屏必须成立**：所有布局先在 320px 宽下看一遍；多列一律 `repeat(auto-fill,minmax(var(--kami-items-min),1fr))`，不许固定像素宽。
6. **面板窄屏要变成贴底抽屉**：皮肤按 `.kami-drop[data-kami-layout="sheet"]` 写规则。

### ⑤ 构建与校验（这几条不过，产物根本出不来）

`node build/lint-skins.mjs [id]` 会拦下面每一条：

- 出现 `@import` / `@font-face` / `<script` / `javascript:`；
- 出现任何**外部网络引用**（`url(http` / `url(//` / `src=http` …）—— 皮肤 CSS 会被注入到**每一个聊天楼层**，
  一个外部请求就是按楼层线性增长的断网风险。允许 `data:` URI、`mask`、`clip-path`、`filter`、`backdrop-filter`、`@keyframes`、`@property`、`@container`、`:has()`、渐变、3D transform；
- 使用 `vh` 单位；
- 选择器不含 `kami`，或没以皮肤前缀开头；
- **令牌缺项**（对照 `src/skin/base.css` 的全集）；
- 缺 `prefers-reduced-motion` 或 `data-kami-motion` 响应；
- 缺 `:focus-visible`，或没有把 `--kami-fs-scale` 乘进字号；
- `effects` 里的 id 在 CSS 里找不到 `[data-kami-effects~="<id>"]`；
- `params` 项缺 `id/label/token`，或缺 `min/max/value`，或 `value` 不在区间内。

警告（不拦但要处理）：没响应 `data-kami-density` / `data-kami-scheme`；没给 `--kami-label-think-title` / `--kami-label-options-title`（会失去品牌化标题）；`skin.json` 里写了 `css` 字段。

### ⑥ 真机验证（预览台不够）

1. **部署是两步**：复制产物到 `OpenAI Settings\` **之后必须在界面里把它选为当前预设**（两道放行名单都要有它）。见 [真机验证备忘](真机验证备忘.md) §一。
2. **对比度与「点不动」这类问题，预览台复现不出来**（它没有酒馆的深色样式、没有用户的自定义 CSS、也没有真 iframe 的沙箱行为）。
3. **`getComputedStyle` 读背景为透明时算出的对比度是假读数** —— 这一条骗过一轮（算出 16:1，实际 2.24:1）。
4. **截图会返回上一帧**：结论以 DOM 读数（`observe` / 预览台 `#diag`）为准，图不对就补一次 `wheel` 再截。

### ⑦ 其它（协作与纪律）

1. **并行会话在改皮肤时，不要往皮肤文件里打补丁** —— 有过一次「补丁被另一路的整体重写覆盖，白改」。
   要改就整体改，改完立刻跑 lint 与预览台。
2. **文案不许手写进皮肤包**：风格性文案的真相来源是 `design/copy/copy-table.json`，
   落地用 `node build/apply-copy.mjs`（幂等、支持 `--check`），校验用 `node build/lint-copy.mjs`。
   **落地脚本绝不重打文案，只读表**；措辞交专职文案 agent。
3. **新类名/新令牌必须先登记进契约再落地**（契约 §3 / §4.2）。没登记的类名 = 别的皮肤不认、审计会报违规。
4. **`.kami-deco` 装饰槽**：声明了 `decor: ["d20"]` 的皮肤要显式写 `.kami-deco.kami-d20::before, ::after { content: none; }`
   并放开 `pointer-events`；**不要**用 `--kami-d20-s` 反推槽位自身尺寸（会和 ResizeObserver 形成回环）。

## 六、验证三关（缺一不可）

| 关 | 怎么跑 | 看什么 |
|---|---|---|
| **1. 静态校验** | `node build/lint-skins.mjs <id>` | 必须 PASS（含令牌全集、前缀、禁项、档位响应） |
| **2. 预览台** | `node test/harness/server.mjs --port 8790` → `preview.html?skin=<id>` | `#diag` 的**列数探针**（网格列数 / 卡片尺寸）、**面板探针**（几何、溢出 0）、**渗漏探针**（消息 iframe 里的 `--kami-items-min` 不该被面板规则污染）、对比度读数 |
| **3. 真机** | 复制产物 → 界面里切为当前预设 → 手机上看 | 对比度、点不动、窄屏、贴底抽屉、动效档位 |

预览台里几个常用的自检参数（`preview.html?...`）：
`skin=<id>` 指定皮肤、`noskin=1` 看兜底皮肤、`notes=1` 注释标记自检、`vars=1` 变量页自检、
`about=1` 「关于」页自检、`check=1` 开关不重画面板自检、`shutdown=1` 注销零残留自检。
