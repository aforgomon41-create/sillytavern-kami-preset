# 皮肤制作流程

本流程配合 [皮肤契约 v0.3](皮肤契约.md) 与 [组件库](ui-components.md) 使用；旧的固定皮肤名单、文案代理写入和“皮肤自行决定面板位置”要求已撤销。修改权限与分工按作者当前的协作约定；前端架构与组件分工见 [前端技术栈](前端技术栈.md)。

## 1. 先确认风格和布局

先读 docs/frontend-design.md。新增风格先沟通用途、配色、字体、密度、组件和参考，经用户确认后更新设计文档；新增或重大改动布局先制作最小预览，明确审阅通过再正式实现。修复已确认布局的故障沿用当前设计。

记录素材来源、使用条件、生图授权。授权生成素材不等于批准布局。不为达到某种视觉效果另造业务控件。

## 2. 从共享组件开始

检查组件库和 src/ui/catalog.json，先确认：
- 容器是 embedded、panel 还是 dialog。
- 卡片是 container、choice 还是 collapse。
- 导航默认 scroll，等分才用 fit，末尾控件用 tab-actions 插槽。
- 模型连接、提示词编辑、搜索资料和弹窗是否已有实现。
- 数据/事件归业务，几何/滚动归公共层，材质/配色归皮肤。

通用控件不能按某个面板 id 修补，不能将 tabs 混进会换行的操作组。

## 3. 建立皮肤包

目录 src/skins/<id>/ 中创建 skin.json、skin.css，可选 assets/。元数据格式、单位和限制见契约 §6、§8。

id 与目录名一致；源码 JSON 不写 css；特效/参数 id 不重复；同一 token 不能配置两次；unit 是实际 CSS 单位，不能写 ×/°。

自动发现目录，无需修改 apply-copy/lint-copy 的固定名单。需要补 design/copy/copy-table.json 对应的介绍、风格槽、特效和参数文案；功能文案留在前端。

## 4. 按顺序实现

1. 默认根级令牌。必填集合以 lint-skins 为准；OPTIONAL_TOKENS 有公共兜底，不是全部必填。基础字/底/强调配色不可只放局部。
2. 明暗、密度、字号缩放、full/calm/off、系统减少动效。
3. 三种容器的外观。舞台、手机抽屉、弹窗正文滚动沿用公共层。
4. 普通/选择/折叠卡、按钮、说明、链接和四种输入。开关与下拉**两种结构都要覆盖**：Radix（`.kami-switch[data-state]` + `.kami-switch-thumb`、`.kami-select-content` / `.kami-select-item[data-state]`）与原生（`.kami-switch-input` + track/knob、`select.kami-select`），见契约 §4。
5. 正常、选中、禁用、焦点、忙碌、错误和空态。
6. 320px、放大字号、长文、空资料、预览缩略与装饰开关。

每条选择器按准确皮肤前缀进入我们自己的组件，分组和媒体查询同样遵守。局部 token 不得复制到 html；生成块由脚本维护。

## 5. 同步与静态检查

~~~sh
node build/sync-tavern.mjs
node build/apply-copy.mjs --check
node build/lint-copy.mjs
node build/lint-skins.mjs
node test/harness/skin-contract.mjs
node test/harness/ui-components.mjs
~~~

apply-copy --check 只检查；需要从已审阅的文案表落地时运行不带 --check 的命令。不得靠改生成块修错，也不得给错误规则加豁免来过构建。

## 6. 浏览器与实机检查

~~~sh
node test/harness/server.mjs --port 8794
~~~

另一终端设置 KAMI_PREVIEW_ORIGIN=http://127.0.0.1:8794；PowerShell 使用 $env:KAMI_PREVIEW_ORIGIN='http://127.0.0.1:8794'。

~~~sh
node test/harness/ui-components-browser.mjs
node test/harness/tab-layout-browser.mjs
~~~

按契约 §10 检查：
- 三容器、明暗、320/390/桌面、默认/放大字号。
- 导航同一行、首尾可达；触摸、滚轮、键盘有效；皮肤快捷下拉没有另占一行。
- 嵌套模型/提示词卡的文字与背景成对；原生下拉展开层可读。
- 长正文背景不拉伸，装饰不挡字/操作；关闭后无残留。
- 动效档和系统设置真正停止循环，停用清理资源。
- 在酒馆宿主/用户自定义 CSS 下复核；预览台不能完全替代实机。

检查透明背景时按真实叠加结果判断，不能把 transparent 当成固定黑白。只检查边界无法发现 tabs 多行，须检查行数和实际滚动。

## 7. 构建与交付

运行项目构建。构建内已强制执行皮肤与组件契约、文案及现有功能检查。生成产物后执行 tab-layout-browser --built，确认实际打包结果。

更新设计文档、功能复用说明和交接：记录新增接口、验证范围、截图路径、已知限制和产物身份。只报告本轮实际做过的检查，不把静态通过说成所有状态已人工验收。发版、源码推送和文件传输按用户当前授权执行。

## 新皮肤提交清单

- [ ] 用户已确认风格；新增/重大布局已审阅，设计文档已更新。
- [ ] 使用共享组件、正确容器/卡片角色/导航插槽。
- [ ] 根令牌完整、局部映射不泄漏、字底成对。
- [ ] 元数据/文案/装饰/资源合法，生成块已同步。
- [ ] 静态检查通过，故障负例能被检查拒绝。
- [ ] 浏览器矩阵及宿主/原生选单必要人工检查已记录。
- [ ] 构建产物核对通过，交接记录和素材来源齐全。
