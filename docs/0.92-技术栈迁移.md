### 迁移模式（照这个抄）

1. 找出脚本里**自成一块**的界面（弹窗、卡片、列表）
2. 用 `RT.React.createElement` 写成组件，**类名保持原样**
3. 容器沿用原来的 `id` / class，React 只渲染它的子节点
4. 原来 `el.xxx.textContent = ...` 的地方改成 `reactRoot.render(...)`
5. 关闭时 `reactRoot.unmount()` 再摘容器
6. 运行库取不到要有降级（这块界面不显示，功能继续）

### 组件层自测（jsdom）

新增 `test/harness/runtime-ui.mjs`（41 项，已接进构建）：用 **jsdom 起一个真 DOM**、
加载**产物里的真 bundle**，把每个组件渲染一遍，钉住两件事：

- 类名契约：`.kami-btn` / `.kami-card` / `.kami-switch` / `.kami-collapse` …
- Radix 的可访问性角色：`role=switch` / `checkbox` / `radio` / `tab` / `tabpanel` / `dialog` / `progressbar`

> 为什么必须用 jsdom 的 `getInternalVMContext()`：手写全局白名单会漏，
> Radix 一碰 `instanceof HTMLFormElement` 就直接 ReferenceError。
> 创建 JSDOM 时要带 `runScripts: 'outside-only'` 才拿得到它。

**这一步抓到一个真 bug**：运行库导出的 `flushSync` 之前取自 `react-dom/client`
（那里没有这个导出），实际是 `undefined` —— 调用方以为能同步刷新，拿到的是异步渲染。
已改为从 `react-dom` 取。

### 解决办法：原生结构兼容控件（已落地）

`src/runtime/ui.jsx` 里新增了一组**用 React 写、渲染出原生结构**的控件：

| 组件 | 渲染成 | 为什么 |
| --- | --- | --- |
| `RT.UI.NativeSwitch` | `label.kami-switch > input.kami-switch-input + span.kami-switch-track > span.kami-switch-knob` | 皮肤靠 `:checked + .kami-switch-track` 这个**兄弟关系** |
| `RT.UI.NativeSelect` | `select.kami-select > option…` | 皮肤用 `select.kami-select` **限定元素名** |
| `RT.UI.NativeCheck` | `input.kami-checkbox[type=checkbox]` | 同上 |
| `RT.UI.NativeButton` | `button.kami-btn[--primary|--ghost]` | 原生按钮语义 |

**这样面板可以先迁到 React，而皮肤一行都不用改。** 等哪天 21 套皮肤都补了 Radix 版本的样式，
再把面板里的 `NativeSwitch` 换成 `SwitchToggle`（Radix）就是一行的事。

自测已覆盖（`test/harness/runtime-ui.mjs` 第 ⑧ 组，15 项）：逐字核对 DOM 结构与兄弟关系、
并验证 `onChange` / `onClick` 真的能通。

> 坑：受控组件在测试里要用 `.click()`，直接改 `.checked` 再派发 change，
> React 的值追踪器认不出「用户操作」，合成事件不触发。

## 三、Radix 与 21 套皮肤的兼容性（**必须先看**）

2026-10-26 实测统计了 `src/skins/*/skin.css` 对原生控件结构的依赖：

| 选择器 | 出现次数 | 含义 |
| --- | --- | --- |
| `.kami-switch-input` | **88 处** | 依赖「原生 checkbox + 兄弟节点」的结构（`:checked + .kami-switch-track`） |
| `select.kami-select` | **27 处** | 元素名限定，只匹配原生 `<select>` |
| `.kami-tab[aria-selected="true"]` | 多处 | **只依赖 aria 属性**，不限定元素类型 |

结论分两类：

**✅ 皮肤安全的 Radix 组件**（换过去皮肤照样生效）

- Tabs —— 皮肤用 `[aria-selected="true"]` 判选中，Radix Tabs 原生就输出这个属性
- Collapse / Accordion —— 皮肤认 `.kami-collapse[data-kami-open]`
- Menu / DropdownMenu / Tooltip —— 皮肤只认类名
- Progress —— 皮肤基本没写，走 `.kami-progress` 类名

**⛔ 会打断皮肤的 Radix 组件**（换之前必须同步改 21 套皮肤）

- **Switch** —— Radix 渲染 `button[role=switch]`，皮肤写的是 `.kami-switch-input:checked + .kami-switch-track`
- **Select** —— Radix 是「按钮 + 弹层列表」，皮肤写的是 `select.kami-select`
- **Checkbox / RadioGroup** —— 同理依赖原生 `input`

也就是说：**「全面改用 Radix」不能无差别铺开**。要么给这三类控件补 21 套皮肤的规则（工作量大、且会打断用户自制皮肤），要么保留原生控件、只在上面那几类上换 Radix。

> 原生 `<select>` / `<input type=checkbox>` 本身就是可访问的，换 Radix 主要是为了弹层与键盘体验。
> 建议：**先换安全的那几类**，开关/下拉这两类等到有皮肤侧配套方案再动。

### 迁移一个面板的步骤

1. 在脚本里取 `HOST.KamiRuntime`（取不到显示「请启用运行库」并退出）
2. 用 `RT.createMountPoint()` 建挂载点，`RT.UI.*` 写界面
3. 原来用 `mk()` / `createKamiUi().xxx()` 的地方换成 `RT.UI.Button` / `RT.UI.TabsRoot` 等
4. 删掉脚本里的 `/* @@KAMI_UI@@ */` 占位（迁移完成后不再需要 shim）
5. 跑 `node build/build.mjs`，再开预览台确认那个面板正常

**建议顺序**：工具箱 → 远程更新 → 引导 → 预设设置 → 皮肤管理（从小到大）。
