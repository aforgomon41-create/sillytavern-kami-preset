## 一、已完成

### 1. 新增「🧩 运行库 v1.0」脚本（默认开启，排第一位）

- 文件：`src/scripts/00-运行库.js`（占位符 `/* @@KAMI_RUNTIME@@ */`）
- 产物：`src/runtime/bundle.js`（esbuild 打包 `src/runtime/`，约 366KB）
- 构建：`node build/build-runtime.mjs` 生成 bundle，`build/build.mjs` 通过 `expandRuntime` 内联进脚本
- 注册位置：`meta.json` 第 0 条 + `folders.json`「基础与外观」第一位

运行库把 React 18、ReactDOM、14 个 Radix 原语、组件层、老的 `createKamiUi` 核心
和基础样式（foundation.css + 令牌）**只打一份**，注册到酒馆宿主窗口：

```js
HOST.KamiRuntime = {
  version, React, ReactDOM, createRoot, flushSync,
  UI,              // Radix 组件层（类名仍是 .kami-*）
  primitives,      // 14 个 Radix 原语
  createKamiUi,    // 老组件核心（面板没迁完时用）
  KAMI_UI_CSS,     // 基础样式
  mount, unmount, createMountPoint, ready,
  host, document
}
```

装没装上，看宿主 html 上有没有 `data-kami-runtime="1.0.0"`。

### 2. 面板不再各自内联组件核心

原来 `core.js`（41KB）被内联进 8 个脚本、`foundation.css`（15KB）8 份，合计约 390KB 纯重复。
现在 `build/kami-doc.mjs` 的 `expandUi` 只发一段**惰性 shim**：

```js
function createKamiUi(doc) {
  var rt = HOST.KamiRuntime;   // 取不到就抛人话错误
  ...
  return rt.createKamiUi(doc);
}
```

> ⚠️ 必须惰性：占位符在脚本里的位置**早于 HOST 定义**，写成 `var x = HOST.KamiRuntime.x` 会在定义时取到 undefined。

**效果**：产物 5.73MB → 5.22MB（省约 550KB）。

### 4. 样式分层（@layer）

`30-皮肤管理.js` 的 `skinCssText` 现在按层输出：

```css
@layer kami.base, kami.component, kami.skin;

@layer kami.component { /* 结构性兜底 + 面板几何 */ }
/* 皮肤 CSS **不分层** —— 未分层永远压过分层，皮肤天然最后一句话 */
```

### 迁移一个面板的步骤

1. 在脚本里取 `HOST.KamiRuntime`（取不到显示「请启用运行库」并退出）
2. 用 `RT.createMountPoint()` 建挂载点，`RT.UI.*` 写界面
3. 原来用 `mk()` / `createKamiUi().xxx()` 的地方换成 `RT.UI.Button` / `RT.UI.TabsRoot` 等
4. 删掉脚本里的 `/* @@KAMI_UI@@ */` 占位（迁移完成后不再需要 shim）
5. 跑 `node build/build.mjs`，再开预览台确认那个面板正常

**建议顺序**：工具箱 → 远程更新 → 引导 → 预设设置 → 皮肤管理（从小到大）。

## 三、注意

- 运行库是普通脚本，用户能在脚本列表里关掉。关掉后所有面板提示「运行库未加载」——
  这是预期行为（用户裁定：默认开启，关掉是他自己的选择）。
- `build/build-runtime.mjs` 改了 `src/runtime/` 之后必须重跑，否则产物是旧的。
  守卫只能发现「占位没展开」，发现不了「bundle 过期」—— 记得重跑。
