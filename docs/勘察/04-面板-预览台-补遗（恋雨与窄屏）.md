## 一、rain（恋雨）

### 面板本体是不是半透明、酒馆页面会不会透上来

1. **不会。rain 的面板是一块几乎不透明的深色板，底下页面读不到上面来。**
   现象：面板外 5px 处是页面的浅灰诊断文字（亮度约 135/255），同一条水平线上面板内部最亮只有 35–54/255（面板底色 32/255）。按面板自己报的背景色 `rgba(22,27,28,0.93)` 算，7% 的渗漏正好对上这个数——界面上看不到任何可读的页面文字，只看到面板自己的雾斑、水珠和一道斜向反光。
   读数：`当前皮肤：rain … bg=rgba(22, 27, 28, 0.93)`（页面顶栏）；像素采样来自我自己写的一次性扫描（不写盘、不改页面）。
   证据：`rain-skin.png`、`rain-params.png`、`rain-fx.png`、`rain-preset.png`；放大件 `_tmp-rain-params-panel.png`、`_tmp-rain-fx-panel.png`、`_tmp-rain-preset-panel.png`。

2. **面板正文照常读得了。**
   现象：标题「皮肤管理」「预设设置」、tab（皮肤/参数/特效、模型/设置变量/…）、参数组名（通用/水汽/面板/光照）、特效名（玻璃起雾/水珠凝结/雨滴敲击/雨痕滑落/车灯光斑）、模型卡标题（表示DeepSeek系列模型）都是近白字压在深底上，一眼能读。
   证据：`rain-params.png`、`rain-fx.png`、`rain-preset.png`、`rain-skin.png`。

3. **面板里的水珠和雾是 rain 自己的装饰，不是页面透上来。**
   现象：面板正文区散着几颗小水珠和一道很淡的斜向亮带（玻璃反光），位置固定、和面板外的页面内容没有对应关系。
   证据：`_tmp-rain-params-panel.png`（面板下半屏的那几颗）、`_tmp-rain-fx-panel.png`。

### 数字输入框

4. **可读，不是黑底黑字。**
   现象：设置变量页的 6000 / 1500 / 3000 / 4 / 8，是深色小方框 + 近白色数字 + 一条白色下划线；参数页「字号缩放」的数字框同样是深框 + 白字（右边跟一个灰色的 ×）。实测框底 rgb(22,27,28)、数字 rgb(230,226,216)，对比度很高。rain 是第三种配色：memo 是纸白底深字，nixie 是深底橙字，rain 是深底白字。
   证据：`rain-preset-var.png`、`rain-params-expanded.png`；放大件 `_tmp-rain-var-inputs.png`、`_tmp-rain-fs-row2.png`。

### overflow:hidden 有没有裁掉卡片内容

5. **面板正文没看到被裁。**
   现象：皮肤页的卡片（标题 + 描述 + 预览缩略图）、参数页的折叠组、特效页的开关行、模型页的条目卡，都完整落在面板宽度里；缩略图是圆角方块，四边都在卡内。
   读数：宽屏 rain「面板内溢出=0 页面溢出=0」「皮肤面板|drop=419>419」。
   证据：`rain-skin.png`、`rain-params.png`、`rain-fx.png`、`rain-preset.png`。

6. **唯一实测到的裁剪是 pre置设置面板的 tab 行**（见下一条），不是卡片。这条是「有没有被裁」的真实答案。

### 预设设置面板（rain）

7. **tab 行被右边缘硬切，且没有任何「还能往右滚」的提示。**
   现象：7 个 tab 排一行，到第 4 个「😀 角色塑造」时贴着面板右边缘被截；界面上没有滚动条、没有左右箭头。
   读数：宽屏 rain「tab行: 条数=7 不同行数=1 轨道419/768(可横滚) 面板内溢出=0 页面溢出=0 tab轨=0/768 可视419」。
   证据：`rain-preset.png`；放大件 `_tmp-rain-preset-panel.png`（能看清「角色塑造」正好压边）。

8. **模型页长名字条目卡被换行撑高。**
   现象：DS/GLM底部破限、DS/GLM强强 在卡里占两行（宽屏），卡片跟着变高；这三张卡是 disabled 状态，名字是暗灰字压深底，比较费眼。
   读数：宽屏 rain「换行样本 DS/GLM底部破限=2行 DS/GLM强强=2行」；`aria-pressed/disabled` 从可访问性树读到这三张是 `[disabled]`。
   证据：`rain-preset.png`、`_tmp-rain-preset-panel.png`。

9. **设置变量页底部两张空壳卡同 memo/nixie。**
   现象：「🧩 清空变量」「🧩 标签格式」两张并排，卡里只有标题 + ⓘ，卡身没有内容，高度约为上面变量卡的一半。
   证据：`rain-preset-var.png`；放大件 `_tmp-rain-var-lower.png`。

### 皮肤管理面板（rain）三页

10. **参数页：四个折叠组只占左边一小截，面板下半屏整片空白。**
    现象：通用(1) / 水汽(1) / 面板(1) / 光照(1) 四行，每行是「▸ + 组名 + 右端计数小块」，从计数块到行尾整片空；四行下面大约四成面板高度是空的（只有水珠装饰）。这是三套皮肤共有的形态，rain 因为组更少、空得更明显。
    证据：`rain-params.png`、`_tmp-rain-params-panel.png`。

11. **特效页：开关和说明文字隔了约 300px；但 rain 的开/关**不只**靠颜色区分。**
    现象：五行特效（玻璃起雾/水珠凝结/雨滴敲击/雨痕滑落/车灯光斑），左边标题 + 一行说明，开关挤在右端。开的那三行是**橙色药丸、圆点在右**；关的两行是**灰色药丸、圆点在左**——形状一样但圆点位置不同，比 memo/nixie 的方块开关好认。
    证据：`rain-fx.png`；放大件 `_tmp-rain-fx-panel.png`、`_tmp-rain-fx-switches.png`。

12. **皮肤页：段控三组的右边界参差。**
    现象：「显示」区里 明暗（跟随皮肤/暗色/亮色）、动效（完整/克制/关闭）、密度（紧凑/舒适/宽松）三组右对齐不一致，「跟随皮肤」那组比另两组短约 12px，整块收尾是斜的。选中项是橙色下划线，不是橙色填充框（和 nixie 的选中样式不同）。
    证据：`rain-skin-bottom.png`。

13. **皮肤页更下面还有一大堆卡片（色块/记事本/辉光管/恋雨/奈亚子的TRPG），缩略图各自渲染自己的皮肤材质**——rain 卡片上的预览是深色玻璃面，记事本卡片上是纸白面。
    证据：`rain-skin.png`、`rain-skin-bottom.png`、`narrow-rain-skin.png`。

## 二、窄屏 375×812（三套皮肤）

统一结论先说：**三套皮肤的面板在窄屏都变成贴底抽屉，铺满宽度、占约 78% 屏高，底部贴住视口下沿；没有出现面板被上下裁掉；tab 行溢出被硬切；条目卡没有挤破，但名字被切成三行断词。**

14. **贴底抽屉，不是浮层。**
    现象：面板铺满整个宽度，从屏幕下方伸上来，底部与视口下沿齐平，顶部留出约 179px 能看到后面的页面。
    读数（memo，页面自己报的）：`[皮肤] 几何(打开) 视口=375x812 sheet=true 单栏=true layout=sheet 面板=[0,179,375,633]`；预设面板 `panel|视口375x812 layout=sheet 舞台=0,0,375,812 drop=-2,169,380,638`。
    证据：`narrow-memo.png`、`narrow-nixie.png`、`narrow-rain.png`（三套皮肤都是同一个形态，皮肤只换材质）。

15. **预设面板比视口宽 5px，左右各顶出去约 2px。**
    现象：视口 375 宽，抽屉的落位是 left=-2、宽 380，于是文档比视口宽 2px。肉眼看不出，但读数上是实打实的。
    读数（memo）：`drop=-2,169,380,638`、`页面溢出=2`；三套皮肤顶栏里的面板读数都是 `0,180,377,636`（皮肤面板本身），差别来自皮肤面板与它内部 .kami-drop 的边框。
    证据：读数，无截图为证（2px 在图上不可见）。

16. **tab 行溢出、被右边缘硬切，同样没有滚动提示。**
    现象：第 4 个 tab 只剩半个字——nixie 是「😀 角」被切，rain 是「😀 角色」被切；memo 那张里 emoji 也已经压到边。
    读数（memo）：`tab行: 条数=7 不同行数=1 轨道376/825(可横滚) 面板内溢出=0 页面溢出=2 tab轨=0/825 可视376`。
    证据：`narrow-memo.png`、`narrow-nixie.png`、`narrow-rain.png`。

17. **条目卡没挤破，但名字被切成三行断词。**
    现象：卡片网格在窄屏仍然是 3 列；「DS/GLM底部破限」被切成 `DS/GL / M底部 / 破限`，卡片随之变高。文字没有溢到卡外，是换行撑高。
    读数（memo）：`可见网格[319px→3列 卡101x97 间距8]`、`换行样本 DS/GLM底部破限=3行 DS/GLM强强=2行`。
    证据：`narrow-nixie.png`、`narrow-rain.png`、`narrow-memo.png`。

18. **面板内部没有横向溢出，也没被内容撑宽。**
    读数（memo）：`面板内溢出=0`、`皮肤面板|drop=374>374`。
    证据：读数；图上看不出溢出。

19. **抽屉底部可见，没有被截掉半截。**
    现象：皮肤管理抽屉底部的页脚「记事本/辉光管/恋雨 · 动效 … · 密度 … · 特效 N」在截图里都看得见，页脚下面就是页面；预设设置抽屉底部的页脚「卡片 28 · 条目 103 · 锁定 16 不在面板 · 写入 0 次」同样可见。
    读数（memo 预设面板）：底边 169+638=807 < 812；皮肤面板 179+633=812，正好贴底。
    证据：`narrow-memo-skin.png`、`narrow-nixie-skin.png`、`narrow-rain-skin.png`、`narrow-memo.png`、`narrow-nixie.png`、`narrow-rain.png`。

20. **抽屉内部布局也跟着变窄屏形态，标题会折行。**
    现象：宽屏下「皮肤管理 🎨恋雨」是一行；窄屏下变成「皮肤管理」一行、「🎨恋雨」下一行。预设面板的版本号「卡密预设0.9-260917-2」也从标题右边挪到下一行。
    证据：`narrow-rain-skin.png` 对比 `rain-skin.png`；`narrow-rain.png` 对比 `rain-preset.png`。

## 三、与既有报告的差异或推翻

1. **rain 一节从「整节未完成」补全**：面板 3 页 + 预设面板 2 页都有截图和读数了；「面板本体是否半透明」「数字框是否黑底黑字」这两条点名怀疑，结论都是**没问题**（面板 93% 不透明，页面读不进来；数字框深底白字，清晰）。
2. **窄屏一节从「未完成」补全**：面板确实是**贴底抽屉**，四套检查（贴底/被裁/tab 溢出/卡片挤）全部有结论。既有报告里「窄屏无结论，不做推测」的空白到此为止。
3. **「特效页开关开/关只靠颜色区分」这条在 rain 下不成立。** 既有报告的证据是 `memo-fx.png`、`nixie-fx.png`，结论本身没错；但 rain 的开关是药丸形，**开=橙色且圆点在右、关=灰色且圆点在左**，圆点位置就是第二重线索。别把这条当成三套皮肤共有。
4. **「数字输入框没有黑底黑字」这条，rain 是第三种配色。** 既有报告写 memo 纸白底深字、nixie 深底橙字；rain 是深底（rgb(22,27,28)）近白字（rgb(230,226,216)）。三套都可读，但别只按前两种描述。
5. **「tab 行 轨道419/825」不是跨皮肤固定的数**。1280 宽下 rain 实测是 `轨道419/768`；375 宽下 memo 实测是 `轨道376/825`。轨道内容宽会随宽度（字号）变，引用时要说清在哪个宽度上量的。
6. **顺带一条方法学提醒（不是结论）**：rain 面板底色 rgb(22,27,28) 和预览台页面底色 rgb(11,11,14) 非常接近，肉眼看这面板会「看小一圈」——我第一次看截图就把它估窄了约 60px，用像素扫描才确认面板实际落在 CSS 415–833，和读数 420,72,420,560 一致。以后拿 rain 的截图判几何，别只靠眼睛。

## 四、方法与限制

- **截图时效**：预览台每张截图前都补了一次无害输入（正文滚轮 deltaY=1），所以图是当前状态。
- **375 宽度怎么来的**：`browser_session start width=375 height=812` 会被浏览器窗口最小宽度钳住，页面实际只拿到 **478×681**，不满足 375。最终改用 `browser_assist emulate width=375 height=812 mobile=true`，页面自己报 `视口375x812 mm768=true`，才算真窄屏。
- **模拟会掉**：每次页面导航之后模拟会失效，截图只剩窗口可见区（863×1120 那种半截图）。所以每轮都是「导航 → 等就绪 → 重新 emulate → 补滚轮 → 截图」。`narrow-memo-skin.png` 我重拍过一次就是这个原因。
- **没做的**：rain 的聊天前端（思维链 / 行动选项两张卡片）本轮没看，它不在这次的任务清单里；nixie、rain 的窄屏读数没有逐条从控制台取回，那两条的窄屏结论里凡是数字我都标了是 memo 的读数，其余靠截图判读。
- **真机酒馆 localhost:11451 一次都没看。**
