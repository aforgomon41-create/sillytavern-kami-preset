## 一、这是什么项目

「卡密预设」：一套运行在 **SillyTavern 1.18 + 酒馆助手（Tavern Helper / JS-Slash-Runner）4.9.5** 上的 AI 角色扮演预设。

| | |
|---|---|
| 工作区 | D:\SillyTavern\卡密预设制作 |
| 真机酒馆 | http://localhost:11451/ |
| 酒馆数据目录 | D:\sillytavern-software\SillyTavern Launcher GUI\data\st_data\default-user\（预设放 OpenAI Settings\） |

**用户是远程的**：通过 Agentanywhere 使用 DSH，**看不到 subagent，也不能操作浏览器**。他的验证方式只有一种：
**下载构建产物 → 导入手机酒馆实测**。所以：结论必须由我们给证据；交付时必须明确说「下载哪个文件」。

18. **输入框对比度**（用户真机两轮反馈才修对，**根因有两层**）：
    - **真凶是用户自己的自定义 CSS**：酒馆 `settings.json → power_user.custom_css`（215-222 行）给
      `input[type=text/number/…]` 上了 `background-color: var(--ui-color-sec) !important` 与同色描边，
      由 `power-user.js:1147-1157` 注入成 `<style id="custom-style">`；深色主题下 `--ui-color-sec` ≈ rgb(47,47,45)。
      **所以两块面板的数字框都是黑底** —— 这也解释了用户最初说"皮肤管理参数调整也有这个毛病"。
    - 第二层：皮肤头部 `.kami-root input { color: inherit }` 把输入框文字压成 `--kami-fg-dim`（`-68` 里是 `--kami-fg` 的深字）
      → **深底压深字**。修复前真机实测对比度只有 **2.24:1**。
    - 修法 = 每套皮肤一条 **panel 作用域**的 `input.kami-number` 规则（**不带面板 id**，两块面板生成的是同一个
      `<input class="kami-number">`，一条规则同时命中）：**显式写 background-color + color + color-scheme
      （浅色皮肤 light、深色皮肤 dark），并且都要 `!important`** —— 不带就赢不了用户那条自定义 CSS。
      修后（真机截图逐像素实测）：memo 16.05 / nixie 7.17 / rain 13.70 / trpg 12.28 / 兜底 13.21。
    - **验证教训**：`getComputedStyle` 的 backgroundColor 为**透明**时，"往上层找背景"算出来的对比度是**假读数**
      （上一轮就这么被骗出 16:1）。修前后必须确认背景是**显式的非透明值**，并且**在真机上读**
      （预览台没有酒馆的深色样式与用户自定义 CSS，复现不出来）。
    - 遗留：同一条自定义 CSS 也给 `input[type=range]` 上了深漆（🎨参数 tab 的滑杆轨道仍是深的，本轮未动）；
      它的描边 `!important` 会盖掉皮肤描边（我们已在 panel 规则里用 `!important` 收回；rain 的"一条水线"会被补出三条边）。

## 五、必须知道的硬事实（都是踩出来的）

1. **酒馆正则引擎不是 native String.replace**（public/scripts/extensions/regex/engine.js:419-445）：
   回调 + replaceAll 只认 $n 与 $<name>，**从不把两个连续美元号还原成一个**，末尾还会跑 substituteParams（吃掉双花括号宏）。
   → 前端文档里不得出现美元号后跟数字、不得做美元号双写转义、不得出现双花括号。verify-frontends.mjs 强制这条。
2. **部署是两步**：复制产物到 OpenAI Settings **之后必须在界面里把它选为当前预设**，
   否则 settings.json 的 preset_settings_openai 与 preset_allowed_regex.openai 不更新，新产物等于没上。切换路径见真机验证备忘。
3. **消息 iframe 的高度**只由酒馆助手的 ResizeObserver(body) 驱动；实测可靠，前端不需要自己 syncHeight。
   （2026-09-21 补：这句话的意思是「前端**不许自己维护高度**」。**启动期用 body.scrollHeight 兜一次是允许的**，
   登记在 [皮肤契约](皮肤契约.md) §9.5；行动选项前端原先自己挂的那枚 ResizeObserver 属重复劳动，已按此删除。）
   但预览台是同文档内嵌，RO 有时不触发，已加 1 秒重新量高兜底（只重新量、不改被测行为）。
4. **皮肤选择器必须以 html[data-kami-skin=...] 原样开头**（特效写成 …[data-kami-effects~=...]），lint 会拦；
   这是面板「皮肤预览卡片」用机械替换生成副本的前提（现在预览卡已改成 iframe，但前缀规则仍然强制）。
5. **写文件时反斜杠转义不可靠**（s 会被吞成 s、
 会变成真换行、$ 会被吃）。写脚本要么避免反斜杠，要么用占位符再还原。
6. **浏览器多人协作**：每人一个端口 + 自己的会话，所有 browser_* 调用显式带 session；真机酒馆标签页同一时间只允许一人借用；
   会话上限 5，注意清理僵尸会话；**坐标点击会被「Agent 正在控制」浮标挡住**（用 focus + press Enter 代替）；
   **截图是异步合成的、会返回上一帧**（结论以 observe 与预览台 #diag 读数为准）。
7. **预览台曾经「太贴心」**（属性一变就重测高度、用 native 语义展开文档），两次把真机才有的 bug 掩盖掉 —— 现在已与真机对齐。
8. **两个皮肤作者陷阱**（已写进契约 §6.5）：.kami-shell 与 .kami-surface 常是同一元素，写 background 简写会把纸面纹理重置；
   在 .kami-root/.kami-surface 这一级写定位会影响面板（平台层已抬特异性兜住，但别去踩）。

9. **第 5 条的适用范围被实测修正了**（重要）：`write` 工具（harness 的文件写入工具）是**逐字节忠实**的 ——
   本轮用探针逐行验过：`$`、`$$`、`$1`、`$<name>`、`${braces}`、`\s`、`\n`、`\\`、`{{char}}`、`{{//注释}}`、
   单双引号全部原样落盘。真正不可靠的只有**通过脚本 / pwsh 内联命令改文件**
   （`pwsh` 内联命令里的双引号会被吞掉，`node -e` 会直接语法错误 —— 本轮踩到过）。
   契约文档当初就是这么被写坏的。
