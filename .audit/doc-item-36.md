36. **★ 想靠"标签"定位内容时，先查酒馆的清洗白名单**（2026-09-26，正文美化 v2 踩出来的）：

    `<content>` 之所以能当判据，是因为**酒馆自带 DOMPurify 的默认白名单里字面就有 `content` 这个名字** → 它会作为真元素
    活到 `.mes_text`，我们在 DOM 里找得到它。而白名单外的名字（例如 `<正文>`、`<narr>`）会被 showdown 转义或被剥掉只留内容，
    **DOM 里根本认不出边界**。所以任何"按标签定位"的设计，第一步都是查白名单；白名单外的只能退回**原始文本指纹对位**，
    并且必须做"**对不上就一个节点都不动**"的保险。另外：**用户输入的标签名永远不要拼进 CSS 选择器**（用
    `getElementsByTagName` 之类的接口），否则一个引号或空格就能把选择器拼坏。

37. **★ 用户的自定义 CSS 与我们的全局层：同特异性下「后注入者赢」**（2026-09-26，酒馆消息区美化）：

    酒馆把用户主题 CSS 通过 `power-user.js` **运行时**追加到 head，所以它可能排在我们注入的 `<style>` 之后 ——
    同特异性下**用户赢**。结论：**不要去打 `!important` 战争**，只挑用户通常不设的属性下手（例如圆角与间距），
    并把冲突点列成清单交用户定；两级都要能看：用户赢时用他自洽那套，我们赢时用皮肤配套的底色+字色，
    避免"底翻了字没翻"。

38. **★ 正文包裹层禁写 `overflow` / `position` / `pointer-events` / `z-index`**（2026-09-26，已入契约 §9.7）：

    正文里**并排着**插件插进来的按钮、HTML 美化条目的卡片、两个既有前端的 iframe。包裹层一写 `overflow:hidden`
    就可能把它们裁掉一截，一写 `position`/`z-index` 就可能吃掉点击或盖住它们。所以这一层只许写排版类属性
    （间距、块级、`overflow-wrap`），颜色归皮肤。**回归时必须含「模拟插件按钮真点击回调 0→1」这一条。**
