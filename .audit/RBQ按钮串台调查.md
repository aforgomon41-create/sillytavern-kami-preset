# 「点插件的生图按钮，却开我们的皮肤管理面板」调查与修复

日期：2026-09-24 · 排查与修复：派活方（主智能体）
相关文件：`src/scripts/10-脚本按钮.js`（修）、`src/scripts/20-反截断.js`（同一类风险一并修）、
`test/harness/preview.html`（新增 `?rbq=1` 复现探针）、`test/harness/index.html`（新增两条回归用例）、
`收到的文件/RBQ-Draw-index.js`（插件本体存档）、`收到的文件/smart-draw-trigger.js`（子插件存档，990 KB）。

## 一、结论（先行）

**根因：按钮中转站的「点击兜底」在整页范围内按「文字前缀」认按钮，而皮肤管理的登记名就是一个 🎨。**

第三方插图插件 RBQ-Draw 的子插件「智能生图触发器 (Smart Draw)」v6.0.64 往聊天页插了一枚按钮：

```html
<button id="rbq-sdt-manual-submit" class="menu_button" type="button">🎨 生成</button>
```

（源码：`RBQ-Draw-Plugins / plugins/smart-draw-trigger.js`，文案与类名逐字照抄）

它的类名含 `button` → 命中我们 `isButtonish()`；文字 `🎨 生成` **以登记名 `🎨` 开头** →
命中 `matches()`（`text.indexOf(name) === 0`）。于是中转站在**捕获阶段**把它当成我们自己的按钮：

```js
ev.stopImmediatePropagation(); ev.preventDefault(); fire(🎨);   // 皮肤管理面板打开
```

插件的按钮**永远收不到这次点击** —— 用户看到的就是「点生图按钮，开的却是皮肤面板」。
关掉皮肤管理 → `🎨` 这个登记名不存在了 → 现象消失（与用户观察一致）。

## 二、复现（预览台，确定性）

`preview.html` 新增 `?rbq=1`：按子插件源码原样注入它的三种按钮（悬浮球 / 悬浮菜单项 / 消息内「生成图片」），
**外加真凶那一枚 `🎨 生成`**，并挂一条**插件自己那一侧**的冒泡监听做对照。

- **修复前**：点 `🎨 生成` → 控制台 `[按钮] 点击 🎨 → 已调用登记方 click()` + `[皮肤] 几何(打开) … open=1`，
  插件侧监听**一次都没响** → 串台复现 ✓
- **修复后**：同一次点击 → `RBQ探针|插件侧收到了点击：rbq-sdt-manual-submit`，
  且**没有** `[按钮] 点击 🎨` → 插件拿回了自己的点击 ✓
- 同一轮里点我们自己 QR 条上的 `[data-hub-btn="🎨"]` → `[按钮] 点击 🎨` + 面板打开 ✓ 我们的按钮照常。

## 三、机制细节（为什么只有皮肤管理中招）

- 中转站里**绘制侧**本来就有收口：`findNode()` 只在 `.qr--button-label / .qr--button / #qr--bar button /
  [data-qr-button]` 里找我们的按钮。
- 但**点击兜底侧没有**：`clickHandler` 从点击目标往上爬 6 层、只按「宿主自己的文字以登记名开头」认人，
  **搜索空间是整页**。两条路的搜索空间不一致，就是这个 bug 的形状。
- 为什么是皮肤管理：它的登记名是**单个 emoji `🎨`**（`30-皮肤管理.js:1092`，标签是 `'🎨' + 皮肤按钮字`），
  是最容易被第三方按钮前缀命中的名字；其它登记名（`🧭引导` / `🌟卡密预设` / `📜 压缩`）都带汉字，碰上的概率低得多。
- `20-反截断.js` 里有一份**独立实现**的同类兜底（它要能单独分享），同样的收口也缺（它的 `ownMatches` 多要求
  一个空格边界，只是更难命中，不是免疫）。

## 四、修复

两处都补上「**只在按钮条里认人**」的收口（与绘制侧同一套选择器），第三方按钮一律不碰：

- `src/scripts/10-脚本按钮.js`：新增 `HUB_SPACE` / `inHubSpace()`，`clickHandler` 里
  `if (!inHubSpace(host)) return;`。
- `src/scripts/20-反截断.js`：新增 `OWN_SPACE` / `ownInSpace()`，`ownButtonHost()` 里加上同样的判断。

保留原有语义：带我们自己标记（`data-hub-btn` / `data-anti-btn`）的按钮仍然直接认；
按钮条里的按钮即使标记被 ST 重绘掉，仍可按标签前缀认出来（兜底存在的意义）。

## 六、遗留与后续

- 未在**真机**装这套插件复现（插件是完整 ST UI 扩展，会改动用户的酒馆环境）；但复现探针里的按钮
  markup 与文案是**从子插件源码逐字抄的**，机制链条（捕获阶段前缀匹配 → stopImmediatePropagation）是确定的。
- 插件后续版本若改了按钮文案（比如不再以 🎨 开头），这个具体碰撞会自然消失，但**收口本身必须留着** ——
  它挡的是一整类「第三方按钮被短前缀登记名吃掉」的问题。
- 同类风险的通用教训已写进 `docs/交接.md` §五：**点击兜底的搜索空间必须与绘制侧一致；
  登记名不要用单 emoji 这种超短前缀。**
