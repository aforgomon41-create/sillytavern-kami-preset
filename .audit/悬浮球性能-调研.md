## 第一步：拖动链路（读完 80-状态栏.js 全文）

**结论先行：每个 pointermove 都是「同步读窗口尺寸 → 同步写 3 个 CSS 变量到全屏舞台 → 触发重排+重绘」，没有 rAF 节流，且位置用的是 left/top 而非 transform。**

证据（D:\\SillyTavern\\卡密预设制作\\src\\scripts\\80-状态栏.js）：

1. move 处理器原文（约 L214-224）：
```
    ball.addEventListener('pointermove', function (ev) {
      if (!drag || ev.pointerId !== drag.id) { return; }
      var dx = ev.clientX - drag.sx, dy = ev.clientY - drag.sy;
      if (!drag.moved && Math.abs(dx) + Math.abs(dy) < MOVE_SLOP) { return; }
      drag.moved = true;
      geom.x = drag.ox + dx;
      geom.y = drag.oy + dy;
      clampGeom();
      paint();
    });
```
   每一次 move 都无节流地调用 clampGeom() 与 paint()，没有 requestAnimationFrame 合并。

2. clampGeom 每次读窗口尺寸（约 L139-148）：
```
  function viewW() { try { return HOST.innerWidth || HDOC.documentElement.clientWidth || 0; } catch (e) { return 0; } }
  function viewH() { try { return HOST.innerHeight || HDOC.documentElement.clientHeight || 0; } catch (e) { return 0; } }
  function clampGeom() { ... var w = viewW(), h = viewH(), s = geom.size; ... }
```

3. paint 把位置写进舞台（全屏 fixed 元素）的 CSS 变量（约 L150-157）：
```
      stage.style.setProperty('--kami-ball-x', Math.round(geom.x) + 'px');
      stage.style.setProperty('--kami-ball-y', Math.round(geom.y) + 'px');
      stage.style.setProperty('--kami-ball-size', Math.round(geom.size) + 'px');
```

4. 球的位置走 left/top（布局属性，非合成属性），不是 transform（约 L120）：
```
    '#' + PANEL_ID + ' .kami-ball{position:absolute;left:var(--kami-ball-x,0px);top:var(--kami-ball-y,0px);...}'
```

5. 图片带 filter（每帧重绘开销大户）（约 L123）：
```
    '#' + PANEL_ID + ' .kami-ball-img{...filter:drop-shadow(var(--kami-ball-shadow,0 2px 6px rgba(0,0,0,.30)));}'
```

6. 监听方式：pointermove/pointerup/pointercancel 均未传第三参（默认 passive=false）；pointerdown 里 setPointerCapture + preventDefault，球上 CSS 有 touch-action:none（约 L135、L168-172）。touch-action:none 这一条是对的。

7. 位置记忆写回时机：**已经是「抬起才存」** —— saveVars() 只在 endDrag（pointerup/cancel）里调用（约 L232-236），SAVE_DELAY=300ms 防抖（L44、L106-117）。拖动过程中不写酒馆存储，此项不卡。

3. 交接线索①「ResizeObserver 兜底核对最坏等 8 秒」说的是 d20 装饰模块（.audit/d10装饰模块.md L23），与球无关；球用的是 HOST resize 监听（80-状态栏.js L302-303）。

## 第五步：根因排序（最可能造成「不跟手」的前三条）

**① 每一次 pointermove 都同步做「读窗口尺寸 + 写 3 个 CSS 变量」，没有 rAF 节流**（80-状态栏.js L222-231 → L229-230 clampGeom/paint → L165-172 setProperty ×3；全文 rAF 0 次）。iPhone 触摸采样率高于屏幕刷新率，一帧内可能跑多次 handler、写多次样式；样式失效后的重排重绘全部排在主线程，酒馆主页面一忙（消息 iframe、8 秒 sweep、其它脚本）就跟手变差。这是机制上最直接的「不跟手」来源。

**② 位置走 left/top（布局属性）而不是 transform，且移动的 img 挂着 filter:drop-shadow**（L121 的 left:var(--kami-ball-x)/top:var(--kami-ball-y)；L124 的 filter:drop-shadow；产物核对 transform 0 次、left:var 1 次、filter 1 次）。left/top 每帧必走主线程 style→layout；transform 只更新合成器。drop-shadow 让这颗 img 成为每帧需要滤镜重绘的层，中低端 iPhone 上掉帧明显。同样写 CSS 变量的面板（40 号 L1283-1284、30 号 L855-856）被拖动元素上没有 filter，所以面板同样写法却不卡 —— 差别就在这两条。

**③ 写样式的目标是无条件铺满视口的 fixed 舞台**（L176-190 build 里 position:fixed;inset:0 + z-index:29000；写点是 L165-172）。自定义属性写在祖先上，失效范围是整棵子树，且 setProperty 是纯主线程操作，无法与合成器并行。叠加球上没有任何 will-change/层提升提示，每帧都要重新判定合成。

已排查不成立的怀疑项（写清楚免得下轮重复查）：
- 位置记忆写回：**已经是抬起才存**（L232-243 endDrag 才 saveVars；SAVE_DELAY=300ms 防抖 L44/L106-117），拖动中零写盘 → 不是卡因。
- 被动监听/触摸黏滞：touch-action:none 已正确挂在球上（L121），pointermove 未传 passive 但默认 false 且 move 里不需要 preventDefault → 不存在被动监听问题。
- skin 耦合、MutationObserver 连带：见第四步，不成立。
- 拖动期间的定时器轮询：无。

## 第六步：最小改动方案（只改 src/scripts/80-状态栏.js，共 4 处；不新增类名/令牌）

**改动 1（必做）：pointermove 加 rAF 节流，一帧最多写一次样式**（L222-231）。pointermove 只更新 geom 并请求一帧；clamp+paint 挪进 rAF 回调。要点：
- rAF 必须向**宿主窗口**要：`var raf = HOST.requestAnimationFrame ? HOST.requestAnimationFrame.bind(HOST) : requestAnimationFrame;`（酒馆助手把脚本跑在隐藏 iframe 里，不可见 iframe 的 window.requestAnimationFrame 不触发；面板/heartbeat 类项目先例：本脚本全文没有 rAF 用法可抄，但事件都显式走 HOST，同一套取法）。
- endDrag（L232-243）与 teardown 里 cancelAnimationFrame；抬手的最终位置仍由 endDrag 里既有的 clamp+paint 兜住，不依赖 rAF。
- paint（L165-172）顺手跳过 size 未变时的写入，每帧从 3 次 setProperty 降到 2 次。
- 参考写法（保持本项目 var/ES5 风格）：
```
    var rafId = 0;
    ball.addEventListener('pointermove', function (ev) {
      if (!drag || ev.pointerId !== drag.id) { return; }
      var dx = ev.clientX - drag.sx, dy = ev.clientY - drag.sy;
      if (!drag.moved && Math.abs(dx) + Math.abs(dy) < MOVE_SLOP) { return; }
      drag.moved = true;
      geom.x = drag.ox + dx;
      geom.y = drag.oy + dy;
      if (!rafId) {
        rafId = raf(function () {
          rafId = 0;
          if (!drag) { return; }
          clampGeom();
          paint();
        });
      }
    });
```

**改动 2（强烈建议，一行 CSS）：left/top 改 transform**（L121）。把 `.kami-ball` 的 `left:var(--kami-ball-x,0px);top:var(--kami-ball-y,0px)` 改成 `left:0;top:0;transform:translate3d(var(--kami-ball-x,0px),var(--kami-ball-y,0px),0);will-change:transform;`。几何令牌纪律不变（仍走 --kami-ball-x/-y），verify-status-ball.mjs 第⑤组只 grep 变量名与 setPointerCapture/touch-action:none，全部不受影响；契约 §9.10 L1206 枚举了「位置与尺寸读令牌」，改后字面仍成立，但建议顺手把契约那一行的 left/top 描述改准（文档改动，需 owner 授权，不在本次只读范围）。

**改动 3（可选，先不动）：filter:drop-shadow 每帧滤镜重绘**（L124）。改 1+2 后若真机仍卡再动它；两个方向都有代价：换成按钮上的 box-shadow+border-radius:50% 会改变外观（icon 有硬切边，圆角盒会露棱角，且用户 2026-09-30 明说 icon 截线「先不改了」）；拖动期间临时摘 filter 视觉可感知。都要用户拍板，本轮只记录。

**明确不改**：位置记忆时机（已正确）、touch-action:none（守卫钉着）、setPointerCapture（拖动必需）、监听 passive 设置（无需）。

## 第七步：验收口径（预览台怎么量）

- 球在预览台是装好的：test/harness/preview.html L1085-1088 启动即 loadScript('/dev/80-状态栏.js')（?nostatus=1 不装）。PC 没触摸能力，用**合成 PointerEvent** 模拟拖动：对 document.querySelector('#kami-status-ball .kami-ball') 连续 dispatch pointerdown/pointermove×N/pointerup（带 clientX/clientY/pointerId）——setPointerCapture 对合成事件抛错但被 try 吞掉（L219），move 监听直接挂在球上，合成事件可达。
- 三个可量化读数：
  1. **每帧写入次数**：console 里猴补 CSSStyleDeclaration.prototype.setProperty 打时间戳，在同一 rAF 周期内派发多次 move —— 改前次数=move 次数，改后 ≤1。这是「节流生效」的直接读数。
  2. **每帧主线程耗时**：DevTools Performance 录一段合成拖动，看每帧 Recalculate Style/Layout/Paint 占比；改 2 之后帧里应只剩 Composite（transform 生效的判据）。
  3. **位置正确性**：KamiStatusBar.status() 的 x/y 与球 getBoundingClientRect() 对得上；拖到屏外再缩窗口，clampGeom 仍把它夹回（证明 transform 版没破坏夹取）；拖完约 300ms 后 getVariables({type:'script'}).kami-statusbar 有值（证明 saveVars 没被 rAF 改动弄丢）。
- ⚠️ 两个预览台局限：① /dev/ 路由不展开图标占位符（test/harness/server.mjs L120-143 没有 KAMI_ICON_STATUS 处理），预览台的球没有图，filter 开销在预览台测不出来，只能在真机或 /built/80-状态栏.js（读最新产物，带图标）下看；② #diag / #pdiag / #mdiag / #gdiag / #iosdiag 都没有球相关探针（#diag 是文案/面板/骰位探针，L2005-2307），要量球只能在 console 里现搭，没有现成读数可抄。

## 第八步：风险清单

1. **rAF 取错窗口 = 完全不动**：隐藏 iframe 的 requestAnimationFrame 不触发（Chrome 对不可见跨文档 iframe 不调度 rAF）。必须 HOST.requestAnimationFrame，且 endDrag 的 clamp+paint 保持兜底，否则球会「停在最后一帧」。
2. **transform 版与位置记忆**：--kami-ball-x/-y 语义不变（仍是左上角坐标、仍是 px），clampGeom/读写变量都不动，「刷新/换聊天在原地」不受影响；但 transform 会在球上建包含块，球内只有 img，无子元素依赖，安全。
3. **与 8 秒兜底核对的关系**：sweep 只动 iframe 与皮肤属性（第四步），与本轮改动无交集；但改 2 后若以后皮肤想给球写 transform 覆盖，会与脚本的内联 transform 打架 —— 契约 §4.6 L714 已禁止皮肤给球写 position/left/top/尺寸，建议同时补一句 transform（文档侧，需 owner）。
4. **守卫 verify-status-ball.mjs**：⑤要求 setPointerCapture、touch-action:none、--kami-ball-* 三变量、var(--kami-ball-shadow 都在 —— 改动 1/2 全部保留；③要求 ICON_STATUS data URI 逐字节一致 —— 不要动图标。改完必须 node build/build.mjs 全绿 + node build/verify-status-ball.mjs。
5. **build 纪律**：只改 src/scripts/80-状态栏.js，改动会经 build/kami-doc.mjs 展开进产物；产物要重新构建并交付用户导机（用户是远程，只能下载产物实测）。
6. **契约文档漂移**：§9.10 L1206 的枚举未同步时，下一轮审计可能按旧清单误报 —— 列入交付说明即可。
