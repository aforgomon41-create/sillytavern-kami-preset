## 〇、结论先行

1. **真机上没有"重置列表符号"的全局规则**。酒馆 `style.css` 里 4 条 `list-style` 全部 scoped 到酒馆自己的 UI 类；Tailwind 预科（`st-tailwind.css`）与移动端样式表 0 命中。而且思维链前端跑在**隔离的 srcdoc iframe** 里，酒馆页面 CSS 根本不会级联进去。所以「外层把列表点重置没了」这个假设**不成立**。
2. **这 6 套在"干净环境"和"注入全局重置 `ul,ol{list-style:none}` 的模拟环境"下，列表点全部正常出现**（探针读数逐套列在下面）。皮肤选择器特异性高于任何全局重置，压不掉。
3. 问题 1 唯一真实缺口：**rain 的嵌套列表没有层级区分**（`ul ul` 与 `ul` 同为 `square`、`ol ol` 与 `ol` 同为 `decimal`）。已修：二级无序换 `circle`、二级有序换 `lower-alpha`、嵌套 marker 压淡。
4. 问题 2 根因是**三处** `white-space:nowrap`：结构层兜底 `base.css:227`、`memo` 的 `.kami-sub`（还带 `text-overflow:ellipsis`+`overflow:hidden`）、`rain` 的 `.kami-sub`。已在结构层 + memo + rain 三处修好，**只放开"字段标签下的说明"这一处**，标题栏/页脚/参数单位的单行 `.kami-sub` 原样保留（有读数为证）。

## 二、问题 2：特效页说明换行

### 2.1 根因

`30-皮肤管理.js` 的 `renderFxPane()`（约 1049-1055 行）建的是 `.kami-field > .kami-field-label > .kami-sub`（说明文字）。`.kami-sub` 这个类在多处被当成"单行短文本"用了 `white-space:nowrap`：

- **结构层兜底** `src/skin/base.css:224-228`：`.kami-sub { …; white-space: nowrap; }`（皮肤管理没运行时生效）。
- **memo** `skin.css:365-375`：`.kami-sub { …; overflow:hidden; text-overflow:ellipsis; white-space:nowrap; }`。
- **rain** `skin.css:556-563`：`.kami-sub { …; white-space: nowrap; }`。

这三处让"字段标签下的说明长文"在 375px 挤一行、被截断。其余 3 套（grokbot/nixie/manga/senren）的基础 `.kami-sub` 没有 nowrap，本来就能换行。

> 架构澄清：`base.css` 是**兜底皮肤**，作用域 `html:not([data-kami-skin])`，有皮肤运行时整体失效。所以 fx 页在**选中皮肤下**的截断，直接根因是各皮肤自己的 `.kami-sub`；`base.css:227` 是兜底路径的同一 bug、也是这套 nowrap 写法的源头。两处都修。

### 2.2 修法（结构层立规矩 + 两套皮肤各自清截断）

一律用**已登记类名**、只引既有令牌、不新增类名/令牌、不写 JS：

1. **结构层 `src/skin/base.css`**（在"表单控件"节，`.kami-field-value` 规则后追加）：
   ```css
   html:not([data-kami-skin]) .kami-root[data-kami-comp="panel"] .kami-field:has(.kami-sub) { align-items: flex-start; }
   html:not([data-kami-skin]) .kami-root[data-kami-comp="panel"] .kami-field .kami-field-label .kami-sub {
     display: block; margin-top: 3px; line-height: 1.5; white-space: normal; overflow-wrap: anywhere;
   }
   ```
   选择器精确锁 `.kami-field .kami-field-label .kami-sub`（= fx 说明），**不碰**标题栏/页脚/参数单位的 `.kami-sub`。
2. **memo `skin.css`**（`.kami-field-value` 规则后追加）：同作用域规则，额外 `overflow:visible; text-overflow:clip;` 把基础规则的 `hidden`+`ellipsis` 一起卸掉；并补 `.kami-field:has(.kami-sub){align-items:flex-start}`（memo 原来没有，开关会被坠到行中间）。
3. **rain `skin.css`**（`.kami-field:has(.kami-sub)` 规则后追加）：同作用域换行规则（rain 已有 flex-start，只差换行）。

**未改 `30-皮肤管理.js`**：fx 页 DOM 的 `.kami-field-label` 是 `.kami-field`（flex）的 flex 项、`flex:1 1 auto`，说明 div 是它的块级子元素，`white-space:normal` 后自然向下撑高；开关靠 `align-items:flex-start` 顶到左上与标签首行对齐。纯 CSS 即可，无需动渲染结构（符合任务"只在结构/渲染确实需要时再动"）。

## 五、遗留与说明

1. **用户"列表没点"的观感来源推测**（当前 6 套均已确认有点击裂，非缺陷）：① grokbot 是当前真机皮肤，它的点是与文字同色的 4×7px 圆角小方块（`currentColor`），低调；② manga/senren 的点是上一轮才补全的，用户可能看的是补全前；③ 思维链默认折叠，未展开时只看到标题栏。
2. **rain 表格在 ≤560px 未做"块化横滚"**（`display:table` 保持原生）：rain 表格是 `width:100%`、单元格可折行，md-probe 375px 实测不横向溢出；若以后要更稳，可照 civdawn/empire 等加一条 `@media(max-width:560px){.kami-md table{display:block;overflow-x:auto}}`。本次未加，避免扩大改动面。
3. **预览台未覆盖真机的酒馆深色样式与用户自定义 CSS**：对比度类问题按流程 §五-⑥ 仍需真机复核；本次改动只碰换行与列表类型，不影响配色。
4. 三个临时探针留在 `.audit/` 供复跑读数，不需要可删。
