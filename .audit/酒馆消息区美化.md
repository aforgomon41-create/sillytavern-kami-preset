## 二、令牌怎么上提（`build/sync-tavern.mjs`）

**为什么必须上提**：全局层规则形如 `html[data-kami-skin] #chat { background: var(--kami-card-2) }`，而 `#chat` / `.mes` **不在任何 `.kami-root` 里**；令牌原先只定义在 `html[data-kami-skin="<id>"] .kami-root` 上，自定义属性**只向下继承、不向上**，所以全局层读不到。必须把令牌**同时定义一份到 `<html>` 作用域**。

**做法（踩过一个坑后的定稿）**：terminal 等皮肤的**基础令牌块是混合块**——`--kami-*` 令牌和 `box-sizing / color / font-family` 等组件根样式在**同一个 `.kami-root { }` 里**。所以不能简单「把纯令牌块的选择器扩一份」（会漏掉整批基础色）。定稿改为：
- 用极简 CSS 解析器拆出每条**顶层** `.kami-root` 规则，抽出其中全部 `--kami-*` 声明；
- 按**原选择器条件**生成一份 `<html>` 作用域副本（基础 / `[data-kami-scheme=light]` / 三档 `[data-kami-density]` / 两档 `[data-kami-motion]`），**追加**到皮肤末尾的「生成块」；
- 只追加、不改写既有规则 → `.kami-root` 层行为一字不变；
- `@media`（如 `prefers-reduced-motion` 的时长）跳过 —— 全局层用不到；
- **幂等**：生成块带起止标记，重跑先整块删除再按当前源码重建；脚本内置「二次变换必须零变化」自检。实测连跑四次：第一次自愈（把追加块统一成与主体一致的 CRLF），后三次全「无变化」。
- **行尾健壮**：皮肤源是 CRLF（Windows）。脚本按文件主流行尾生成追加块、剥离标记行尾无关，避免「CRLF 主体 + LF 追加块」的混合行尾在外部（git autocrlf / 另一进程归一）后被误判成「又变了」。加固后 terminal/skin.css 为纯 CRLF（CRLF=1740 / 裸 LF=0）。

**验收**：`node build/sync-tavern.mjs` 二次运行全「无变化（幂等 ✓）」；15 套共生成 101 条 `<html>` 令牌规则；产物里「全局层令牌上提」标记出现 30 次（15×开/关）。

## 三、注入链路（`30-皮肤管理.js`）

- `applyTo(doc)` 里，皮肤 CSS 与用户参数下发之后，加一行：
  `if (doc === HDOC && TAVERN_CSS) { putStyle(doc, TAVERN_STYLE_ID, TAVERN_CSS); }`
  —— 与现有皮肤 CSS **同一条下发链**（`syncAll` → `applyTo`），**不新增观察者**。
- `doc === HDOC` 守住**只注入酒馆页面**：消息 iframe 里没有 `#chat`/`.mes`，注入也匹配不到，还每个楼层白背一份。
- `teardown()` 里 `dropStyle(HDOC, TAVERN_STYLE_ID)` 收回。
- `TAVERN_CSS` 内容由 `sync-tavern.mjs` 从 `src/skin/tavern.css` 内联进占位区（`KAMI_TAVERN_CSS_BEGIN/END` 标记之间）。

## 五、与用户自定义样式谁赢（冲突清单）

**机制（探针 `?user=1`，注入一份按调研 §1.3 描述的、带 `!important` 的代表性用户 CSS，且**追加在 tavern.css 之后**，模拟 `power-user.js` 运行时后注入）**：

| 属性 | 用户设了（带 `!important`）→ 谁赢 | 用户没设 → 谁赢 |
|---|---|---|
| `.mes` background-color | **用户赢**（读到用户值 rgb(36,26,18)） | 我们赢（皮肤卡色） |
| `.mes` color | **用户赢**（rgb(255,233,201)） | 我们赢（皮肤字色） |
| `.mes` padding | **用户赢**（14px） | 我们赢（padding-bottom=gap） |
| `.mes_text` font-family | **用户赢**（Courier New） | 我们赢（皮肤字体） |
| `#chat` background-color | **用户赢**（rgb(27,27,34)） | 我们赢（皮肤 card-2） |
| `.mes` border-radius | （用户通常不设） | **我们赢**（8px / 0px） |
| `.mes` margin-bottom（间距） | （用户通常不设） | **我们赢**（gap） |

**结论**：
- 同特异性下**后注入者赢**；用户 `power-user.js` 在运行时把 `#custom-style` 追加到 `document.head`，可能排在我们的 `#kami-tavern` 之后 → **用户设了的属性用户赢**。
- 我们的规则**刻意只挑用户通常不设的属性**（圆角 / 间距 / 字体栈）先落地，这些在用户主题下也基本能存活；底色是唯一大概率撞车的一格。
- **两种情况都可读**：用户赢时用的是用户自己那套（自洽）；我们赢时用的是皮肤卡底+皮肤字色（自洽）。没有「底翻了字没翻」。
- 我们**不打 `!important` 战争**（调研 §3.2a 明令）。

**本机现状**：`D:/SillyTavern/SillyTavern/data/default-user/settings.json → power_user.custom_css` 当前为**空字符串**；真酒馆 `localhost:11451` 上 `data-kami-skin="grokbot" data-kami-scheme="dark"`（皮肤管理在跑，旧预设），主题为暗（`--SmartThemeBodyColor: rgba(220,220,210,1)` 浅字、`--SmartThemeChatTintColor: rgba(23,23,23,1)`）。**即当前没有那套 25KB 自定义 CSS 在生效**，故此刻无实际冲突；上表是按其描述复现的机制结论。浏览器工具不支持任意 JS 求值、且真酒馆跑的是旧预设（无 tavern.css），故「谁赢」用探针（同一条 CSS 级联，确定性等价）测，真酒馆只用于读主题底色这一层上下文。

## 七、lint 怎么改的（`build/lint-skins.mjs`）

**实测**：令牌上提后 `node build/lint-skins.mjs` **15 套直接全 PASS**，无需放宽——因为全局层的 `<html>` 作用域选择器 `html[data-kami-skin="<id>"]` 既含 `kami`（在属性里）又以皮肤前缀开头，原有「必须含 kami」「必须以前缀开头」两条检查天然放行。`tavern.css` 在 `src/skin/` 而非 `src/skins/`，lint 本就扫不到。

仍做了两处**面向全局层**的改动：
1. **显式豁免 + 注释**：前缀检查里加 `if (t === PREFIX) continue;`，把「`<html>` 令牌作用域」登记为合法，防止将来「收紧成必须落 `.kami-root`」的改动误伤它。
2. **新增正向检查（不许漏掉真问题）**：每套皮肤的 `html[data-kami-skin="<id>"] { … }` 里必须看得到 `--kami-fg`，否则报「基础令牌未上提到 `<html>`（全局层读不到）：跑 node build/sync-tavern.mjs」——把「漏跑同步脚本 / 手删生成块」变成能抓住的真问题。

## 十、遗留与已知限制

1. **浅色皮肤 + 深色酒馆主题**：消息卡因「谁改色谁配底」始终可读；但**聊天区以外的酒馆 UI**（顶栏/抽屉/输入框，后续增量）若也皮肤化，仍会遇同一问题，届时照 §9.7-4 / §9.8-2 的「谁改色谁配底」处理。
2. **`.mes_text` font-family 是潜在冲突点**：若用户自定义 CSS 给 `.mes_text` 设了带 `!important` 的字体，用户赢（§五表）。圆角 / 间距是我们稳定赢的两类。
3. **`.mes` 选中态**：酒馆 `#chat .mes.selected{background:rgb(102,0,0)}` 特异性 (1,2,0) 高于全局层 (0,2,0)，选中高亮仍归酒馆；但选中态那条只改底色不改字色，极端下（浅色皮肤选中时）可能出现「深红底 + 皮肤深字」对比偏低——选中是瞬态，暂不特殊处理，需真机观察后再定。
4. **边框宽度读数 0.571px**：探针在代理窗口（非 1× 缩放）下 `border-width` 回报为亚像素；真酒馆 1× 下为皮肤的 `--kami-border-w`（terminal=1px）。非功能问题。
5. **第 16 套皮肤**：新增后跑一次 `node build/sync-tavern.mjs` 即自动上提令牌、自动吃到全局层，无需手改。
6. **全局层无独立开关**：它本身就是皮肤的一部分，想关就切皮肤（调研 §5 建议）。
