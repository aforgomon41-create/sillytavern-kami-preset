## 〇、先回答那个关键事实：`<content>` 在酒馆里到底保不保留？

**结论：保留（以元素形态存活到 `.mes_text`），证据两条。**

1. **代码证据**：酒馆把消息正文跑完 markdown 再交给 DOMPurify（酒馆 `public/script.js:1898-1908` 的 `DOMPurify.sanitize(mes, config)`，config 只多登记 `ADD_TAGS:['custom-style']`，另有 `MESSAGE_SANITIZE:true`——该键在现代版 DOMPurify 里已移除、解析时被忽略）；渲染管线末端 `public/script.js:2637` 灌进 `.mes_text`。本机酒馆 1.18.0 自带 DOMPurify **3.4.2**（`node_modules/dompurify/dist/purify.min.js`），其默认 html 允许标签表的字面串：`…"col","colgroup","content","data","datalist"…`——**`content` 在白名单里**（它是旧版 Web Components 的遗留标签，DOMPurify 一直收着）。
2. **真浏览器实测证据**：`.audit/清洗链路证据.html` 用本机酒馆 node_modules 里的**同一份** showdown + DOMPurify 3.4.2、酒馆 `script.js:521-530` 的同款 showdown 选项、`script.js:1898-1908` 的同款 config 复刻整条管线。页面读数：
   - `<content>标签内文字</content>标签外文字` → 保留输出 **`<content>标签内文字</content>标签外文字`**（原样）；
   - `<正文>…</正文>` → showdown 直接把它**转义成字面文本** `&lt;正文&gt;`，DOM 里**认不出元素边界**；
   - `<narr>…</narr>` → 过 showdown 后被 DOMPurify **剥掉标签只留内容**；
   - 整条消息落到 DOM：`content` 元素个数=**1**，`正文` 元素个数=**0**。

   也就是说：**`content` 是主路径能用的名字；白名单外的自造名（`正文`、`narr` 这类）会被清洗处理掉**——任务书里预设的两种结果都真实存在。

## 一、三件事分开做了什么

### ① 收窄到用户指定标签内（默认 `content`），标签名可改

**选了哪条路、为什么可靠**：主路径 = **DOM 检测**——`content` 白名单存活已被证明，所以在 `.mes_text` 内用 `getElementsByTagName(标签名)`（不把用户输入拼进 CSS 选择器，注入面为零）找**最外层**的标签元素，只包它内部的直接子节点（连续段合成包裹层，让位清单照旧）。兜底路径（标签被剥掉时）= **原始文本指纹对位**：按楼层号取酒馆助手 `getChatMessages` 的原始文本，正则定位 `<tag>…</tag>` 的内文，用「只留文字/数字/emoji」的归一化指纹（`normText`，strip 掉标点、markdown 记号与空白）去 `.mes_text` 直接子节点的**连续窗口**上对位——**对上才包、对不上一个节点都不动**；指纹按（标签名, 原文长度）记在元素上防重复扫描。兜底的安全性来自失败即不做事：内文被 code fence 包住、楼层有 `display_text` 改写等都无法对上时保持原样，只打一行 log。

- 落点：`src/scripts/30-皮肤管理.js`
  - `DEFAULT_STATE.bodyTag = 'content'`（`readState` 里也过一遍校验）
  - `normalizeBodyTag()`：空值 / 超过 32 字符 / 含尖括号·引号·斜杠·空白 / `createElement` 或 `querySelectorAll` 抛错 → 拒绝并回退 `'content'`；`bodyTag()` 统一取生效值
  - 包裹主循环重写：`bodyContainers()`（找最外层容器、嵌套同名只认外层）→ `wrapRunsIn(host, kids)`（原 concat 搬节点手法不变）
  - 兜底链：`readMesRaw` / `bodySectionsIn` / `wrapByFingerprint` / `tryRunsCount` / `wrapFromBodyRange`
  - `syncBody()`：开关关 → 逐条还原；开 → 容器路径为主、兜底路径只在「容器一个没有 + 原文里确实出现 `<tag>`」时才走
  - `unwrapOneMesText()` 改成**后代查询 + 逆序还原**（包裹层现在在标签容器内部）
  - 面板「显示」卡新增「正文标签」输入行（`.kami-field` + 契约已登记的 `.kami-text`，行为钩子 `data-kami-bodytag`，`change` 委托 → `setBodyTag()`：改完**先全拆再按新标签重包**，与开关的就地点火同一路径；非法值 toast + 回显默认）
  - 全局 API 新增 `KamiSkin.setBodyTag(v)`
- `src/scripts/meta.json`：`data.kami-skin` 加 `"bodyTag": "content"`。
- 契约（只增不删）：§4.2 正文包裹层骨架段追加「适用范围 v2」条目（只包用户标签以内、校验规则、清洗存活性判据与兜底路径）。

### ② 开关放最上面

「显示」卡的行序改为：**正文美化（第一行） → 正文标签 → 明暗 → 动效 → 密度**（后三行相对顺序不变）。读数见 §三。

### ③ 桌面档悬浮窗放大到两倍 + 可视区约束

- 默认尺寸：`restoreGeometry` 的默认从 420×560 → **`PANEL_DEF_W=840 / PANEL_DEF_H=1120`**，**只在脚本变量里没存过 `w/h` 时使用**（老用户拖出过自定义尺寸的继续用他们存的那套；拖过位置但没缩放过尺寸的用户同样吃到新默认）。
- 可视区约束（防「一开面板就看不见边」）：
  1. 尺寸夹取沿用现成的 `min(vw−24) / min(vh−24)`；
  2. 新增**位置收窄**：任何一边不许超出可视区（`x+w > vw−12 → x = max(0, vw−w−12)`；`y+h > vh−12 → y = max(0, vh−h−12)`），默认与老存档都吃这条兜底；
  3. 拖动的落点夹取改成「整个面板不出屏」（原先允许 −40 的探出余量被收紧），缩放的上限同步改成受 `vw−drag.x−12 / vh−drag.y−12` 约束——**可拖、可缩放保留**，只是不再能把面板拖出屏幕。
- **手机档不受影响**：`sheetMode()` 分支照旧清掉全部几何令牌，贴底抽屉由 `data-kami-layout="sheet"` 的 `!important` 规则接管（`78%` 高）。
- **其它三块面板不受影响**：40-预设设置与 60-压缩各自维护自己的 `PANEL_W=420 / PANEL_H=560` 常量（40 号第 60 行、60 号第 97 行，grep 可证），引导是全屏向导；30 号注入的几何 CSS 兜底串（`var(--kami-panel-w,min(420px,…))`）**一字未改**——「只改皮肤管理」的隔离方式就是：默认值全部收在 30 号自己的 `PANEL_DEF_W/H` 常量里，共享令牌与 CSS 兜底不动（皮肤那边也完全没碰）。

## 二、遗留与已知限制（如实说）

1. **白名单外的标签名（如 `正文`、`narr`）在真酒馆里进不了 DOM**：showdown/DOMPurify 会转义或剥掉它们 → 主路径找不到元素，走兜底指纹路径。指纹对得上才会包，对不上保持原样（log 一行）。给预览台实测过的名字是白名单内的 `section`。**这是机制边界，不是 bug**：想在真机上用非白名单名，印记/原始文本仍是唯一判据，其可靠性受 `display_text` 改写与插件后插节点影响，故做了「对不上就不动手」的保险。
2. **v2 收窄意味着「没有用户标签的旧消息不再被包裹」**——这是用户要的行为（只美化标签内），旧聊天里模型没写 `<content>` 的楼层不会被打磨。
3. **同一消息多个 `<content>`**：每个容器独立包裹；嵌套同名只认最外层。
4. 性能：触点仍是三条既有链（iframe 事件 / 300ms 防抖 MO / 8s sweep），未新增观察者；兜底路径的 `getChatMessages` 只在「无容器 + 原文含 `<tag>`」的消息上才触发，且结果被 (标签名+原文长度) 记忆防重复。
5. 「逐拍打点」探针里保留了少量仅探针级的 console 调试（.audit 文件，不影响生产脚本）。
