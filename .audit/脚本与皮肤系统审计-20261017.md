## 01：压缩会跨聊天写入与隐藏

位置：[60-压缩.js:1471](D:/SillyTavern/卡密预设制作/src/scripts/60-压缩.js:1471)、[切换聊天:1656](D:/SillyTavern/卡密预设制作/src/scripts/60-压缩.js:1656)、[保存和隐藏:1617](D:/SillyTavern/卡密预设制作/src/scripts/60-压缩.js:1617)。

触发步骤：在聊天 A 开始大总结 → 模型尚未返回时切到聊天 B → A 的请求返回。

流程开始时只记楼层数；等待期间没有绑定聊天身份。切聊天又会更换全局 `st`，后面的保存和隐藏按“当前聊天”执行。

**诊断实测：**请求从 A 发出，切到 B 后，保存目标为“聊天 B 世界书”，B 中生成 `0-14` 压缩块，B 的 `0-14` 楼被隐藏。

建议：给每轮任务固定聊天和世界书身份；每次异步等待后、写盘前、隐藏前都核对身份。切聊天时取消旧任务，旧响应只丢弃，不能改动新聊天。

## 02：自定义 LLM 无法获取模型列表

位置：[60-压缩.js:2448](D:/SillyTavern/卡密预设制作/src/scripts/60-压缩.js:2448)。

### 直接缺陷：缺少酒馆校验码，而且错误提示失真

`fetchModelList()` POST `/api/backends/chat-completions/status`，只带 `Content-Type`。酒馆默认要求 `X-CSRF-Token`，也就是用来确认请求来自自己页面的校验码。

本机 SillyTavern 1.18 源码证据：

- [script.js:645](D:/SillyTavern/SillyTavern-1.18.0/public/script.js:645)：`getRequestHeaders()` 同时提供内容类型与校验码。
- [server-main.js:167](D:/SillyTavern/SillyTavern-1.18.0/src/server-main.js:167)：启用 CSRF 时，从 `x-csrf-token` 取值并校验。
- [openai.js:4437](D:/SillyTavern/SillyTavern-1.18.0/public/scripts/openai.js:4437)：酒馆自己的模型列表请求使用 `getRequestHeaders()`。
- [酒馆助手 generate/index.ts:43](D:/SillyTavern/SillyTavern-1.18.0/public/scripts/extensions/third-party/JS-Slash-Runner/src/function/generate/index.ts:43)：助手现有 `getModelList()` 同样使用标准请求头。

该缺陷会在默认开启校验的环境导致 HTTP 403；关闭校验或另有外部补头的环境可能暂时避开，所以不能仅凭有人能用就排除它。

脚本又没有检查 `resp.ok/status`。403 返回网页或错误 JSON 时，解析失败被吞掉，最终走“接口未返回任何可用模型”。配套探针已复现：**请求没有校验码，模拟 403 后界面提示空列表**。

### 补上请求头后仍要核对来源适配

当前对所有非 `custom` 来源统一传 `reverse_proxy/api_key/proxy_password`，但本机 1.18 的 `/status` 并不按同一套字段处理所有来源：

- **Claude：**原生前端主动跳过模型列表状态检查（[openai.js:4358](D:/SillyTavern/SillyTavern-1.18.0/public/scripts/openai.js:4358)），服务端该路由没有对应来源分支，会进入不支持来源的 400。
- **Azure OpenAI：**服务端需要 `azure_base_url/azure_deployment_name/azure_api_version`，当前配置和请求没有提供（[chat-completions.js:1849](D:/SillyTavern/SillyTavern-1.18.0/src/endpoints/backends/chat-completions.js:1849)）。
- **OpenRouter：**此路由使用酒馆自己保存的密钥，不读取这里的独立 `api_key/proxy_password`（[chat-completions.js:1748](D:/SillyTavern/SillyTavern-1.18.0/src/endpoints/backends/chat-completions.js:1748)）。只在压缩配置里填密钥，可能仍取不到列表。
- **OpenAI 等来源留空地址：**服务端会读取酒馆自己的对应密钥，而非这张配置卡独立传入的 `api_key`。需要明确独立配置与酒馆配置的优先关系。

这些是对**本机安装的 1.18 实现**的核对结果，没有访问反馈用户的服务器，不能据此断言其具体供应商只存在一种失败原因。

建议：先补标准请求头、HTTP 错误检查和有意义的报错；OpenAI 兼容来源可复用助手现有模型列表能力，其他来源逐项适配。补足来源测试及超时处理。不要通过关闭酒馆校验来修这个功能。

## 03：连续保存会把新编辑回滚掉

位置：[40-预设设置.js:558](D:/SillyTavern/卡密预设制作/src/scripts/40-预设设置.js:558)、[失败回滚:592](D:/SillyTavern/卡密预设制作/src/scripts/40-预设设置.js:592)、[取消包装:651](D:/SillyTavern/卡密预设制作/src/scripts/40-预设设置.js:651)。

每次保存都临时包装宿主 `fetch`。连续改两次时，后一层套在前一层外面；响应到达顺序又决定回滚和恢复顺序。

**诊断实测：**原值 `1` → 保存 `2` → 再保存 `3`；第一个请求失败、第二个成功。最终内存值退成 `1`，并且 `fetchRestored=false`，宿主 fetch 没恢复成原函数。

此外，取消时设置的是 `slot.done`，回调检查的却是另一个 `done`；未完成请求仍可能在注销后执行回滚。

建议：对同一预设的写入排队；每笔保存带序号，旧失败只能回滚自己仍拥有的值。请求观察器应统一安装和管理，不依赖多层 fetch 包装的完成顺序。

## 11：键盘切换行动选项模式会误折叠

位置：[frontend-options.html:33](D:/SillyTavern/卡密预设制作/src/regex/frontend-options.html:33)、[标题 keydown:349](D:/SillyTavern/卡密预设制作/src/regex/frontend-options.html:349)。

“填入/发送”按钮在可折叠标题里；标题的 keydown 不区分事件来自自己还是子按钮。用户聚焦子按钮按 Enter/空格时，事件冒泡到标题，被 preventDefault，并切换折叠状态。

**诊断实测：**来自子按钮的 Enter 使 `open:1→0`，且 `defaultPrevented=true`；原生按钮应执行的键盘激活被取消。

建议：标题只处理自身的键盘事件，或跳过内部交互控件；用键盘真实验证模式切换。

## 性能开销：最值得优化的是重复工作

### 已确认的开销机制

[30-皮肤管理.js:1743](D:/SillyTavern/卡密预设制作/src/scripts/30-皮肤管理.js:1743) 监听整个聊天树的节点变化，约每 300ms 合并触发一次**全 iframe** 同步；此外 [1765](D:/SillyTavern/卡密预设制作/src/scripts/30-皮肤管理.js:1765) 附近还有每 8 秒的兜底扫描。

每轮同步会：

1. 遍历所有已渲染的消息 iframe，而不只是新建的那一个。
2. 无条件重写每个文档的 5 个皮肤属性；已有前端又监听这些属性并刷新文案。
3. 拼接当前皮肤整段 CSS，并与样式节点的文本比较。**内容相同时没有真的重写整个样式表**，这一点不能误报。
4. 再扫描聊天，清理早已退役的包裹层；`syncAll()` 路径还会重复调用这项清理。

正文外壳也在监听聊天树并扫描全部 `.mes`。因此楼层越多、流式变化越频繁，重复遍历的成本越大。这里的数量指**实际渲染的 DOM/iframe 数**，不能直接拿聊天总楼层数计算。

建议顺序：只处理新增/变更 iframe → 属性值不变就不写 → 同一皮肤的组合 CSS 缓存一次 → 退役清理只在启动或发现旧节点时执行 → 确认事件可靠后降低兜底全量扫描频率。
