## 四、★ 三个只有实测才能发现的坑（都写进契约了）

### 坑 1：`:where(:not([class], [style]))` 只挡「元素自己」，挡不住后代

最初把字号写在 `.mes_text` 上、用 `:where(:not([class], [style]))` 当闸门。实测（grokbot）：
插件卡片 `.rbq-sdt-card` 自己的段落**没事**（它带行内 `color`，且不在射程里），
但**卡片里那个自己没 class 的 `<strong>` 被我们的规则抓到了**（算出的是皮肤字色）。
读数：`卡片内加粗色 = rgb(236,235,232)`＝皮肤 `--kami-fg`，而它本该是卡片自己的 `#e6edf3`。

**验法**（探针里的「对照实验」）：往页面注入一条更高特异性的 `strong { color: #e6edf3 !important }`，
颜色当场变回 —— 证明「原本就是我们的规则在赢」，不是别的来源在改。

### 坑 2：想用 `:not([class] *)` 把「带 class 的容器整棵子树」一次排掉 —— **不行**

`.mes_text` 自己就带 `class`，`[class] *` 会把**整条正文**一起排掉（实测：整段规则彻底失效，
连正常的段落间距都没了）。所以在纯 CSS 里**没有办法**表达「不在任何带 class 的容器内部」。

### 坑 3：`--kami-accent` 当**正文文字色**时，多套皮肤过不了 4.5:1

第一版链接与引用用 `--kami-accent`，实测最低对比度：
**wod 暗档 2.56:1** / trpg 亮档 3.35:1 / civdawn 3.90:1 / crt80s 4.20:1 / mileng 4.21:1 / senren 4.46:1 / manga 4.92:1。
accent 是给描边、记号、按钮用的装饰色，**不是字色**。改成契约 §2.7 保过对比度的三支
（`--kami-fg` / `--kami-fg-dim` / `--kami-fg-mute`）后，最低值变成 **4.20:1**（crt80s 的引用，亮/暗两档取较差的一档）。

**定稿的机制（CSS 一半 + 脚本一半）**：
- **CSS 一半**：字号 / 行距只落在 `.mes_text` 的**裸直接子元素**上（`> :where(:not([class], [style]))`）——
  插件卡片是「带 class 的 div」，天然不在射程里，它的整棵子树于是既不吃我们的字号、也不吃我们的行距。
- **脚本一半**：`markMesHosts()` 给 `.mes_text` 里「带 class / 带行内 style 的直接子元素」写
  `data-kami-mes-host`（`.TH-render` / `.kami-root` / `.mes_*` 豁免不打），全局层每个后代规则带
  `:not([data-kami-mes-host] *)`，把「宿主里那些自己没 class 的元素」也一并挡住。
  关开关 / 注销时 `unmarkMesHosts()` 摘干净。
- **代价一条（如实记）**：消息正文的**字号**沿用酒馆当前字号（皮肤只改字族 / 行距 / 排版）。
  要做到字号也跟着皮肤，等于把插件卡片的尺寸一起改掉，不在全局层做 —— 属第二阶段的皮肤专属活。

## 八、第二轮：消息楼层吃皮肤的「面 + 特效」

### 8.1 用户的原话与判据

> 「消息楼层仍然保持着酒馆的原生背景，各皮肤的特效也没有作用上消息楼层」

实测确认（探针读数）：第一轮只给了 `.mes` 一个 `--kami-card` 的**平底**；皮肤的**面**在
`.kami-shell` / `.kami-surface` 上（3~12 条视觉规则/套，含背景图、投影、裁剪、隔离），**特效** 167 条
挂在 `.kami-shell` / `.kami-surface` / `.kami-root` 上（`::before` / `::after` / `animation`）——
**消息楼层里没有这些类名，一条都不命中**；而且特效要的令牌（`--kami-texture` / `--kami-term-scan` /
`--kami-crt-*` / `--kami-gb-*` …）也不在上提到 `<html>` 的 101 条里，`background-image: var(--kami-texture)`
解析成空、整条声明被丢。

### 8.2 为什么走「改写规则」而不是「给 .mes 加组件类」

先做了「挂类名」原型（探针 `?shell=1`），**三条坏代价实测**：
① `.mes` 的 `display:flex` 被皮肤夺走变成 `display:block` —— 头像列与 swipe 的几何靠它，会歪；
② 插件卡片被卷进 `.kami-root` 作用域（`closest(.kami-root)` 变真），`.kami-root *` 那套会碰它的盒模型；
③ 伪元素特效仍不亮（缺令牌 + `.kami-surface` 需要 `position:relative`）。
所以定稿 = **不动 DOM**，由 `build/sync-tavern.mjs` 把皮肤写在这些类上的视觉声明**改写成消息楼层作用域**。

### 8.3 生成器的四条机械判据

1. **只碰壳与面**：选择器里出现 `.kami-shell` / `.kami-surface`，或裸 `.kami-root` 整块。
   面板与组件内部的（`.kami-drop` / `[data-kami-comp="panel"]` / `.kami-card` / `.kami-item` / `.kami-head` /
   `.kami-title` / `.kami-dot` …）整条跳过（消息楼层上没有那些元素，搬过去是错的语义）。
2. **只搬视觉属性**（白名单）：底、描边、圆角、投影、`clip-path`、`filter`、`backdrop-filter`、
   `mix-blend-mode`、`opacity`、`color`、`letter-spacing`、`animation*`、`content`、`inset` / `top/right/bottom/left`、`z-index`。
   **几何一律不搬**：`display` / `flex*` / `width` / `height` / `overflow` / `position` / `margin` / `padding` / `gap`。
3. **`overflow` 永不搬**：消息楼层里有插件浮层与头像列，裁一下就可能被切掉。圆角与内容的贴合改用
   一条保底 `::after`（`inset:0` + `border-radius:inherit` + 描边 + `pointer-events:none`）画上去。
4. **`.kami-md` 只搬底色族**：底色与描边已经由 `.mes` 给了，再给 `.mes_text` 来一套就是「卡片套卡片」。

### 8.4 又踩两个坑（都在生成器里堵掉了）

- **坑 4：字色与底色脱对（terminal 1.01:1 / empire 1.03:1）**。镜像里混着「组件面 → 另一套配色」的
  后代规则（`.kami-md` 级别把 `--kami-fg` 重映射成墨色），漏下来正文就成了深墨。
  修法：**生成期把 `--kami-bg × --kami-fg(-dim/-mute)` 按皮肤自己的 `var()` 链解析成实际色值**，
  在生成块最后钉一条成对规则（同时命中 `.mes` 与 `.mes_text`，并把三支字色令牌一起钉住）。
  解析器要做「逐层剥 `var()` + 选择器回退（`html[…] .kami-root`）」，因为令牌的基座不是 `<html>`。
- **坑 5：镜像规则特异性压过宿主闸门**。生成的选择器 (1,3,1) 与全局层那条
  `… .mes_text strong:not([data-kami-mes-host] *)` 打平，排在后面就赢 —— 实测插件卡片里的 `<strong>`
  被染上皮色。修法：每条生成规则都带 `:not(:where([data-kami-mes-host] *))`
  （`:where()` 把这条的特异性压成 0，不改变生成规则与全局层原有的胜负关系）。
- **附带**：放宽令牌上提判据（从「必须以 `.kami-root` 结尾」改成「选择器里出现 `.kami-root`」）后，
  皮肤给组件面写的令牌重映射（grokbot 的 `--kami-clay-*` 等）也进了 `<html>`（101 → **193 条**）；
  不改这一条，grokbot 的消息卡会拿到炭底而不是黏土白。
