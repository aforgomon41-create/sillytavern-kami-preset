## 二、根因归类（实测计算样式，不靠推断）

### A 类 · `xianyun` 独有：整块面板角标规则缺失

`src/skins/xianyun/skin.css` 里**一条** `.kami-item > .kami-badge` 的面板规则都没有，emoji 角标继续吃通用 `.kami-badge`（`skin.css:905-917`）那套「朱砂小短签」造型，而且是**行内 flex 项**（不是绝对定位）——它和条目名挤在同一行，把名字可用宽度直接吃掉。实测「DS/GLM底部破限」的名字只剩 **13.4px** 宽。

同时 ⓘ 也没有紧凑尺寸：`.kami-card-note` 只给了 `font-size: var(--kami-fs-xs); margin-top: 4px`（`skin.css:1153-1157`），在 `--kami-lh: 1.68` 下占 **19.6px** 高，`margin-top:4px` 又把它从 `top:6px` 推到 10px。卡片本身**没有任何** `:has()` 上下内边距补偿。

### B 类 · 其余 7 套共有一个病根：补偿值算小了

7 套的 emoji 角标**早就退成纯字形**（实测 `padding:0; border:0; background:transparent; pointer-events:none`），真正的漏子是 `:has()` 补偿给的高度不够：

| 皮肤 | ⓘ top | ⓘ 高 | ⓘ 底边 | 旧补偿值 | 差额 |
|---|---|---|---|---|---|
| grokbot | 6px | 18px | 24px | `calc(12px + .5em)` = 18.75px | 5.3px |
| mileng | 5px | 15.4px | 20.4px | `calc(pad-lg-y + .4em)` = 17.1px | 3.3px |
| civdawn | 5px | 15.8px | 20.8px | 18px | 2.8px |
| terminal | 5px | 15.3px | 20.3px | 17.9px | 2.4px |
| empire | 5px | 16px | 21px | 19.3px | 1.7px |
| nixie | 1px | 16.4px | 17.4px | 16.3px | 1.1px |
| rain | 1px | 15.3px | 16.3px | 17.3px | 0（但 rain 的 **emoji 角标高 17px**、底边 18.5px，差 1.2px） |

**⚠️ 与上个 agent 报告的一处差异**：报告说这 7 套的残余重叠来自「ⓘ 的 `margin-top` 没归零」。我复测时 7 套的 ⓘ 计算 `margin` **都已经是 `0px`**（`.kami-card-note` 的基础规则在这些皮肤里没写 `margin-top`，或被别的规则覆盖），所以 `margin` 不是当下的病根。我仍然按规范把 `margin-left: 0` 改成 `margin: 0` 作为显式保障，但真正修好重叠的是把补偿值改对。

## 三、修法

### 3.1 皮肤（8 套）

1. **`xianyun`：补上整块面板角标规则**（`skin.css:1171-1247`）
   - `.kami-item > .kami-card-note[data-kami-note-mark][data-kami-corner]`：补 `display:inline-flex; align-items/justify-content:center; width/height:1.4em; line-height:1; margin:0`，把 ⓘ 从「整行 line-box（19.6px）」收成紧凑方框（16.4px）。
   - 新增 `.kami-item > .kami-badge[data-kami-corner]`：`position:absolute` + `padding:0; border:0; background:none` + `pointer-events:none`，四角各就各位。
   - 新增 `:has(> .kami-badge[tl|tr], > .kami-card-note[tr])` → `padding-top`，`:has(> .kami-badge[bl|br])` → `padding-bottom`。
2. **其余 7 套：两处小改**
   - ⓘ 角标规则 `margin-left: 0` → `margin: 0`（显式归零，防 `.kami-card-note` 以后加回 `margin-top`）。
   - `:has()` 补偿 `calc(var(--kami-pad-lg-y) + 0.4em)` / `calc(12px + .5em)` → **`calc(var(--kami-pad-y) + 1.4em)`**。

**为什么 `calc(var(--kami-pad-y) + 1.4em)` 一定够**（不是试出来的，是推出来的）：
`1.4em` 在补偿规则里取的是**卡片**的字号 `--kami-fs-sm`，而角标自身的 `1.4em` 取的是它自己的 `--kami-fs-xs`；所有皮肤的 `fs-sm > fs-xs`（如 xianyun 13.2 vs 11.7），所以 `1.4em`(卡片) 必然盖过角标本体高度；`--kami-pad-y` 再盖过角标的 `top` 偏移。约束收缩成 `pad-y > top − 1.4×(fs-sm − fs-xs)` ≈ `top − 2.1px`，而各皮肤最紧的 `top` 是 6px、最松的紧凑档 `pad-y` 是 5px —— 恒成立。

### 3.2 引导（`src/scripts/50-引导.js` 的 `GUIDE_CSS`，18 行纯新增）

在 `padding:0` 那两条（原 536 / 578 行）之后各补两条**同样以面板 id 开头、并带 `:has()`** 的规则：

```
#<面板id> .kami-guide-grid     > .kami-item:has(> .kami-badge[data-kami-corner="tl"], > …"tr", > .kami-card-note[data-kami-corner="tr"]){padding-top:calc(var(--kami-pad-y,7px) + 1.4em);}
#<面板id> .kami-guide-grid     > .kami-item:has(> .kami-badge[data-kami-corner="bl"], > …"br"){padding-bottom:calc(var(--kami-pad-y,7px) + 1.4em);}
#<面板id> .kami-guide-skins    > .kami-item:has(…同上…){padding-top / padding-bottom:…}
```

特异性对账：旧规则 `#id .kami-guide-grid > .kami-item` = (1,2,0)；皮肤补偿 `.kami-item:has(> .kami-badge[data-kami-corner="tl"])` = (0,6,1)；新规则 = **(1,4,0)** —— 压得过旧规则，也压得过皮肤自己的（id 永远赢，但两条都是 id 开头时比后面）。取值与皮肤一致，只走令牌，没定义颜色/字体/材质，引导的「图版/报纸」观感不变。
`GUIDE_COPY`、引导文案、DOM 结构、其它脚本**一字未动**（`git diff` 对该文件仅 18 行新增，全在 `GUIDE_CSS` 数组内）。

## 八、遗留

1. **引导的补偿规则今天不命中任何元素**。引导现有的 `.kami-guide-grid > .kami-item` 全是图版位卡片、`.kami-guide-skins > .kami-item` 是皮肤预览卡，都不带 `data-kami-corner`。这 4 条是**防回归**：将来谁把带角标的条目卡直接排进这两个网格，补偿会自动接住（A/B 已证明没有它就会回到 224~268px²）。
2. **预览台自身 tab 栏在 375px 下横向溢出**（body 377/360，越界元素是 `#tabbar .t`）。与皮肤无关，未改。
3. **`trpg` 在 375px 下面板本体 drop 367/360 溢出 7px**。改动前就有，且 trpg 不在我的 8 套里，未动。
4. **带角标的卡片变高了**（xianyun 95→105px、grokbot 91→103px、civdawn 111→123px、terminal 85→95px）。这是契约「角标只占高度不占宽度」的必然结果，兜底皮肤与 manga/senren 同样如此；网格同行卡片仍被 `align-items:stretch` 拉平。
5. **真机未验**：预览台没有酒馆的深色样式、没有用户自定义 CSS、也没有真 iframe 沙箱行为。对比度类问题按流程仍需真机复核。
6. **临时探针留在 `.audit/`**（未删，便于复测）：`overlap-probe.html`（单套）、`overlap-probe2.html`（多套 + 窄屏 + 密度档）、`guide-comp-probe.html`（引导 A/B 注入）、`cdp-measure.mjs`（Node + CDP 直连本机 Chrome，不依赖 npm 包）。预览台全程只用 8781；CDP 用的是本机 Chrome 的远程调试口 9223 与一次性临时 profile，跑完即关即删。
