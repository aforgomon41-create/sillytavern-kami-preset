## 八、角色名样式问题：根因与修复（2026-10-20）

用户用酒馆助手的提示词查看器看到 `<n>` 没替换，实际回复时模型收到的也是没替换的版本。查实是 35 号脚本的保护范围写大了：

- **根因**：酒馆的「压缩系统消息」会把连续 system 条目合并成一条大 system 消息。35 号原来只要消息里出现 `<image_task>` 就**整条跳过**；合并后这一条里既有文生图块、也有「输出规范」和几十处角色名标记，于是整条系统消息都没替换。
- 旁证：11451 控制台旧日志是「本次替换 62 处；跳过 1 条文生图条目」，跳过的就是这条合并消息；用户截图里的 system 消息正是它。
- **修复**：新增 `_name-wrap-pure.js`（构建期内联），只保护**行首的完整** `<image_task>…</image_task>` 块，块外照常替换；HTML美化条目里那句行内提及 `<image_task>` 不算块；块内万一有 `<n>` 则原样保留并告警。
- 验证：`test/harness/name-wrap.mjs` 25 项通过；隔离 11452 + mock 实际收到的请求 `n=0`、`backticks=96`、`image_task=true`；控制台 `本次替换 25 处` 且不再有「跳过文生图条目」。构建 90 全绿。
- 90 已导入 11451 并选中；文件已发用户。

## 九、91 版：色块皮肤原生块边框修正（2026-10-20）

用户反馈色块皮肤下思维链美化没有边框。根因是结构而不是配色：

- 91 之前把 `.kami-root` 和 `.kami-shell` 都挂在原生 `details` 同一个元素上。色块（grokbot）皮肤的边框/底色规则写成 `.kami-root:not(…) .kami-shell`，是**后代选择器**，同元素不匹配，所以 `.kami-shell` 的 1px 实线边框和黏土白底都没生效。
- 修复：details 外面再包一层 `.kami-root`，details 只挂 `.kami-shell .kami-surface .kami-collapse`；皮肤的后代选择器恢复命中，边框/底色/圆角/投影都回来了。
- 真机（11451，色块暗色，旧楼层 #9 原生块）：91 导入后原生块外壳有 1px 实线边框，标题栏/内容区都套在壳里；折叠、展开、字数右对齐、原生三按钮位置都不受影响。截图 `cot-91-grokbot-border-20261020.png`。
- 契约同步：`docs/皮肤契约.md` 的 native 行与 §9 例外写明 `.kami-root` 必须是 details 的父元素，不能合并。

### 关于「预设头部」那段标签格式提示

用户看到的那段「思维链起止标签各自独占一行……」不是头部说明，也不是误塞的公告，而是 `🧩 标签格式` 这个 prompt 条目的正文末尾：

- 位置：`src/preset.base.json` 第 838 行，条目名 `🧩 标签格式`，identifier `prompt_1788362900096_7ladf0n`，role system。
- prompt_order 里排第 5（index 4），所以它在预设提示词列表靠前的位置出现，合并系统消息后也会落在 system 消息里。
- 它是 2026-10-19「标签引用前置保护」那一轮故意加的：让模型在思维链里提及标签时写全角尖括号，避免写出真正未闭合的结构标签害正则；同时要求先结束思维链再开始 `<out_body>`。
- 如果只是觉得它出现在靠前位置碍眼，可以把它移到更靠后的 prompt 位置或并进「📌 输出规范」，但**不建议删**；删了会回到未闭合标签被正则误判的老问题。
